Vou ler o código de artigos e autores para apontar os pontos concretos em que vários coautores quebrariam URLs e a API atuais.1. `articleMapper` and the favorite/unfavorite handlers both emit a single `author` profile (`username`, `bio`, `image`, `following`). Replacing that with an array, or renaming it, breaks every current list, slug, create, update, and favorite response; extra co-authors have to be added beside the existing object, which must stay the original primary author.

2. `favoriteArticle` and `unfavoriteArticle` spread the raw Prisma row (`id`, `authorId`, `favoritedBy`) and then overwrite `author` with `profileMapper`, while list and slug routes go through `articleMapper`. Including co-authors without the same explicit `select` used today will leak `password` and `email`, and the two response shapes will diverge.

3. The public URL is `Article.slug`, built as `` `${slugify(title)}-${authenticatedUserId}` ``, and `updateArticle` recomputes it with the caller’s id. A co-author title edit changes that suffix and the old `GET/PUT/DELETE /articles/:slug` 404s; dropping the user-id suffix instead makes two users’ identical titles hit the unique slug check and return 422 `title must be unique`.

4. Update and delete authorize with `existingArticle.author.id !== id`. Once `author` is a list, that comparison throws or always returns 403, so today’s owners can no longer edit. Whether any co-author may update or delete must be decided separately from `Comment.authorId`, which is a different required foreign key and must stay a single commenter.

5. `buildFindAllQuery` and `getTags` only return an article when its one `author` is `demo: true` or is the viewer, and `?author=` is a `username` match on that same relation. Applying the `demo` check to any co-author either publishes a non-demo article as soon as a demo co-author is added, or hides a demo article when a non-demo co-author is added, and `GET /articles?author=<primary username>` stops matching the rows current clients already get.

6. `getFeed` keeps only articles whose `author.followedBy` contains the viewer. Treating a followed co-author as enough changes `/articles/feed` for current clients; leaving the check on the primary only means followers of a co-author never see the article, and `articlesCount` will disagree with the list if the count query and the `findMany` query do not use the same predicate.

7. `authorId` is `NOT NULL` with `ON DELETE CASCADE` in the initial migration, so deleting the primary user deletes the article and its comments. An implicit many-to-many like `_ArticleToTag` has no order, so the profile emitted as `author` can change between requests, and repeating that migration’s drop-without-copy would wipe authorship. `prisma migrate deploy` runs only the SQL files, so a `schema.prisma` edit alone does not migrate existing rows or keep `User.articles` (`UserArticles`) pointing at a stable primary.

8. Every article `PUT` calls `disconnectArticlesTags` and then reconnects tags only when `tagList` is a non-empty array. Copying that onto authors means a current client body of `{title, description, body}` removes the primary author. `createArticle` today connects only `req.auth.user.id` and ignores unknown fields, so a required co-author list would 422 those clients, and `seed.ts` (`createArticle` with just the creator id) would fail the same way.

9. `authorMapper` and `profileMapper` call `followedBy.some`, and every article `include` selects `followedBy` on the single author. If `author` arrives as an array, or a co-author `select` omits `followedBy`, `GET /articles`, `/articles/feed`, `GET /articles/:slug`, create, and update all 500. Each profile’s `following` flag is per viewer, and the hand-built comment `author` objects are filtered by the commenter’s `demo` flag, not the article author.

10. A missing username, a duplicate co-author, or the primary listed again surfaces as an unhandled Prisma error (`P2025` / `P2002`). The handler in `src/main.ts` turns that into HTTP 500 `err.message` instead of the 422 `{ errors: ... }` body that blank `title`, `description`, and `body` already use.
