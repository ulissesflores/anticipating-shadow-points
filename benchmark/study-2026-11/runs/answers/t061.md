I've written the co-author plan; no code was changed. It's saved at `<config>/plans/allow-an-article-to-cozy-bonbon.md`.

**Assumptions (no one to ask in this run):**
- The current `author`/`authorId` stays as the primary author (owner). Co-authors are extra.
- Responses keep every field they have today and gain one new field, `coAuthors: Profile[]`.
- The owner or a co-author can edit an article. Only the owner can delete it or change the co-author list.
- Clients set co-authors with an optional `article.coAuthors: string[]` (usernames) on POST and PUT. Leaving it out of a PUT keeps the current list.
- `?author=` and the feed keep filtering on the primary author only. A new `?coAuthor=` filter covers co-authors.

**Plan:**
1. **Schema:** add a link table, `ArticleCoAuthor(articleId, userId, position, createdAt)`, with cascade deletes and a stored order. The migration only adds a table, so existing data needs no backfill.
2. **Shared include and mapper:** `article.service.ts` repeats the same include block 6 times; I'll pull it into one `articleInclude` that also loads co-authors. `article.mapper.ts` will turn them into profiles using the existing `author.mapper.ts`.
3. **Favorite/unfavorite:** these two functions copy the raw database row into the response, so they would leak the new link-table rows. They get an explicit mapped `coAuthors`, and their other fields stay as they are.
4. **Service rules:**
   - A new `resolveCoAuthors` check removes duplicates and the owner, returns 422 for unknown usernames, and caps the list.
   - `updateArticle` allows the owner or a co-author, and only the owner can change the list. The list is replaced in one transaction.
   - **Slug fix:** a new title's slug must be built from the owner's id, not the caller's (`article.service.ts:317`). Otherwise a co-author renaming the article puts their own id in its URL.
   - `deleteArticle` stays owner-only.
   - The article list filter also shows non-demo articles to their co-authors, and gains `?coAuthor=`.
5. **Docs, seed and tests:** update the controller comments, optionally add co-authors in the seed data, and add unit tests for the new rules and the slug fix.

**Verification:** run the migration and seed, then `nx test` and `nx e2e`. Then check with curl: an existing article's response should differ only by `coAuthors: []`, and a co-author's rename should leave the slug ending in the owner's id.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Slug takes the editor's id | `updateArticle` builds `newSlug` from the caller's `id` | Build it from `existingArticle.authorId`, and test it |
| 2 | Raw link-table rows in responses | Favorite/unfavorite copy the raw row (`...article`) into the output | Set a mapped `coAuthors` there, and test the response shape |
| 3 | Clients see a changed response | RealWorld clients expect `author` to be one object | Leave `author` alone; only add `coAuthors` |
| 4 | Permissions get looser | Today edit and delete both mean "the author"; co-authors split that | Only the owner can delete or manage the list; test the 403 cases |
| 5 | Visibility filter breaks | `buildFindAllQuery` nests the visibility check inside `author` | Move it to a top-level `OR`, and add unit tests for it |
| 6 | Meaning of `?author=` changes | Profile pages rely on it meaning "my articles" | Keep it as is; add `?coAuthor=` |
| 7 | Tags or co-authors half-updated | The tag clear and the update already run as separate queries | Wrap the co-author replacement and the update in `$transaction` |
| 8 | Slower list queries | Each article loads more joins, including every co-author's `followedBy` | Index `userId`, cap co-authors, and only load the `followedBy` ids needed |
| 9 | Deleting a user drops their co-authorships | Cascade deletes remove the link rows | That's acceptable; note it in the docs |
| 10 | Test mocks break | The Prisma-mock fixtures don't include `coAuthors` | Default to `?? []` in the mapper, and update the fixtures |

Riskiest: #1. A co-author renaming an article would silently move it to a slug with their own id in it.
