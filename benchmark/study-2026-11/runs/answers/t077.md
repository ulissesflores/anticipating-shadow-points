## Assumptions
- The current `author` / `authorId` stays as the **primary author** (the person who created the article). Responses keep `article.author` as a single profile object, so the RealWorld contract holds.
- Co-authors are returned in a new field, `coAuthors: Profile[]`, which is always present and is `[]` when there are none. Existing clients can ignore it.
- Co-authors can edit an article. Only the primary author can delete it or change the co-author list.
- `?author=<username>` and the feed will match articles where that user is the primary author or a co-author. This is a product decision you should confirm.
- Existing slugs are never rewritten, so every current URL keeps resolving.

## Plan
1. **Schema and migration** (`src/prisma/schema.prisma`):
   - Add an implicit many-to-many relation: `Article.coAuthors` and `User.coAuthoredArticles`, both on `@relation("ArticleCoAuthors")`. This follows the pattern already used by `_ArticleToTag` and `UserFavorites`.
   - The migration only adds things: one join table plus indexes, with cascade on delete. Generate it with `--create-only` and review the SQL before applying.
2. **Service** (`src/app/routes/article/article.service.ts`):
   - The same `include` block is copied six times. Pull it into one `articleInclude` constant and add `coAuthors` to it.
   - **`createArticle`:** accept an optional list of `coAuthors` usernames. Return 422 for unknown names, and drop duplicates and the creator.
   - **`updateArticle`:**
     - Allow the edit if the caller is the primary author or a co-author.
     - **Fix the slug:** the new slug currently ends with `${id}`, the caller's id. Switch it to the article's `authorId`, or a co-author changing the title would put their own id into the URL.
     - Only the primary author may change `coAuthors` (using `set`); anyone else gets 403.
   - **`deleteArticle`:** unchanged, primary author only.
   - **`buildFindAllQuery` and `getFeed`:** add an `OR` across `author` and `coAuthors.some`, in both the count query and the list query.
   - **`favoriteArticle` / `unfavoriteArticle`:** these currently spread the raw Prisma row into the response. Route them through `articleMapper` so the new relation doesn't leak each co-author's `followedBy` list.
3. **Mapper** (`article.mapper.ts`): add `coAuthors` by reusing `author.mapper.ts`. `author` stays as it is.
4. **Optional endpoints:** `POST /articles/:slug/coauthors` and `DELETE /articles/:slug/coauthors/:username`, primary author only.
5. **Tests, seed and docs:**
   - Add `coAuthors: []` to the mocks in `src/tests/services/article.service.test.ts`.
   - Add tests for co-author edit permissions, the slug using `authorId`, and the `?author=` filter.
   - Update the seed data and the README.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Slug changes when a co-author edits the title | `updateArticle` builds the slug from the caller's `id` | Build it from the article's `authorId`; add a test |
| 2 | Response shape changes for current clients | Favorite/unfavorite spread the raw Prisma row, so new relations show up automatically | Send them through `articleMapper`; compare before/after JSON |
| 3 | Co-authors' `followedBy` lists leak | The raw spread includes the new relation and its follower lists | Use the same mapper everywhere |
| 4 | `?author=` and feed results change meaning | The filter becomes primary OR co-author | Confirm with product; document it |
| 5 | Article visibility changes | The demo/own-id rule checks only the primary author | Leave that rule on `author`; test the listing |
| 6 | Wrong permission checks | Edit, delete and co-author changes now need different rules | Write the rules down explicitly; add 403 tests |
| 7 | Migration slows or locks production | A new join table and foreign keys on large tables | Make the migration add-only; review the SQL; test on a copy |
| 8 | Slower list queries | Every article query now joins co-authors and their `followedBy` | Index the join table; select only needed fields |
| 9 | Unit tests break | Mocks don't include `coAuthors` | Default to `?? []` in the mapper; update the mocks |
| 10 | Deleting a co-author's account | Cascade must remove only the link, never the article | Implicit m:n cascades only the join row; test it |

Riskiest: #1. A co-author editing the title would build the slug from their own id, changing the article's URL.
