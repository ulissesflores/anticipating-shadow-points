1. Existing tokens signed with default settings by earlier versions of `itsdangerous` will immediately fail validation with `BadSignature` upon upgrading, causing widespread session invalidation in downstream consumers like Flask. This exact issue caused the yanked 1.0.0 release when the default was previously switched to SHA-512 without a transition mechanism.
2. If SHA-1 is added to `Serializer.default_fallback_signers` by eagerly referencing `hashlib.sha1` rather than maintaining lazy loading (analogous to `_lazy_sha1`), imports will crash on FIPS-compliant systems where SHA-1 is disabled.
3. Updating `Signer.default_digest_method` without also updating `HMACAlgorithm.default_digest_method` will desynchronize the defaults, causing `Signer(algorithm=HMACAlgorithm())` to silently default to SHA-1 while `Signer()` defaults to SHA-256.
4. While `Serializer` supports `fallback_signers` to verify older tokens, `Signer` itself has no fallback mechanism, leaving direct `Signer` callers without an out-of-the-box way to validate legacy SHA-1 signatures.
5. In `Signer.derive_key()`, the `"concat"`, `"django-concat"`, and `"hmac"` key derivation schemes use `self.digest_method`, meaning switching to SHA-256 alters the derived key value and expands its length from 20 to 32 bytes, breaking any interoperability expecting SHA-1 key derivation.
6. The test suite contains explicit assertions in `test_digests` and `test_iter_unsigners` (`tests/test_itsdangerous/test_serializer.py`) expecting default outputs to match SHA-1 signatures (`"[42].-9cNi0CxsSB3hZPNCe9a2eEs1ZM"`) and the initial unsigner to use `_lazy_sha1`.
7. Hardcoded test vectors like `test_malformed_future_timestamp` in `tests/test_itsdangerous/test_timed.py` rely on precomputed SHA-1 signatures and will fail `TimestampSigner.unsign()` signature verification before the malformed timestamp logic is exercised.
8. Switching to SHA-256 increases the Base64-encoded signature length from 27 to 43 characters, adding 16 bytes per token and potentially overflowing fixed-size database columns, URL length constraints, or HTTP cookie size limits.
9. Documentation examples and doctests in `docs/concepts.rst`, `docs/serializer.rst`, and `docs/signer.rst` contain hardcoded SHA-1 signature outputs and explanations stating SHA-1 is the default, which will become inaccurate and break doctest verification.
10. Removing or renaming `_lazy_sha1` in `src/itsdangerous/signer.py` rather than maintaining it for backward compatibility will raise `ImportError` in tests and external projects relying on it for FIPS workarounds.
