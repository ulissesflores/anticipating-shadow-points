1. If historical slug resolution is only added to `ArticleRetrieve` (`GET /api/articles/:slug`), nested sub-resource endpoints like `ArticleCommentCreate`, `ArticleCommentList`, and `ArticleFavorite` will still look up articles by the URL parameter using `FindOneArticle` and return 404 for shared links.
2. In `ArticleDelete`, authorization checks the fetched model but the subsequent deletion executes `DeleteArticleModel(&ArticleModel{Slug: slug})` using the raw path parameter; if invoked with a historical slug, the query matches zero rows and returns 204 No Content without deleting the article.
3. `makeUniqueSlug` in `articles/models.go` only checks the `slug` column of `ArticleModel`; without checking historical slugs, a newly created or retitled article could claim an old slug, causing database constraint collisions or hijacking existing shared links.
4. If preserving shared links is implemented using HTTP redirects (such as 301 or 302) instead of internal alias resolution, clients sending authenticated requests to sub-resource endpoints (e.g., `POST /api/articles/:slug/comments`) will drop `Authorization` headers or downgrade `POST` to `GET`, dropping the request body.
5. In `ArticleUpdate` (`articles/routers.go`), updating the article model occurs without an enclosing database transaction; if saving the historical slug alias fails after updating `ArticleModel.Slug`, the slug is changed without preserving the alias, permanently breaking existing links.
6. Reverting an article's title to a previous title (e.g., A -> B -> A) can trigger unique constraint collisions against the article's own history records, cause an infinite redirect loop, or force `makeUniqueSlug` to append an unnecessary suffix instead of reclaiming the original slug.
7. Because `ArticleModel` relies on GORM soft deletes and `makeUniqueSlug` uses `db.Unscoped()`, failing to soft-delete or scope historical slug records will leave old links resolving to deleted articles or permanently block slug reuse.
8. The project uses declarative `db.AutoMigrate` calls rather than migration files, and calls them explicitly in `hello.go` as well as multiple times in `articles/unit_test.go`; adding a new history model without updating every test setup site will cause migrations and tests to fail.
9. Without restricting who can claim historical slugs, another author could update an article to a vacated slug belonging to someone else, effectively hijacking traffic and inbound links from the original author.
10. The retry logic in `ArticleUpdate` specifically handles `gorm.ErrDuplicatedKey` on `articleModel.Update`, but it does not account for collision handling or race conditions when inserting into a separate slug history table under concurrent requests.
