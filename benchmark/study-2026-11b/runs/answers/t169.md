**Ways this could go wrong** (based on reading the code):
- **Exposing someone else's data:** a route that takes a user id would let one user download another's data.
- **Leaking secrets:** dumping every `User` field would include `password_hash`, `avatar_hash` and `role_id`.
- **Including other people's content:** the comments other users left on your posts belong to them, not you.
- **Unconfirmed users get blocked:** `app/auth/views.py:12` sends unconfirmed users to the "please confirm" page for any route outside the `auth` section. A download page in the main section would break "every user".
- **Odd or ambiguous dates:** this app uses Flask 0.12, whose built-in JSON writer turns dates into email-style strings. The stored dates also carry no timezone.
- **Wrong content from existing helpers:** the `to_json()` methods return API links and counts, not the actual text.
- **Missing comments:** comments a moderator hid could be filtered out, even though the user wrote them.
- **Browser caching:** a shared computer's browser or a proxy could keep a copy of the personal file.
- **Encoding and filenames:** non-ASCII text could be garbled, and the download filename header needs care.
- **Heavy users:** the whole file is built in one request.

**Assumptions:** the download is one JSON file. It contains only the logged-in user's own data, with no id in the link. It includes every comment the user wrote, including hidden ones, marked as such. Follower lists and an admin "export anyone" option are out of scope. The app is small enough to build the file in one go.

**Plan:**
1. **`app/models.py`:** add `User.export_data()`. It lists exactly which fields go in:
   - **Profile:** username, email, name, location, about, role name, confirmed, member since, last seen.
   - **Posts:** ordered by date. Each has its text, rendered HTML, date and full link.
   - **Comments:** the user's own comments, with text, HTML, date, a hidden flag, and the post they belong to.
   - Dates are written as `isoformat()+'Z'`, and a `format_version` field is added.
2. **`app/auth/views.py`:** add `/auth/export-data`, available only when logged in. It uses `current_user` only and writes the file with `json.dumps(..., ensure_ascii=False)`. The response is marked as a download named `flasky-<username>-<date>.json`, with `Cache-Control: no-store` and `nosniff`.
3. **`app/templates/user.html`:** add a "Download my data" button next to "Edit Profile", shown only on your own profile.
4. **`tests/test_client.py`:** user A gets a post and a comment that a moderator has hidden. User B comments on A's post. The tests check that:
   - A's file has A's posts and comments, including the hidden one.
   - B's comment is not in it.
   - `password_hash` is not in it.
   - A logged-out visitor is sent to the login page (302).
   - An unconfirmed user gets the file (200).

**To check it:** run `python -m unittest discover tests`. Then by hand: register, confirm, post and comment, download the file, and check it with `python -m json.tool`.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Another user's data gets downloaded | Every other route here takes an `<id>` or `<username>` | No id in the link; use `current_user` only |
| 2 | Secrets in the file | `User` stores `password_hash`, `avatar_hash` and `role_id` | List exactly which fields go in; test that `password_hash` is absent |
| 3 | Other people's comments included | `Post.comments` holds everyone's comments on the post | Export `user.comments` only; test that B's comment is absent |
| 4 | Unconfirmed users can't download | The confirm check redirects routes outside the `auth` section | Put the route under `auth`; test it |
| 5 | Dates ambiguous or in odd formats | Flask 0.12 writes dates email-style; stored dates have no timezone | `isoformat()+'Z'` explicitly |
| 6 | Hidden comments left out | Moderators set `Comment.disabled` | Include them with a `disabled` flag |
| 7 | Personal file cached | A plain GET download can be stored by browsers or proxies | `Cache-Control: no-store` |
| 8 | Garbled text or broken filename | Posts may contain non-ASCII text | `ensure_ascii=False`, UTF-8 type, ASCII-only filename |
| 9 | Slow for heavy users | The whole file is built in one request | Fine at this size; streaming or a background job later |
| 10 | Format changes break users' files | Fields may be added later | `format_version` field |

Riskiest: #2. Exporting `User` fields without a fixed list would put `password_hash` into a downloadable file.
