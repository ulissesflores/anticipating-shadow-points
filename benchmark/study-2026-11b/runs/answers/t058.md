I didn't edit any files. This plan comes from reading `app/models.py`, `app/main/views.py`, `app/templates/user.html`, `app/decorators.py`, `config.py` and `tests/test_client.py`. The app is the Flasky blog (Flask, SQLAlchemy, Flask-Login), with `User`, `Post` and `Comment` models and a separate token-authenticated API at `/api/v1`.

## Assumptions
- **Who and how:** a logged-in user can download only their own data. They do it from a button on their own profile page.
- **Format:** one JSON file, `flasky-export-<username>-<YYYYMMDD>.json`. JSON keeps the profile, posts and comments together in one file and is machine-readable. Nobody asked for ZIP, CSV or HTML.
- **Profile fields included:** username, email, name, location, about_me, member_since, last_seen, role name, confirmed.
- **Profile fields left out:** `password_hash`, `avatar_hash` and internal ids.
- **Posts:** every post the user wrote, with `body` (the source markdown), `body_html`, `timestamp` and a link to the post.
- **Comments:** every comment the user wrote, including ones a moderator disabled (with a `disabled` flag). Each comment records the post it belongs to as a post id and link only, not the other author's post text.
- **Left out:** comments other people wrote on the user's posts, and the follower/followed lists. Those are other people's data or weren't asked for; followers can be added later.
- **Size:** it's a small app with no background job queue, so the file is built while the request runs. No database migration is needed.

## Plan

**1. Serialisation (`app/models.py`)**
- Add `User.to_export_dict()`. It returns `{"export_version": 1, "generated_at": ..., "profile": {...}, "posts": [...], "comments": [...]}`.
- Posts come from `self.posts.order_by(Post.timestamp)` and comments from `self.comments.order_by(Comment.timestamp)`. Both relationships already exist and use `lazy='dynamic'`.
- Write each field out explicitly (an allow-list). Don't loop over model columns, so `password_hash` can never leak in.
- Turn datetimes into ISO-8601 strings ending in `Z`, because the stored values are naive UTC.
- Build links with `url_for(..., _external=True)`.
- Don't reuse `to_json()`. It returns API links and counts, not the full data.

**2. Route (`app/main/views.py`)**
```python
@main.route('/export')
@login_required
def export_data():
    data = current_user.to_export_dict()
    resp = make_response(json.dumps(data, ensure_ascii=False, indent=2))
    resp.mimetype = 'application/json'
    resp.headers['Content-Disposition'] = 'attachment; filename="flasky-export-%s-%s.json"' % (...)
    resp.headers['Cache-Control'] = 'no-store'
    return resp
```
- The route takes no username or id parameter, so a user can't request someone else's data by changing the URL.
- It sends `Cache-Control: no-store` because the file contains the email address and moderated content.
- `make_response` is already imported there.
- Usernames come from a restricted character set (the registration form validator), so they're safe in the filename. Sanitise anyway as a precaution.

**3. Access for unconfirmed users**
- `auth.before_app_request` redirects unconfirmed users away from `main` routes. With the route in `main`, they can't export.
- I'm accepting that for v1, matching the rest of the app.
- If they should be able to export, either move the route to the `auth` blueprint or add the endpoint to the allow-list in `app/auth/views.py`.

**4. UI (`app/templates/user.html`)**
- Next to "Edit Profile" (inside `{% if user == current_user %}`), add `<a class="btn btn-default" href="{{ url_for('.export_data') }}">Download my data</a>`.

**5. API (optional, not in this change)**
- `GET /api/v1/users/me/export` could reuse the same `to_export_dict()`. I'm leaving it out to keep the scope small.

**6. Tests (`tests/test_client.py`, and the model test in `tests/test_user_model.py`)**
- An anonymous request to `/export` redirects (302) to login.
- A confirmed user with 2 posts and 1 disabled comment gets 200 with a JSON content type and an `attachment` disposition. The parsed JSON has the right counts, includes the disabled comment, and contains neither `password_hash` nor the text `pbkdf2`.
- When there are two users, A's export contains none of B's posts or comments.
- A user with no posts or comments gets empty lists.
- Non-ASCII text survives the round trip.

## Verification
- Run `flask test`, or `python -m unittest discover tests`.
- Manual check: run `flask deploy` and `fake.users()`/`fake.posts()`, log in, click "Download my data", then check the file with `python -m json.tool`.
- Watch the slow-query log while exporting a user with many posts.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Password hash or other secrets in the export | `User` holds `password_hash`, and a generic column dump would include it | Explicit field allow-list, plus a test that checks the file for `password_hash` and `pbkdf2` |
| 2 | Another user's data exposed | A future `/export/<username>` route or an admin shortcut could skip the ownership check | Route takes no parameters and uses only `current_user`; test with two users |
| 3 | Other people's content leaks | Comments belong to posts, and copying in post text or replies pulls in other authors' data | Comments reference the post by id/link only; other people's comments are left out |
| 4 | Large or slow exports | The file is built during the request, and with many posts `json.dumps` can block a Gunicorn worker | Order by timestamp, use `yield_per`, and move to streaming or a background job later if needed |
| 5 | Caching of personal data | Proxies or the browser could keep the file, which includes the email address | `Cache-Control: no-store`; Heroku already forces HTTPS (`SSL_REDIRECT`) |
| 6 | Unconfirmed users can't export | `before_app_request` redirects unconfirmed users away from `main` routes | Decide this on purpose: allow-list the endpoint or accept it and document it |
| 7 | Datetime serialisation errors or wrong timezone | Stored values are naive UTC datetimes, which `json` can't encode | `isoformat() + 'Z'` helper, covered by a test |
| 8 | Incomplete "all data" | Moderated comments or future models (likes, follows) could be silently left out | Include `disabled` comments; add `export_version`; add a checklist note to the models file |
| 9 | Repeated large exports | There's no rate limiter in the app | Login is required; add per-user throttling if it's abused |
| 10 | Bad characters in the filename header | The filename uses `username` | Sanitise to `[A-Za-z0-9_.-]` |

Riskiest: #1, leaking the password hash or another secret field through a generic serialiser.
