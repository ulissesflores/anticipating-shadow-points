## Context
This is a Laravel 5.5 RealWorld ("Conduit") API.
- Comments live in `app/Comment.php` and are served by `Api/CommentController` (index, store and destroy).
- `DeleteComment::authorize()` lets only the comment's author delete it.
- The app has no roles, policies or moderator concept. `AuthServiceProvider` is empty and `users` has no role column.
- `CommentTransformer` outputs the body to everyone, and `Article::comments()` is a plain `hasMany`.

## Assumptions
- A "moderator" is a global role stored on the user, not per article. Article authors are not moderators.
- "Hide" is a soft state, not a delete. The comment stays in the database and is removed from public listings.
- The appeal is a single request with a short text. The author can file it only while the hidden comment is under 7 days old, counted from `hidden_at`.
- A moderator resolves an appeal by upholding the hide or restoring the comment. Nobody else handles appeals.
- The author keeps seeing their own hidden comment, marked as hidden. Moderators see all comments.
- No email or notification is sent. The author sees the status when they list comments.

## Design

**1. Schema** (new migrations; don't edit the existing ones)
- Add `users.role` (string, default `'user'`) or a boolean `is_moderator`. I recommend `role`.
- Add these columns to `comments`:
  - `hidden_at` (nullable timestamp)
  - `hidden_by` (nullable user id, foreign key with `nullOnDelete`)
  - `hidden_reason` (nullable string)
  - `appeal_status` (nullable string: `pending`, `upheld` or `restored`)
  - `appeal_body` (nullable text)
  - `appealed_at` (nullable timestamp)
  - `appeal_resolved_by` (nullable user id)
  - `appeal_resolved_at` (nullable timestamp)
- The existing comments migration stays untouched.

**2. Models**
- `User::isModerator()`.
- `Comment`:
  - `scopeVisible()` (`whereNull('hidden_at')`).
  - `isHidden()`.
  - `canBeAppealed()`, true when hidden, `hidden_at` is within 7 days, and no appeal exists yet.
  - Add `hidden_at` and the appeal fields to `$dates`. Leave them out of `$fillable` so mass assignment can't set them.
- Put the 7-day window in `config` (for example `comments.appeal_window_days`).

**3. Routes** (`routes/api.php`; the `comments` resource currently allows only index, store and destroy)
- `POST articles/{article}/comments/{comment}/hide` (moderator).
- `DELETE articles/{article}/comments/{comment}/hide` (moderator, unhide).
- `POST articles/{article}/comments/{comment}/appeal` (comment author).
- `PUT articles/{article}/comments/{comment}/appeal` (moderator, with `decision: upheld|restored`).
- Also add `GET comments/appeals`, a moderator queue of pending appeals.

**4. Requests and authorization**
- Add `HideComment` and `ResolveAppeal` form requests that follow the `DeleteComment` pattern, with `authorize()` calling `isModerator()`.
- Add `AppealComment`, which requires `comment.user_id == auth()->id()`, `canBeAppealed()` and a non-empty body. Return 403 if the caller isn't the author and 422 if the window has passed.
- Check that `{comment}` really belongs to `{article}`. The existing `destroy` doesn't check this, so don't copy that gap.

**5. Controller**
- Add methods to `CommentController`, or a new `CommentModerationController`, reusing `respondWithTransformer`, `respondForbidden` and `respondError`.
- `index()` filters by viewer:
  - Guests and other users: `visible()` only.
  - The author: their own hidden comments, flagged as hidden.
  - Moderators: everything.
- `index` uses optional auth, so `auth()->user()` can be null. Handle that case.

**6. Transformer**
- `CommentTransformer` adds `hidden`, `hiddenAt`, `appeal: {status, appealedAt}`, and `hiddenReason` for the author and moderators only.
- For a hidden comment, show the body only to the author and moderators. Blank it for everyone else, or filter those comments out entirely.

**7. Tests** (extend `tests/Feature/Api/CommentTest.php`, which uses `DatabaseMigrations`)
- A moderator hides a comment, and a non-moderator gets 403.
- Guests and other users don't see a hidden comment. The author and moderators do.
- Appeal on day 6 succeeds and on day 8 fails (use `Carbon::setTestNow`). A second appeal fails.
- Only the author can appeal.
- A moderator upholds or restores an appeal. Restoring clears `hidden_at`.
- A comment id from a different article returns 404.
- Add a user factory state for moderators in `database/factories/ModelFactory.php`.

**8. Docs and rollout**
- Add the new endpoints to `readme.md`.
- Moderators need a way to be created, such as a seeder or an artisan command. The plan can't leave this open, because there is no admin UI.
- Run migrations before deploying the code. The new columns are nullable and defaulted, so old code keeps working.

## Verification
- Run `vendor/bin/phpunit`. The existing suites must stay green, especially `CommentTest` and the article read tests that embed comments.
- Run a manual curl flow against `php artisan serve`: register two users, promote one to moderator, hide, list as each role, appeal, resolve.

## Open points I resolved by assumption
- Global moderator role versus per-article moderators.
- Whether the hidden body is blanked or the comment is dropped for the public.
- Whether the appeal window starts at `hidden_at`.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden bodies leak | `Comment` is eager-loaded and serialized in `index` and the article responses, with no visibility filter today | Apply the filter in one place (scope + transformer), and test each viewer role |
| 2 | Privilege escalation | No roles exist, and `$fillable` or `UpdateUser` could expose `role` | Keep `role` out of `$fillable` and the request validators; test it |
| 3 | Wrong-article comment ids | `destroy` ignores `{article}`, so a moderator could hide a comment from another article | Verify the comment's article matches the route; return 404 |
| 4 | Appeal window edge cases | The 7 days could be read from `created_at` or `hidden_at`, and timezone/DST can shift the cutoff | Use `hidden_at` in UTC, put the window in config, test day 6 and day 8 |
| 5 | Optional-auth null user | `index` uses `auth.api:optional`, so viewer checks can hit a null user | Null-safe viewer helper; guest test |
| 6 | Appeal abuse or races | Double submits, or appealing after a resolution | One appeal per hide, status checks, `lockForUpdate` in a transaction |
| 7 | No moderator bootstrap | Without a seeder or command the feature can't be used | Add an artisan command or seeder and document it |
| 8 | Client contract change | The new transformer fields could break existing RealWorld frontends | Only add fields, never rename; keep defaults falsy |
| 9 | Audit gap | Hide and restore decisions are contestable and need a record | Store who and when in the columns; consider a log table later |
| 10 | Old framework | Laravel 5.5 (no `nullOnDelete()` helper, older test APIs) | Use 5.5-compatible syntax and run the migrations on a fresh DB |

Riskiest: #1, hidden comment bodies leaking through the existing comment serialization paths.
