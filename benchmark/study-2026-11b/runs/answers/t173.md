## Current state

`starlette/middleware/sessions.py:24-36` currently defaults to `same_site="lax"` and `https_only=False`. With those defaults the cookie gets `httponly; samesite=lax` and no `secure` flag. These are documented in `docs/middleware.md:235-237`. `tests/middleware/test_session.py:130-163` already shows the main danger: when `https_only=True`, a client on `http://testserver` never sends the cookie back, so the session is silently empty.

## Ways this could go wrong (before planning)

1. **Sessions silently vanish over plain HTTP.** Local dev (`uvicorn` on `http://localhost`), the default `http://testserver` TestClient base URL, and apps behind a TLS-terminating proxy without `--proxy-headers` would all lose session state. Nothing raises an error. Logins just "don't stick".
2. **Strict breaks top-level cross-site navigation.** If a user follows a link from email, Slack or a search result into the app, the browser doesn't send the cookie on that first request, so they look logged out. OAuth/OIDC/SAML callbacks are cross-site redirects, so state or nonce values stored in the session are lost and login flows fail. Authlib's Starlette integration, for example, keeps OAuth state in `request.session`.
3. **Existing test suites break.** Downstream projects' tests that use the default `TestClient` over `http://` and rely on sessions persisting between requests would start failing. So would several tests in this repo, e.g. `test_session.py:64` and `:175`, which use `http://`.
4. **Hidden breaking change in a minor release.** Users who never passed these arguments get new behaviour with no warning. That needs a release note and probably a major or minor version-policy decision.
5. **Naming mismatch.** A parameter called `https_only` that defaults to `True` reads oddly. Renaming it (e.g. `secure=`) would add API churn and deprecation work.
6. **Docs drift.** The defaults are stated in `docs/middleware.md`, and its example at line 250 tells users to set `https_only=True`, which would become redundant. AGENTS.md also requires prose after each heading before any code.
7. **The clear-session cookie must match.** The expiry cookie reuses `security_flags`, so it stays consistent automatically. That's fine, but it's worth asserting in tests.
8. **Duplicate PR.** AI_POLICY.md bans contributors who open duplicate PRs. Upstream has discussed this before, so search issues, PRs and discussions first.

## Assumptions (non-interactive)

- I'm changing the defaults only: `same_site="strict"` and `https_only=True`. The parameter names and the `Literal` type stay as they are, and nothing is renamed.
- Explicit `same_site="lax"` / `https_only=False` remain supported as the opt-out.
- No environment auto-detection, e.g. skipping `Secure` on localhost. That would be implicit magic, and Starlette avoids it.
