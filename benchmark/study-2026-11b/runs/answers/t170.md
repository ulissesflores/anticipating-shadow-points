**Where the code stands.** `ArticleUpdate` (`articles/routers.go:152-160`) already regenerates the slug when the title changes. It overwrites `articles.slug` in place and keeps no record of the old value. Every `:slug` route calls `FindOneArticle(&ArticleModel{Slug: slug})`, so the old URL returns 404 after a rename. Only the "without breaking links" half of the request is missing. I haven't edited any file.

**Assumptions**
- Old slugs should keep working indefinitely, as long as the article exists.
- Reads (`GET /articles/:slug` and `GET /articles/:slug/comments`) resolve an old slug to the same article. The response body carries the new canonical `slug`, so clients can update their links. Plain JSON-API behavior is enough, with no HTTP 301.
- Write routes (PUT, DELETE, favorite, comments) also accept old slugs. They all share one lookup, so this costs nothing extra.
- The design is a new `ArticleSlugAlias` table (`slug` unique, `article_id`), written in the same transaction as the rename. `FindOneArticle` falls back to it when the direct lookup misses. The table is added through GORM AutoMigrate.
- `makeUniqueSlug` must also check the alias table, so no new article or rename can take a retired slug.
- Renaming back to a title whose slug is one of the article's own aliases reuses that alias. It doesn't create a `-2` variant.
- Deleting an article removes its aliases.

**Ways it could go wrong**
1. **Slug hijack:** a new article or rename claims a retired slug, so the shared link now shows someone else's content.
2. **Spurious renames:** the code compares the new base slug (`foo`) with the stored slug (`foo-2`), so re-saving an unchanged title changes the URL.
3. **Alias chains and loops:** A→B→A, or renaming back and forth, leaves duplicate or dangling alias rows.
4. **Partial writes:** the slug update and the alias insert run in separate statements. A failure between them leaves the old URL dead.
5. **Concurrent races:** the unique-slug check isn't atomic, and two renames can collide. The existing retry covers only `articles.slug`, not the alias table.
6. **Soft deletes:** a soft-deleted article's slug and aliases still occupy the unique index. Hard-deleting it or restoring it can orphan or revive aliases.
7. **Authorization leaks:** resolving aliases on write routes must not skip the author checks (403).
8. **Existing deployments:** the new table needs a migration. Articles renamed before this change have no alias, so their old links stay broken.
9. **Client caching and API contract:** clients that cache by slug see a different `slug` in the response than the one they requested. Tests and Hurl/Bruno suites that expect a 404 for the old slug will fail.
10. **Performance:** the fallback lookup adds a query to every 404, and the alias table grows without bound.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Retired slug reclaimed | `makeUniqueSlug` checks only `articles` (`models.go:299`) | Check aliases too; unique index on alias slug |
| 2 | Spurious rename on same title | `base != articleModel.Slug` compares against a suffixed slug | Compare against the stored slug's base, or the old title's base |
| 3 | Alias loops or duplicates | Rename-back reinserts an existing alias | Remove the alias when the slug returns to being canonical |
| 4 | Partial write | `Update` and alias insert are separate | One DB transaction for both |
| 5 | Concurrent rename race | Count-then-insert isn't atomic | Keep unique indexes and retry on `ErrDuplicatedKey` for both tables |
| 6 | Soft-delete and alias drift | `Unscoped` collisions, `gorm.Model` soft delete | Delete aliases with the article; test the restore path |
| 7 | Auth bypass via alias | Handlers use the lookup result as-is | Resolve aliases in `FindOneArticle` only; keep the author check after it |
| 8 | Old renames not covered | No history for past slug changes | Document it; no backfill is possible |
| 9 | Contract and test breakage | Specs and tests assume the old slug 404s | Update the Hurl/Bruno and unit tests; document the canonical `slug` in responses |
| 10 | Query overhead and growth | A second query on every miss; unbounded rows | Index the alias slug; cap or prune aliases if needed |

Riskiest: #1, a retired slug reclaimed by another article, which silently sends shared links to the wrong content.
