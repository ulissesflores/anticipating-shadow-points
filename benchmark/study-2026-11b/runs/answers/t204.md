## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Sessions silently stop working over plain HTTP | Browsers and httpx drop `Secure` cookies on `http://`. Dev servers and the default test client are HTTP, and nothing raises. | Release note, a docs section on opting out, and a clear migration snippet. |
| 2 | Breaking change for every existing user | The defaults change for everyone who didn't set them explicitly. | Gate the change behind a deprecation warning, or ship it in a major or minor release with a loud note. |

| 5 | Behind a TLS-terminating proxy, `Secure` still works but test clients and health checks may not | The cookie is set regardless of the scheme, so the browser decides. Internal HTTP clients drop it. | Document the proxy case. |
| 6 | Docs examples contradict the new defaults | `docs/middleware.md` and `docs/config.md` assume the old values. | Grep the docs and update them in the same PR. |
| 7 | Duplicate-PR ban under `AI_POLICY.md` | A prior proposal or rejection may already exist. | Search PRs, issues, and discussions before opening. |
