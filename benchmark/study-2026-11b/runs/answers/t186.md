## Plan: let users download their data as a single JSON file

I didn't edit any project files. The full plan is saved in the plan file at `claude-home/plans/let-every-user-download-immutable-sundae.md`.

**Assumptions** (non-interactive run, so I chose these instead of asking):
- **Format:** one JSON file named `flasky-export-<username>-<date>.json`, sent as a download. No ZIP or CSV.
- **Who can export:** each user can export only their own data. There is no admin "export anyone" option.
- **Timing:** the file is built while the user waits. The app has no background job queue, and the data sizes are small.
- **What's included:**
  - Profile fields, including email.
  - All of the user's posts.
  - All of the user's comments. Comments a moderator disabled are included and marked as disabled.
  - The usernames the user follows and is followed by. This is a small extra and easy to drop.
- **What's left out:** `password_hash`, `avatar_hash`, internal role and permission fields, tokens, and anything other users wrote.

**Changes**
1. **`app/models.py`:** add `User.to_export_dict()`. It returns `export_format_version`, `generated_at`, `profile`, `posts[]`, `comments[]` (each with `post_id`, `post_url` and `disabled`), `following[]` and `followers[]`.
   - It uses ISO-8601 UTC timestamps and one ordered query per collection.
   - I would not reuse the existing `to_json()` methods. They return API links and raw datetime objects, and they run a `.count()` query for every row.
2. **`app/main/views.py`:** add a new `@main.route('/export')` behind `@login_required`.
   - It always exports `current_user`, so there is no id in the URL and no way to request someone else's data.
   - The response is `application/json` with `Content-Disposition: attachment` and `Cache-Control: no-store`.
3. **`app/templates/user.html`:** add a "Download my data" button next to "Edit Profile". It sits inside the existing `{% if user == current_user %}` check, so it only shows on your own profile.
4. **Tests in `tests/test_client.py` and `tests/test_user_model.py`:**
   - A logged-out request is redirected to login.
   - The download header is set and the counts are correct.
   - A disabled comment is marked as disabled.
   - The secret fields are absent from the raw response.
   - Other users' post text does not appear.
   - Non-ASCII text survives the export unchanged.
   - A user with no posts or comments gets empty lists.
5. **No database migration** is needed.

**How to check it:** run `flask test`. Then seed data with `app/fake.py`, log in, download your own export, confirm the button doesn't appear on other profiles, and confirm `/export` redirects to login when you're logged out.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Leaking secrets in the export | `User` has `password_hash` and `avatar_hash` columns; a generic column dump would include them | Explicit allow-list of fields; a test checks those strings aren't in the body |
| 2 | Leaking other users' data | Comments belong to other people's posts; followers are other users | Export post id and URL only, not post text; usernames only for followers |
| 3 | Access control mistake (IDOR) | An `/export/<id>` route would let anyone fetch anyone's data | No id in the URL; always use `current_user`; `@login_required` |
| 4 | Slow or large response | No background job queue; heavy users mean big queries and a big file | One query per collection; add streaming or a queue only if it's ever needed |
| 5 | Repeated queries per row (N+1) | Existing `to_json()` runs `.count()` for every row | Use a separate export serializer instead of `to_json()` |
| 6 | Wrong or ambiguous timestamps | Times are stored without a timezone (`utcnow`), and Flask's `jsonify` uses an older date format | `.isoformat()+'Z'`, applied the same way everywhere |
| 7 | Cached personal data | The browser or a proxy could keep a copy of the file with the user's email | `Cache-Control: no-store` |
| 8 | Unconfirmed users can't export | `auth.before_app_request` redirects unconfirmed users | Accept for now and document it; exempt the export route later if required |
| 9 | Format drift breaks old exports | Users or tools may parse the file later | `export_format_version` field |
| 10 | Disabled comments surprise users | Moderated comments are hidden in the UI but still belong to the user | Include them with `disabled: true` |

Riskiest: #1. A single missed field in the export puts a password hash or private data into a file that users download and share.
