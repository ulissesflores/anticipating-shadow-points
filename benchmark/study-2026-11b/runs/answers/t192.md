I've written the plan to `<config>/plans/let-moderators-hide-abusive-distributed-prism.md` and changed no repo files. In short: add a moderator flag, a hide record with the appeal on it, three new requests and one new controller, and filter the comment list.

**What's there today:** Comments can only be created, listed and deleted. Only the comment's author can delete it, checked in `app/Http/Requests/Api/DeleteComment.php:14`. There are no roles, no soft-hide and no notifications. Permission checks live in request classes, not policies.

**Assumptions**
- **Moderators:** a new `users.is_moderator` flag, set through the seeder or directly in the database. There is no API to grant it.
- **Hiding:** it is reversible, not a delete. Hidden comments disappear from the list for everyone except the author and moderators.
- **Appeals:** the author gets one appeal per hide. The 7-day window starts when the comment was hidden, includes the last moment of day 7, and uses server time (UTC).
- **Decisions:** any moderator can decide an appeal. "Overturn" makes the comment visible again; "uphold" keeps it hidden for good.
- **Notifications:** none. The author sees the hide status and appeal deadline as new fields on their own comment.

**Plan**
1. **Database changes (three new migrations):**
   - `users.is_moderator` (true/false).
   - `comments.hidden_at` (nullable timestamp), indexed with `article_id`.
   - A new `comment_moderations` table with one row per hide: moderator, reason, `hidden_at`, appeal message and time, appeal status (pending / upheld / overturned), who resolved it, when, and a note.
2. **Models:**
   - `User::isModerator()`.
   - On `Comment`: links to its hide records, `isHidden()`, `appealDeadline()`, and a `visibleTo($user)` filter.
   - A new `CommentModeration` model.
   - `config/moderation.php` with the 7-day window as a setting.
3. **Comment list:** `CommentController@index` (`app/Http/Controllers/Api/CommentController.php:33`) uses `visibleTo(auth()->user())`. `CommentTransformer` only gains fields (`hidden`, plus a `moderation` block when hidden), so existing RealWorld clients are unaffected.
4. **New request classes** (same style as `DeleteComment`):
   - `HideComment`: moderators only.
   - `AppealComment`: the author only; the comment is hidden, not yet appealed, and within 7 days.
   - `ResolveAppeal`: moderators only; the appeal is still pending.
   - Each one also checks that the comment belongs to the article in the URL. Today any comment ID works under any article.
5. **New `CommentModerationController` and routes:**
   - `POST articles/{article}/comments/{comment}/hide`
   - `POST articles/{article}/comments/{comment}/appeal`
   - `GET moderation/appeals?status=pending`
   - `POST moderation/appeals/{moderation}/resolve`

   Each write runs in a database transaction and locks the hide record while it changes it.
6. **Test data:** a moderator option in the factory and an optional moderator user in the seeder.
7. **Tests:** a new `tests/Feature/Api/CommentModerationTest.php`:
   - Permissions on every route: non-moderators can't hide or resolve, other users can't appeal.
   - Who can see a hidden comment.
   - The deadline at exactly 7 days and 7 days plus one second (frozen clock with `Carbon::setTestNow`).
   - A second appeal is rejected.
   - "Overturn" brings the comment back; "uphold" keeps it hidden.
   - A comment ID that doesn't match the article.

   Run `vendor/bin/phpunit`; the existing `CommentTest` must still pass unchanged.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments still show up | Every query on `$article->comments()` has to be filtered by hand | Use the `visibleTo` filter; test the list as a logged-out user, another user, the author and a moderator |
| 2 | Comment ID not checked against the article | `Comment $comment` is looked up by ID only, regardless of the article in the URL | Check `comment->article_id == article->id` in every request class |
| 3 | Deadline off by one | Time zone, and whether day 7 counts | Count from `hidden_at` in UTC, include the end; test with a frozen clock |
| 4 | Two appeals or two decisions at once | Concurrent requests can both pass the checks | Transaction plus row lock; check status before writing |
| 5 | Author deletes the evidence | The existing delete still lets authors remove hidden comments | Keep the reason in `comment_moderations`; consider blocking delete while an appeal is pending |
| 6 | No safe way to make someone a moderator | No roles or admin API exist | Set it only through the seeder or database; never accept it from `UpdateUser` input |
| 7 | API clients break on the new response shape | The comment format follows the RealWorld spec | Only add fields; never remove or rename |
| 8 | Author never learns their comment was hidden | No notification system exists | Show `hidden` and `appealDeadline` to the author; email later if wanted |
| 9 | Migrations fail on the test database | Enum columns and foreign keys behave differently on SQLite vs MySQL | Store status as a string; run migrations on both |

Riskiest: #1. A hidden abusive comment leaking through any unfiltered query defeats the whole feature.
