## What exists today (Laravel 5.5 RealWorld API)
- **Comments:** `app/Comment.php` has only `body`, `user_id`, `article_id` and timestamps. There's no status or soft-delete column.
- **Routes:** `routes/api.php:36` gives comments `index`, `store` and `destroy`. `CommentController@index` returns every comment on the article, unfiltered.
- **Authorization:** it's done inside FormRequests. `DeleteComment::authorize()` just checks `user_id == auth()->id()`. `AuthServiceProvider` has no real policies.
- **No roles:** the `users` table has no admin or moderator concept at all.
- **Response shape:** `CommentTransformer` returns the RealWorld spec shape, which frontends depend on.
- **Tests:** feature tests are in `tests/Feature/Api/CommentTest.php`. `TestCase` creates two users and a JWT header.
- **Existing bug:** the `{article}` route parameter isn't checked in `destroy`, so a comment can be reached through any article's slug. New hide and appeal routes would copy this bug if they reuse the pattern.

## Ways this could go wrong
1. **Hidden comments still leak.** If hiding is only enforced in `index`, they still come back from `store` responses, from eager loads and from any future endpoint.
2. **Moderator check is wrong.** There's no role system, so an ad-hoc check could be skipped. Or the `auth.api:optional` middleware could let a guest reach a moderator path.
3. **Author not treated as author.** The author may be blocked from seeing their own hidden comment, so they can't find out it was hidden or appeal it.
4. **The 7-day window is computed wrong.** If it's counted from `created_at` instead of the hide time, or with timezone drift, the window is wrong. A comment that's hidden, restored and hidden again needs its own window per hide.
5. **Repeat or racing appeals.** Several appeals per hide, or two requests at once, could create duplicate rows.
6. **Appeals reach the wrong person.** Someone other than the author could appeal, or a moderator could resolve an appeal on their own hide decision.
7. **The spec contract breaks.** New fields, or changed 404/403 behaviour, could break RealWorld frontends.
8. **The migration and the tests drift apart.** The new non-null columns need defaults, and the test DB (`realworld_test`) must be migrated.
9. **No audit trail.** If hide/unhide overwrites a single flag, nobody can tell who hid what or why.
10. **Article routes aren't checked.** The comment's `article_id` isn't matched against the route's article, as noted above.

## Assumptions
- "Hide" means a moderator hides the comment so it can be undone. It is not deleted.
- Other users and guests can't see a hidden comment. The author still sees their own, marked as hidden.
- Moderators are marked by a new `users.is_moderator` boolean (default false) and set by seeding or the DB. There's no admin UI for this.
- The 7 days run from `hidden_at`. Each hide allows one appeal, with an optional text message.
- A moderator resolves an appeal by accepting it (the comment is unhidden) or rejecting it (it stays hidden). A moderator can't resolve an appeal against their own hide.

## Plan
1. **Migrations**
   - `users.is_moderator` (bool, default false).
   - On `comments`: `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users), `hidden_reason` (nullable text).
   - A new `comment_appeals` table: `id`, `comment_id`, `user_id`, `hidden_at` (a snapshot of the hide being appealed), `message`, `status` (pending/accepted/rejected), `resolved_by`, `resolved_at`, timestamps. It gets a unique index on `(comment_id, hidden_at)`, so there's one appeal per hide and racing requests can't both get in.
2. **Models**
   - `Comment`: add the casts, `scopeVisibleTo(?User $viewer)` (shows comments where `hidden_at` is null, or where the viewer is the author or a moderator), `isHidden()`, `appealDeadline()` (= `hidden_at + 7 days`) and an `appeals()` relation.
   - `User`: add `isModerator()`.
   - New `CommentAppeal` model.
3. **Authorization:** add `app/Policies/CommentPolicy.php` and register it in `AuthServiceProvider`.
   - `hide` / `unhide`: the user is a moderator.
   - `appeal`: the user is the author, the comment is hidden, the deadline hasn't passed and there's no appeal for this hide yet.
   - `resolveAppeal`: the user is a moderator and isn't the one who hid the comment.
   - New FormRequests (`HideComment`, `AppealComment`, `ResolveAppeal`) follow the `DeleteComment` pattern. Each calls the policy and checks `comment->article_id === article->id`.
4. **Routes and controller**, in the `auth.api` group:
   - `POST articles/{article}/comments/{comment}/hide` with `{reason}`
   - `DELETE …/hide` to unhide
   - `POST …/appeal` with `{message}`
   - `PUT …/appeal` with `{status: accepted|rejected}`
   - Accepting an appeal clears `hidden_*` inside a DB transaction.
5. **Reading comments:** in `CommentController@index`, use `$article->comments()->visibleTo(auth()->user())`. `CommentTransformer` adds `hidden: bool` (plus `appealDeadline` and appeal status) only when the viewer is the author or a moderator. Everyone else gets the spec shape unchanged.
6. **Out of scope:** notifications, a moderator queue UI, and an endpoint listing pending appeals. The last one is an easy addition if needed.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments still visible | `index` returns everything, and `Comment` loads `user` on every query, so filtering in one place is easy to miss | `visibleTo` scope plus tests that check guests and other users |
| 2 | Wrong people can hide or resolve | There are no roles today, and checks live in each FormRequest | `is_moderator` plus `CommentPolicy`, and 403 tests |
| 3 | Comment reached through the wrong article | `destroy` already ignores `{article}` | Check `article_id` in every new request |
| 4 | Appeal deadline wrong | It's easy to use `created_at`, or to share one window across repeat hides | Deadline = `hidden_at + 7d`, with time-frozen tests |
| 5 | Duplicate appeals | Two requests at once can both pass the check | Unique `(comment_id, hidden_at)` index |
| 6 | Author can't see their hidden comment | A blanket filter hides it from the author too | Scope lets the author see their own comment |
| 7 | RealWorld clients break | `CommentTransformer` returns the spec shape | Extra fields only for author or moderator |
| 8 | Moderator reviews their own hide | No separation between hider and reviewer | Policy blocks `hidden_by == resolver` |
| 9 | No record of moderation | A single flag gets overwritten | Store `hidden_by`/`reason`; appeals table keeps history |
| 10 | Migration or test DB out of sync | New columns, and the tests use a separate DB | Nullable or defaulted columns; migrate `realworld_test` in CI |

Riskiest: #1 — hidden comments leaking through a read path that skips the visibility scope, which defeats the whole feature.
