## Assumptions
- The app is a Laravel 5.5 RealWorld API. `User` has no role or admin concept, and comments are hard-deleted. `DeleteComment` allows only the author to delete. `CommentController@index` and `CommentTransformer` expose every comment.
- "Moderator" will be a new `users.role` column (or `is_moderator` flag) with a policy check, not a separate auth system.
- "Hide" means a soft state, not deletion. The comment stays in the database but is removed from public listings.
- The appeal is a single appeal per hide. The 7 days run from the hide time. The author submits it with a reason. A moderator, other than the one who hid the comment, decides it. An approved appeal unhides the comment.
- There is no mail or queue setup. Notifications are out of scope.

## Ways this could go wrong (before planning)
- **Authorization:** Any logged-in user hides comments, because there is no role system. A moderator hides their own critics. The hiding moderator also decides the appeal. An author appeals someone else's comment. A mass-assignable `role` field lets a user promote themselves, because `User::$fillable` is open to registration and update payloads.
- **Visibility leaks:** Hidden comments still appear in `index`, in the author's own view, or in any path that skips the new scope. `$with` and the transformer don't know about the hidden state. A hidden body leaks through the appeal response or moderator endpoints. Other consumers of `comments()` bypass the filter.
- **Deadline logic:** "7 days" is computed in a different timezone or from `updated_at` instead of the hide time. A boundary appeal at day 7 is accepted or rejected inconsistently. Re-hiding after an approved appeal restarts or evades the window.
- **State machine:** There are concurrent or duplicate appeals, and an appeal on a comment that is no longer hidden or was deleted. The author deletes a hidden comment to escape review. Cascade deletes remove the evidence when a user or article is deleted.
- **Data and migrations:** Existing rows need safe defaults, so the migration must not lock a large table or break the existing API contract. Rollback must work.
- **API contract:** New fields or status codes break RealWorld-spec clients.
- **Abuse:** Appeal spam, with no rate limit or length cap. Moderators have no audit trail.
- **Testing gaps:** The existing feature tests assume authors alone mutate comments. Time-dependent behaviour needs frozen time.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Privilege escalation via roles | No role system exists, and `User::$fillable` is open | Guard `role` out of `$fillable`, and add a policy plus tests |
| 2 | Hidden comments leak | `index`, `$with` and the transformer have no hidden state | Global scope, plus a moderator-only opt-in |
| 3 | Moderator conflict of interest | Hider and appeal reviewer could be the same person | Require a different reviewer, and log both |
| 4 | 7-day window miscalculated | Timezone and `updated_at` pitfalls, boundary cases | Store `hidden_at`, compute in UTC, freeze time in tests |
| 5 | Appeal races and duplicates | Concurrent requests, and appeals on non-hidden comments | Unique appeal per hide, row lock, state checks |
| 6 | Author deletes to dodge review | `DeleteComment` lets authors delete freely | Block delete while an appeal is pending, or keep an audit copy |
| 7 | Migration breaks existing data | Existing comments need defaults, and rollback must work | Nullable columns, default visible, tested `down()` |
| 8 | API contract drift | RealWorld clients expect the current comment shape | Add fields only for moderators and authors, and keep the default shape |
| 9 | Appeal and moderation abuse | No rate limits, and no record of who did what | Throttle, cap length, add an audit table |
| 10 | Thin test coverage | Tests only cover author actions today | Feature tests per role, state and time boundary |

Riskiest: #1, privilege escalation through the missing role system, because every other control depends on that check being right.
