# Plan: online visit booking with no double-booked vets

## Findings
- `Visit` has only `visit_date` (a date) and `description`. It has no vet and no time of day, so "same vet at the same time" can't be expressed or enforced today.
- `VisitController.processNewVisitForm` binds `Visit`, checks the date is in the future, then does `owner.addVisit(petId, visit)` followed by `owners.save(owner)`. Nothing checks availability.
- `visits` is defined separately in `db/{h2,mysql,postgres}/schema.sql`, and `spring.jpa.hibernate.ddl-auto=none`. Schema changes therefore go in all three scripts by hand.
- `Vet` and `VetRepository` already exist, and the form template is `templates/pets/createOrUpdateVisitForm.html`.
- Tests exist at `VisitControllerTests`, `ClinicServiceTests` and `PetClinicConcurrencyTests`, plus the MySQL and Postgres integration tests.

## Assumptions
1. Appointments use fixed 30-minute slots from 09:00 to 16:30, on weekdays. Slot length, hours and weekdays are constants in one place and are easy to change.
2. The owner picks a vet. An "any available vet" option is out of scope.
3. A slot is booked by exactly one visit. Cancelling or rescheduling is out of scope.
4. Existing visits have no vet or time. They stay as-is, with nullable new columns, and don't take part in conflict checks.
5. Vet working schedules, holidays and time zones are out of scope. Clinic-local time is used.

## Design
The database enforces the rule. Application-level checks only give friendly messages. A check-then-insert in Java would race under concurrent requests.

1. **Schema** (all three `schema.sql` files, plus `data.sql` if seed visits need values):
   - Add `vet_id INTEGER` (FK to `vets`) and `visit_time TIME` to `visits`.
   - Add `UNIQUE (vet_id, visit_date, visit_time)`. H2, MySQL and Postgres all allow multiple NULLs in a unique index, so legacy rows don't collide.
2. **Model**: add `@ManyToOne Vet vet` and `LocalTime time` to `Visit`. Validate both with `@NotNull` on the new-booking path.
3. **Slot logic**: a small `VisitSlots` helper in the `owner` package generates the day's slots. A `VisitRepository` query (`findBookedTimes(vetId, date)`) returns the taken ones. The form shows only free slots.
4. **Controller**:
   - Add a `vets` model attribute and a slot-lookup endpoint, or render slots server-side when a vet and date are chosen.
   - In `processNewVisitForm`, validate that the time is a legal slot, then `save`. Catch `DataIntegrityViolationException` and reject the `time` field with "That slot was just taken". Return the form with fresh slots.
   - Keep the existing "date must be after today" rule.
5. **UI and i18n**: add vet select and time select to `createOrUpdateVisitForm.html`. Add message keys to every `messages_*.properties`, because `I18nPropertiesSyncTest` requires them in sync.
6. **Binding safety**: keep `id` disallowed in the binder. Resolve the vet by id from the repository and don't bind a nested `Vet` object.

## Tests
- **Unit and controller**: add cases to `VisitControllerTests` for a valid booking, a taken slot (the constraint exception maps to a field error), a non-slot time, and a weekend.
- **Service**: in `ClinicServiceTests`, two visits for the same vet, date and time throw `DataIntegrityViolationException`. The same time with a different vet succeeds.
- **Concurrency**: extend `PetClinicConcurrencyTests` so N threads book the same slot and exactly one succeeds.
- **Cross-database**: run the MySQL and Postgres integration tests, since the constraint DDL differs per dialect.
- **Manual**: run the app, book a slot, then try again from a second browser session and confirm the slot is gone or rejected.

## Rollout
Because `ddl-auto=none`, existing deployed databases need a migration (`ALTER TABLE` plus the unique index). The repo has no Flyway or Liquibase, so ship the SQL in the PR notes, or add a migration tool as a separate change.

## Risks
| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Race between two owners booking the same slot | A check-then-save in Java passes for both requests | DB unique constraint on (vet, date, time); map the violation to a form error |
| 2 | Schema drift across H2, MySQL and Postgres | Three hand-maintained `schema.sql` files and `ddl-auto=none` | Edit all three together; run the MySQL and Postgres integration tests |
| 3 | Existing deployed DBs lack the new columns | No migration tool in the repo | Provide an explicit `ALTER` script; consider Flyway separately |
| 4 | NULL handling in the unique index | Legacy visits have no vet or time | Nullable columns; unique indexes permit multiple NULLs on all three DBs; test it |
| 5 | Exception not translated as expected | Save happens via `Owner` cascade, so the violation may surface at flush or commit | Test the controller path against a real DB; catch at the save call and in a fallback handler |
| 6 | Overlap only blocked for identical start times | A unique key doesn't catch partial overlaps | Fixed slot grid enforced server-side; reject any non-grid time |
| 7 | Form binding tampering | A user could post arbitrary vet ids or times | Resolve the vet via repository; validate the time against the slot list |
| 8 | i18n test breaks | `I18nPropertiesSyncTest` needs the same keys in all locale files | Add keys to every `messages_*.properties` |
| 9 | Stale slot list shown to the user | The slot is taken between page render and submit | Re-render with fresh slots and a clear error on conflict |
| 10 | Scope creep (cancellation, schedules, time zones) | Real clinics need them | State the assumptions; defer to follow-ups |

Riskiest: #1, the double-booking race, which is the core requirement and only the DB constraint fully closes.
