The change itself is two default values in `SessionMiddleware`; most of the work is in the tests and in documenting a breaking change. I wrote the plan to `claude-home/plans/make-the-session-middleware-s-melodic-ullman.md` and edited nothing else.

**Assumptions** (non-interactive run, so I didn't ask):
- The `same_site` and `https_only` options stay, so users can still opt out. Only their defaults change.
- No new `secure=` alias is added; `https_only` remains the switch for the Secure flag.
- This is a breaking change and goes out in the next release (current version is 1.10.0) with a clear release note.

### Plan
1. **Code** (`starlette/middleware/sessions.py:24-25`): change the defaults to `same_site="strict"` and `https_only=True`. The existing code at lines 33-35 already writes `samesite=…; secure` correctly, so nothing else changes.
2. **Tests** (`tests/middleware/test_session.py`): the test client defaults to `http://testserver`, and httpx won't send a Secure cookie back over plain http. So every test that reads the session on a second request will break, including `test_session`, `test_session_expires`, `test_session_cookie_subpath`, `test_invalid_session_cookie` and `test_session_persists_mutations`.
   - Switch those tests to `base_url="https://testserver"`, or pass `https_only=False` where the test is really about http.
   - Update the exact `Set-Cookie` string checks to expect `samesite=strict; secure`.
   - Add one test that the new defaults are applied, and one that opting out (`https_only=False, same_site="lax"`) still works.
   - Keep test coverage at 100%.
3. **Docs** (`docs/middleware.md`, SessionMiddleware section): update both defaults. Add a short note on opting out for local http development, and on using `same_site="lax"` when an OAuth/SSO login or links from other sites need the session. AGENTS.md requires explanatory text after each heading, before any code snippet.
4. **Release notes** (`docs/release-notes.md`): add a "Changed" entry marked as breaking.
5. **Check**: run `scripts/test` and `scripts/check`. Then start a small app with uvicorn over both http and https and check the `Set-Cookie` header and how a browser handles it.

### Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | OAuth/SSO logins break | Login libraries keep their state check in `request.session`. The return trip from the identity provider is a cross-site navigation, so a Strict cookie isn't sent and the check fails | Explain in the docs and release note that `same_site="lax"` is needed for these flows |
| 2 | Silent logout over plain http | The browser won't send a Secure cookie back over http, so the session looks empty on every request. No error is raised | Highlight the opt-out for http in the docs |
| 3 | Large test fallout | The test client's default URL is `http://testserver`, so most session tests stop sending the cookie | Use an `https://` base URL in the affected tests |
| 4 | Users' own test suites break | Downstream apps test with Starlette's default test client over http | Breaking-change note with a one-line fix |
| 5 | Logged out when arriving from another site | With Strict, the first visit from an email or another site's link arrives without the cookie, so a logged-in user looks logged out | Document the trade-off; Lax remains an option |
| 6 | Safari and localhost | Older Safari versions reject Secure cookies on `http://localhost`, unlike Chrome and Firefox | Mention local development in the docs |
| 7 | Wrong version bump | This is a breaking default change in a minor-version line | Maintainers decide the release; label it clearly |
| 8 | Duplicate PR | AI_POLICY.md bans contributors who open duplicate PRs | Search PRs, issues and discussions first |
| 9 | Frameworks built on Starlette inherit it | FastAPI and others re-export `SessionMiddleware`, so their users get the change without warning | Clear release note; consider pinging the downstream projects |

Riskiest: #1. OAuth/SSO callbacks fail with a confusing state-mismatch error once the default is SameSite=Strict.
