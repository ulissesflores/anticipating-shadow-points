# Plan: moderator comment hiding, with a 7-day author appeal

The repo is a Laravel 5.5 "RealWorld" API. It uses JWT auth and has no roles or policies. `AuthServiceProvider` maps only a placeholder policy. Comments live in `comments` (`id`, `user_id`, `article_id`, `body`, timestamps). The API exposes `GET/POST/DELETE articles/{article}/comments`. `DeleteComment` authorizes by `user_id == auth()->id()`. `CommentController@index` returns every comment. `CommentTransformer` is the response shape. Nothing in `tests/Feature/Api` covers moderation yet.

## Assumptions

- Moderators are a new concept. I'll use a nullable-default `users.is_moderator` boolean. Granting it is done out of band (tinker or seeder), with no API to grant it.
- "Hide" is a soft state, not deletion. The row stays, the body is withheld from the public, and the action is reversible.
- Hiding records who hid it, when, and a required reason.
- The appeal window is 7×24h from `hidden_at`. One appeal per hide. A moderator reviews it and either restores the comment or upholds the hide. A comment that was hidden again after restoration starts a new window.
- The author still sees their own hidden comment, with its status, so they can appeal. Everyone else sees a placeholder or nothing (decision below).
- Notifying the author by email is out of scope for v1. The author sees status through the API.

## Design

**Migrations (new files, not edits to existing ones)**
- `users`: add `is_moderator` boolean, default false.
- `comments`: add `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users, null on delete), `hide_reason` (nullable text), and `restored_at` (nullable timestamp).
- New `comment_appeals` table: `id`, `comment_id` (FK, cascade), `user_id`, `body`, `status` (`pending`/`upheld`/`restored`), `decided_by`, `decided_at`, timestamps. Index on `comment_id` and on `status`.

**Models**
- `Comment`: add `isHidden()`, `appealDeadline()` (`hidden_at + 7 days`), `canBeAppealed()` (hidden, within window, no existing appeal for this hide) and an `appeals()` relation. Add a `scopeVisibleTo($user)` query scope.
- `User`: add an `isModerator()` helper.

**Authorization**
- Add `CommentPolicy` with `hide`, `restore` and `appeal`, registered in `AuthServiceProvider::$policies`. `hide` and `restore` require a moderator. `appeal` requires the comment author. Moderators can't hide their own comments through the moderation path, since that would bypass the appeal flow.
- Add form requests `HideComment` and `AppealComment` under `app/Http/Requests/Api`, following the `DeleteComment` pattern.

**Routes** (in `routes/api.php`, under the existing comments group)
- `POST articles/{article}/comments/{comment}/hide` — moderator; body `reason` required.
- `DELETE articles/{article}/comments/{comment}/hide` — moderator; unhide.
- `POST articles/{article}/comments/{comment}/appeal` — author; body `reason` required; rejected with 403 or 422 after the deadline.
- `PUT articles/{article}/comments/{comment}/appeal` — moderator; decide: `restore` or `uphold`.

**Controller**
- A new `CommentModerationController` keeps `CommentController` small. In `CommentController@index`, replace `->get()` with the visibility-scoped query. The `auth.api:optional` middleware already makes `auth()->user()` available.

**Transformer**
- `CommentTransformer` adds `hidden`, and for the author and moderators also `hiddenReason`, `appealDeadline` and `appealStatus`. For the public, a hidden comment either disappears from the list or appears with `body` replaced by a placeholder.

**Edge cases to handle explicitly**
- Hiding an already hidden comment is idempotent.
- The deadline is computed in UTC from the stored timestamp.
- Author deletion of a hidden comment is still allowed (existing `destroy`). Decide whether it cancels a pending appeal.
- Moderator decisions are re-checked inside a transaction, to avoid racing with an author appealing at the deadline.

## Tests (PHPUnit feature tests in `tests/Feature/Api`)
- A moderator can hide and unhide. A non-moderator gets 403.
- Public `index` hides the body. The author and moderators see the hidden comment.
- An author can appeal on day 6 and 23h, and gets 403/422 after 7 days (use `Carbon::setTestNow`).
- A second appeal on the same hide is rejected. Only the author can appeal.
- A moderator can restore or uphold the hide. Restoring clears `hidden_at`.
- Existing comment tests still pass.

## Verification
Run `php artisan migrate`, then `vendor/bin/phpunit`. Then do a manual flow with curl and a JWT: create a comment, hide it as a moderator, fetch it as the author, as another user and anonymously, appeal it, and decide the appeal.

## Open decision
Should hidden comments disappear from public lists, or show as a "hidden by moderator" placeholder? I'd default to a placeholder, because it keeps threads coherent and makes moderation transparent.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden body leaks via another path | `Comment` eager-loads `user`, and the transformer reads raw data, so any new endpoint can bypass the scope | Filter in the transformer/scope, not just `index`; add a leak test |
| 2 | No role system exists | `is_moderator` is a new trust boundary; mass assignment or a bad seeder could grant it | Keep it out of `$fillable`; grant it only via a tinker command or seeder |
| 3 | Appeal deadline errors | Timezones, `updated_at` changes and re-hides can shift the 7-day window | Use a dedicated `hidden_at`, UTC, and `Carbon::setTestNow` tests |
| 4 | Moderator abuse or self-hiding | One flag gives broad power, and there's no audit trail | Store `hidden_by` and a reason; block self-moderation; log decisions |
| 5 | Race at deadline or on double-decide | Concurrent appeal and decision requests can both pass checks | Wrap in a transaction with `lockForUpdate` |
| 6 | Breaking the RealWorld API contract | Frontends expect the fixed comment shape | Add fields only; leave existing keys unchanged |
| 7 | Migration on populated tables | Adding columns and FKs to live `comments` and `users` | Use nullable columns, defaults, and a reversible `down()` |
| 8 | Legacy JWT middleware quirks | Optional auth means `auth()->user()` can be null on `index` | Null-safe visibility scope; test anonymous access |
| 9 | Cascade deletes lose evidence | Deleting a user or article cascades and removes appeals | Keep the appeal FK cascade, or add soft deletes if retention is needed |
| 10 | Old Laravel 5.5 / PHP version | Missing newer helpers and policy conveniences | Stick to 5.5 APIs; run the full suite on the project's PHP version |

Riskiest: #1, hidden comment bodies leaking through an unfiltered path, because that defeats the feature's purpose.
