Authors can already change a title, and the slug changes with it: `ArticleUpdate` regenerates it at `articles/routers.go:152-183`. What's missing is the second half. The old slug is overwritten, so every link to it returns 404. The plan is to keep old slugs as aliases that still resolve to the article. I haven't edited any repository files; the plan is in `plans/let-authors-change-an-sprightly-orbit.md`.

**Ways this could go wrong (checked against the code):**
1. **Delete by an old slug does nothing but reports success.** `ArticleDelete` checks ownership using the slug, then deletes with `DeleteArticleModel(&ArticleModel{Slug: slug})`. Given an old slug, that deletes nothing and still returns 204.
2. **An old slug gets reused by another article.** `makeUniqueSlug` (`models.go:299`) only checks the articles table, so a new article could take a retired slug. Shared links would then quietly open the wrong article.
3. **Renaming back fails.** Going A→B→A collides with the article's own alias unless the alias check ignores aliases the article owns.
4. **Half-finished rename.** The rename and the alias insert happen as separate writes. If the alias insert fails, the article has a new slug and the old one is gone.
5. **Saving the same title still changes the slug.** If the slug is `foo-2`, `base != articleModel.Slug` is true. `makeUniqueSlug` then returns `foo-3`, which piles up aliases for nothing.
6. **Routes behave differently.** If only GET looks up aliases, someone who opens an old link and then comments or favorites gets a 404.
7. **Redirecting instead of serving.** A 301/302 on PUT, DELETE or POST is unsafe, so the plan returns 200 with the current slug instead.
8. **Deleted articles.** Articles are soft-deleted and their slugs stay reserved. Aliases need the same rule: they should still block reuse and still return 404.
9. **Spec test suite.** The hurl/bruno suite expects the slug to change on a title update. That must still hold.

**Assumptions:**
- An old slug returns 200 with the article, and the response carries the current `slug`. There is no redirect.
- Aliases work on every `:slug` route.
- Aliases are never released.
- The SPA updating its own URL from the response is out of scope.

**Plan:**
- **New table:** `ArticleSlugAliasModel` (alias slug, unique; article ID), with no soft delete. Add it to AutoMigrate in `hello.go` and in both test setups.
- **One lookup helper:** `FindArticleBySlug` checks the current slug first, then aliases. Every `:slug` handler uses it.
- **Delete:** delete by article ID instead of by slug.
- **Uniqueness:** `makeUniqueSlug` also checks aliases, but lets an article take back its own.
- **Rename:** do the article update, the alias insert and the cleanup of the article's own alias in one transaction. Keep the existing retry on `ErrDuplicatedKey`; `TranslateError` is already on in `common/database.go`.
- **No needless changes:** skip regeneration when the current slug already matches `base` or `base-N`.
- **Checks:**
  - Unit tests: old slug works on every route, A→B→A, a new article doesn't take an alias, delete then 404, same-title save keeps the slug.
  - Then `go test ./...` and `scripts/run-spec-tests.sh`.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Delete by old slug does nothing but returns 204 | `DeleteArticleModel(&ArticleModel{Slug: slug})` matches nothing for an alias | Delete by `articleModel.ID` |
| 2 | Another article takes an old slug | `makeUniqueSlug` only checks `article_models` | Also check aliases in create and update |
| 3 | Renaming back (A→B→A) blocked | The article's own alias looks like a collision | Ignore aliases owned by the same article; drop that alias on rename |
| 4 | Half-finished rename breaks old links | Article update and alias insert are separate writes | One `db.Transaction` |
| 5 | Saving the same title changes the slug | `foo-2` ≠ base `foo`, so it becomes `foo-3` | Skip when slug already matches `base` or `base-N` |
| 6 | Only some routes accept old slugs | 8 handlers each call `FindOneArticle` by slug | Shared `FindArticleBySlug` helper |
| 7 | Redirect breaks writes | 301 on PUT/DELETE/POST is unsafe | Serve 200 with the current slug |
| 8 | Deleted article's old link opens another article | Soft delete keeps the slug; aliases would be freed if hard-deleted | No soft delete on aliases; reserve forever; 404 |
| 9 | Spec suite fails | hurl/bruno expect slug to change on title update | Run `scripts/run-spec-tests.sh` |
| 10 | Two renames at once collide | SQLite unique index; reserve-then-write race | Unique index on alias slug + existing retry loop |

Riskiest: #2 — if an old slug is handed to a new article, shared links quietly open the wrong article, and nothing errors or logs it.
