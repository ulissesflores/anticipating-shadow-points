# Plan: moderator comment hiding with a 7-day author appeal

I didn't write a plan file, because you said not to edit any file. This is a read-only plan.

## What the code looks like today
- It's a Laravel 5.5 RealWorld API with JWT auth.
- `CommentController` has `index`, `store` and `destroy`, and `index` returns `$article->comments()->get()`.
- `DeleteComment` is the only comment authorization, and it lives in a FormRequest. `AuthServiceProvider` has no real policies.
- `users` has no role or moderator concept.
- `comments` has no status columns.
- `CommentTransformer` always returns `body`.
- Tests live in `tests/Feature/Api/CommentTest.php`.

## Assumptions
1. A moderator is a user with a role flag. Nothing like it exists yet, so I'm adding `users.is_moderator` (boolean, default false). It gets set by seeder or artisan command, not by any API.
2. "Hide" is a soft state. The comment stays in the database but is excluded from public listings.
3. Hidden comments stay visible to their author, to moderators, and to the article's author.
4. The author can submit one appeal per hide, within 7 days of the hide time (`hidden_at`). A moderator then upholds or reverses it.
5. The 7-day window is computed from `hidden_at`. If a hide is reversed and later re-applied, the window restarts.
6. Moderators can't hide their own comments through this flow.
7. The change keeps the RealWorld response shape and only adds fields.

## Implementation steps
1. **Migrations**
   - Add `is_moderator` to `users`.
   - Add to `comments`: `hidden_at` (nullable), `hidden_by` (nullable FK to `users`, `nullOnDelete`), `hidden_reason` (nullable string), `appeal_body` (nullable text), `appealed_at` (nullable), `appeal_status` (nullable string: pending, upheld or reversed), and `appeal_resolved_by` and `appeal_resolved_at` (nullable).
   - Index `hidden_at`.
   - Write the `down()` methods.
2. **Models** (`Comment.php`, `User.php`)
   - `Comment`: add `scopeVisible`, an `isHidden()` helper, and `canAppeal()` (hidden, no existing appeal, and `hidden_at` within the last 7 days).
   - Keep the new fields out of `$fillable`. Set them explicitly in the controller.
   - `User`: add an `isModerator()` helper.
3. **Policy**
   - Create `CommentPolicy` with `hide`, `unhide`, `appeal` and `resolveAppeal`.
   - Register it in `AuthServiceProvider`.
   - Use it from new FormRequests that follow the `DeleteComment` pattern: `HideComment`, `AppealComment` and `ResolveAppeal`.
4. **Routes** (`routes/api.php`)
   - `POST articles/{article}/comments/{comment}/hide`
   - `DELETE articles/{article}/comments/{comment}/hide` (unhide)
   - `POST articles/{article}/comments/{comment}/appeal`
   - `POST articles/{article}/comments/{comment}/appeal/resolve` (moderator only, with `decision` set to upheld or reversed)
   - Add a moderator-only `GET comments/appeals` queue.
5. **Controller changes** (`CommentController` or a new `CommentModerationController`)
   - `index` filters with `visible()`. Moderators, the article author and the comment's own author get their relevant hidden comments included.
   - Check that the `{comment}` belongs to the `{article}` in every new action, and return 404 if it doesn't. The existing `destroy` doesn't check this.
6. **Transformer** (`CommentTransformer`)
   - For viewers who can see a hidden comment, add `hidden`, `hiddenAt`, `appealDeadline`, `appealStatus`, and `hiddenReason` for the author and moderators.
   - Anyone else gets no body and no hidden metadata.
7. **Tests** (extend `CommentTest.php`)
   - A moderator can hide a comment, and a regular user gets 403.
   - A hidden comment is absent from the public list. The author and moderator still see it.
   - An appeal succeeds at day 6 and gets 403 or 422 at day 8, using `Carbon::setTestNow`.
   - A second appeal is rejected, and only the author can appeal.
   - Upholding or reversing an appeal updates the status and visibility.
   - An article/comment mismatch returns 404.
8. **Docs**: describe the new endpoints and fields in `readme.md`.

## Verification
- Run `php artisan migrate` on a fresh SQLite database, then `vendor/bin/phpunit`.
- Do a manual walkthrough with JWTs for a moderator, an author and a third user, covering hide, list, appeal and resolve.
- Check that the existing comment tests still pass.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden body leaks | `index` and `$with` return everything, and the transformer always outputs `body` | Apply the `visible` scope and gate the body in the transformer; test unauthorized reads |
| 2 | No role system exists | `is_moderator` is new, and a mass-assignment slip could grant it | Keep it out of `$fillable` and set it only by seeder or command |
| 3 | Appeal window miscalculated | Timezones, boundary at exactly 7 days, and re-hides can reset it | Store UTC `hidden_at`, centralize in `canAppeal()`, test with `Carbon::setTestNow` |
| 4 | Article/comment mismatch | `destroy` ignores `{article}`, so the same bug could let actions hit another article's comment | Verify `comment->article_id` in each action and return 404 |
| 5 | Unauthenticated `index` | `index` uses optional auth, so viewer-dependent output varies | Resolve the viewer defensively and treat null as a guest |
| 6 | Appeal abuse or races | Double submits or concurrent resolves can produce inconsistent state | Use a conditional update or lock, and a unique appeal per hide |
| 7 | Old Laravel 5.5 and dependencies | Old stack, so modern Laravel features and some packages won't apply | Stick to 5.5 APIs and avoid new syntax |
| 8 | No audit trail | Moderator actions are contested by nature, and hide-then-unhide overwrites history | Add a `comment_moderation_logs` table if disputes matter, or at least keep `hidden_by` |
| 9 | Frontend contract change | RealWorld clients expect a fixed comment shape | Only add fields and keep existing keys unchanged |
| 10 | Migration on a big table | Adding many columns to `comments` can lock a large production table | Use nullable columns with no backfill and run off-peak |

Riskiest: #1, the hidden comment body leaking through the public `index` and the transformer, because the whole feature depends on hidden content not being served.
