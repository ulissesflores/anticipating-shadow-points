## Plan: moderators hide comments, authors appeal within 7 days

**Where the code stands now.** This is the Laravel 5.5 RealWorld API with JWT login. Each request class decides who is allowed to do what (see `app/Http/Requests/Api/DeleteComment.php`), and transformer classes build the JSON. There are no user roles. Comments can only be deleted, and only by their author. The comment route also doesn't check which article a comment belongs to: `CommentController@destroy` ignores `$article`.

### Assumptions
- **Who is a moderator:** a new `users.is_moderator` flag, set by hand (seeder, tinker or SQL). There is no API to grant it.
- **What hiding does:** the comment stays in the database but leaves the public list. Its author and moderators still see it, marked as hidden.
- **Appeals:** one appeal per hide. The window is 7 days from `hidden_at` and can be changed in `config/moderation.php`. A moderator either keeps the comment hidden (`upheld`) or reverses the hide (`overturned`).
- **Notifications:** none in v1. Authors find out from the `hidden` flag on their own comments.
- **API compatibility:** only new JSON fields are added, so existing clients keep working.

### Steps
1. **Database migrations**
   - `users.is_moderator`.
   - On `comments`: `hidden_at` (indexed), `hidden_by` (cleared if that user is deleted) and `hidden_reason`.
   - A new `comment_appeals` table with `comment_id`, `user_id`, `body`, a copy of `hidden_at`, `status`, `resolved_by` and `resolved_at`. A unique key on (`comment_id`, `hidden_at`) allows one appeal per hide.
2. **Models**
   - `User::isModerator()`. `is_moderator` stays out of `$fillable` so users can't make themselves moderators through `PUT /user`.
   - On `Comment`: `isHidden()`, `appealDeadline()`, `canBeAppealed()`, an `appeals()` relation and `scopeVisibleTo(?User)`. That scope returns visible comments for the public, the author's own hidden ones too, and everything for moderators.
   - A new `CommentAppeal` model.
3. **Request classes** (same pattern as `DeleteComment`)
   - `HideComment` and `UnhideComment` (moderator only; hiding requires a reason).
   - `AppealComment` (comment author only).
   - `ResolveAppeal` (moderator only; decision is uphold or overturn).
   - Every comment-scoped request checks that `comment->article_id` matches the article in the URL.
4. **Routes and controllers**
   - `GET …/comments` uses `visibleTo(auth()->user())` and loads appeal status in the same query.
   - `POST` and `DELETE articles/{a}/comments/{c}/hide`.
   - `POST articles/{a}/comments/{c}/appeal`, returning 422 if the comment isn't hidden, the window has closed or an appeal already exists.
   - `GET appeals?status=pending` (moderators, paginated with the existing `Paginate`).
   - `PUT appeals/{id}`. It runs in a transaction, rejects appeals that are already resolved, and an overturn clears the hide fields.
   - A moderator can't resolve an appeal on their own comment.
5. **JSON output**
   - `CommentTransformer` adds `hidden`, `hiddenAt`, `appealDeadline` and `appeal.status`, only when the viewer is the author or a moderator.
   - A new `CommentAppealTransformer`.
6. **Tests** (new `CommentModerationTest` and `CommentAppealTest`, with `Carbon::setTestNow` to control the clock):
   - Hiding: a non-moderator gets 403.
   - Visibility: a hidden comment is missing for anonymous users and other users, and shown with the flag to its author and moderators.
   - Appeal timing: just under 7 days is accepted, 7 days plus one second gets 422.
   - Appeal rules: a second appeal gets 422 and a non-author gets 403.
   - Outcomes: overturn unhides, uphold keeps it hidden, and a re-hide allows a new appeal.
   - Wrong article: a comment ID from another article gets 404.

### How to check it
- Run `php artisan migrate` on a fresh database and on an existing one.
- Run `vendor/bin/phpunit` (uses the MySQL `realworld_test` database).
- By hand: set a moderator in tinker, then with curl hide a comment, list as anonymous and as the author, appeal, and resolve.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments leak | `index` calls `$article->comments()->get()` directly; any other query path skips the filter | Route all reads through `visibleTo()`; test anonymous, other-user and author views |
| 2 | Comment from another article is acted on | The comment route isn't tied to its article, and `destroy` ignores `$article` | Check `article_id` in every new request; 404 test |
| 3 | Users make themselves moderators | `UserController@update` mass-assigns fields | Keep `is_moderator` out of `$fillable`; add a test |
| 4 | Off-by-one at the 7-day limit | Time zones, `now()` vs DB time, inclusive vs exclusive cutoff | One `appealDeadline()` helper, strict `<`, tests with a fixed clock |
| 5 | Double appeal or double resolution | Concurrent requests, no locking today | Unique (comment_id, hidden_at), transaction plus status check |
| 6 | Moderator rules on their own case | No separation of duties exists | Block resolving appeals on your own comment |
| 7 | Hide and appeal state out of sync | Overturn must clear three comment columns and update the appeal | Do it in one transaction; test both outcomes |
| 8 | Extra queries when listing comments | Transformer reads appeal status per comment | Load appeals in the same query (`with('currentAppeal')`) |
| 9 | Migration on a live MySQL database | Adding columns to `users`/`comments` can lock the tables | Only nullable or defaulted columns; run off-peak |
| 10 | Spec or client drift | RealWorld clients expect a fixed comment shape | Only add fields, never change existing ones |

Riskiest: #1. A hidden comment showing up through a query that skips the visibility filter defeats the whole feature.
