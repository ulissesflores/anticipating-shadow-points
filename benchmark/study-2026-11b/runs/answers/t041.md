**Assumptions**
- This is a breaking change, so it ships in the next major release (10.0.0).
- The new default only applies when `AXES_LOCKOUT_PARAMETERS` is unset **and** none of the deprecated lockout flags are set. Those flags (`AXES_ONLY_USER_FAILURES`, `AXES_LOCK_OUT_BY_*`, `AXES_USE_USER_AGENT`) keep their current mapping.
- No database migration is needed, because `AccessAttempt` already stores both username and IP.

**Plan**
1. **`axes/conf.py:37-60`**: move the fallback into a helper, `_get_default_lockout_parameters()`. When no legacy flag is set it returns `[["username", "ip_address"]]` instead of `["ip_address"]`. It builds a new list on each call, because the `AXES_USE_USER_AGENT` branch modifies `[0]` in place. Also fix the outdated comment on line 38.
2. **No handler or check changes.** The lookup and cache-key code in `axes/helpers.py:333-386` already handles combined parameters. The W006 check in `axes/checks.py:181` already accepts a nested list that contains `ip_address`. The verbose startup log in `axes/apps.py` already prints "combination of username and ip_address".
3. **Docs**:
   - Add an `AXES_LOCKOUT_PARAMETERS` row to `docs/4_configuration.rst`, which currently has none.
   - Fix the wording in `docs/5_customization.rst:181`.
   - Change the upgrade line in `docs/2_installation.rst:160` ("no flags" → set `["ip_address"]` explicitly).
   - Mention the default in `docs/3_usage.rst`.
4. **`CHANGES.rst`**: add a breaking-changes entry: "to keep the old behaviour, set `AXES_LOCKOUT_PARAMETERS = ["ip_address"]`".
5. **Tests**:
   - The IP-only tests in `tests/test_login.py:383-407` and `526-550` rely on the old default without saying so. Pin them with `@override_settings(AXES_LOCKOUT_PARAMETERS=["ip_address"])`.
   - Add tests for the new default, for both the database and cache handlers: same user + same IP is blocked; a different user from that IP is allowed; the same user from a different IP is allowed.
   - Unit-test the new helper in `tests/test_conf.py` for every legacy-flag combination. `conf.py` runs once at import, so `override_settings` alone can't test the default.
   - Search `test_handlers.py`, `test_attempts.py`, `test_helpers.py` and `test_logging.py` for other tests that assume the old default.

**Verification**
- Run the full `pytest` suite and `mypy`.
- In a test project with no `AXES_LOCKOUT_PARAMETERS` set: after 3 failed logins, user A is locked out on that IP, and user B can still log in from the same IP.
- `manage.py check` should raise no W006 warning.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Weaker protection against password spraying | One IP trying many usernames is no longer stopped; each username gets its own failure limit | State it clearly in CHANGES; document `["ip_address", ["username","ip_address"]]` as a stricter option |
| 2 | Distributed brute force on one account | Attempts on one username from many IPs never reach the limit | Document the `["username"]` and tiers options; recommend them for admin accounts |
| 3 | Silent behaviour change on upgrade | Projects relying on the implicit default change without any config edit | Major version bump, breaking-changes entry, explicit upgrade line in `2_installation.rst` |
| 4 | Lockouts reset during upgrade | Cache keys move from an IP hash to a username+IP hash, and database rows that locked by IP no longer add up per username | Release note: lockouts active at upgrade are effectively reset |
| 5 | Legacy flags mapped differently | `AXES_USE_USER_AGENT` modifies `[0]`, so a nested default would quietly become `[["username","ip_address","user_agent"]]` | Keep the legacy branch separate from the new default; unit-test each flag combination |
| 6 | Hidden test dependencies | Many tests assume IP-only without an override | Pin them explicitly; run the suite under both the database and cache handlers |
| 7 | Can't test the default directly | `conf.py` resolves settings once at import | Test through the extracted helper function |
| 8 | Requests with no username | Database filter matches `username IS NULL`; cache key drops empty values, so it equals the IP-only key | Add tests for an empty username under the new default |
| 9 | Admin and reset workflow | Support teams using `axes_reset_ip` may now also need `axes_reset_username` | Document this in CHANGES and the usage docs |

Riskiest: #1. The new default gives up IP-wide throttling, so one IP can now try a password across many usernames, each with its own full failure limit.
