## Context
This is the Laravel 5.5 RealWorld API, using JWT auth. Authorization is done inside FormRequests: for example, `DeleteComment::authorize()` only checks `user_id == auth()->id()`. The app has no roles at all, and `AuthServiceProvider` contains only the placeholder policy mapping. The comments table is plain, and `CommentController@index` returns every comment on the article.

## Assumptions
1. **Who is a moderator:** a new `users.is_moderator` boolean. It stays out of `$fillable` so users can't make themselves moderators through `PUT /api/user`. It is granted only through the seeder or tinker.
2. **"Hide" can be undone:** the comment stays in the database but drops out of public listings. Its author and moderators can still see it, which the author needs in order to appeal.
3. **The appeal window** is 7×24h from `hidden_at`, checked on the server in UTC and set in `config/moderation.php`. Each hide allows one appeal.
4. **Appeal outcomes:** a moderator either upholds the hide (final) or overturns it (the comment becomes visible again). Any moderator can decide.
5. **Hiding the same comment again** after an overturn creates a new record and starts a new 7-day window.
6. **Authors can still delete** their own hidden comments. The moderation record keeps a copy of the comment body for audit.

## Approach
- **Migrations:**
  - `users.is_moderator`
  - `comments.hidden_at`, nullable and indexed
  - a `comment_moderations` table: comment_id (null on delete), moderator_id, reason, body_snapshot, hidden_at, appeal_body, appealed_at, status `hidden|appealed|upheld|overturned`, resolved_by, resolved_at
- **Models:**
  - `User::isModerator()`
  - `Comment::moderations()`, `currentModeration()` and a `visibleTo($user)` scope
  - new `CommentModeration` with `appealDeadline()` and `canBeAppealed()`
- **Authorization:** a new `CommentPolicy` (hide, appeal, resolveAppeal), registered in `AuthServiceProvider`. New FormRequests `HideComment`, `AppealComment` and `ResolveAppeal` follow the existing `DeleteComment` pattern.
- **Controller:** a new `CommentModerationController` extending `ApiController`. Every status change runs in `DB::transaction` with `lockForUpdate()`.
- **Routes:**
  - `POST articles/{article}/comments/{comment}/hide`
  - `POST articles/{article}/comments/{comment}/appeal`
  - `POST articles/{article}/comments/{comment}/appeal/resolve`
  - `GET moderation/appeals` (the moderators' queue, paginated with the existing `Paginate`)
- **Listing:** `CommentController@index` uses `visibleTo(auth()->user())` and eager-loads `currentModeration`.
- **Response format:** `CommentTransformer` adds `hidden`. Only the author and moderators get a `moderation` block (status, reason, hiddenAt, appealDeadline). Existing clients get the same response as before.
- **Fix an existing gap:** today `{comment}` isn't checked against `{article}`, so any comment id works under any article slug. The new routes and `destroy` should return 404 when they don't match.
- **Seed data:** a `moderator` state in the factory and one moderator user in `DummyDataSeeder`.

## Verification
- **New tests:** `tests/Feature/Api/CommentModerationTest.php`, following the style of `CommentTest`. They cover:
  - a non-moderator trying to hide gets 403
  - who can see a hidden comment
  - the 7-day boundary, checked with `Carbon::setTestNow` (6 days passes, 7 days + 1s is rejected)
  - a second appeal is rejected, and so is an appeal by someone other than the author
  - overturn makes the comment visible again; upheld stays hidden
  - a comment under the wrong article returns 404
  - `is_moderator` sent to `PUT /api/user` is ignored
- **Full suite:** run `vendor/bin/phpunit` against `realworld_test`. The existing `CommentTest` must still pass.
- **Manual check:** `php artisan migrate`, make a user a moderator in tinker, then call the endpoints with curl.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments leak publicly | `index` returns all comments, and the comment relation is reused elsewhere | `visibleTo` scope plus tests for anonymous and other users |
| 2 | Users make themselves moderators | Profile update mass-assigns user fields | Keep `is_moderator` out of `$fillable`; add a test |
| 3 | Comment id doesn't match the article | Route binding never checks article ownership | Check it and return 404 |
| 4 | Off-by-one or timezone error on the 7-day deadline | Carbon/app timezone; "within 7 days" is ambiguous | Compute on the server in UTC; boundary tests with `setTestNow` |
| 5 | Double appeal or decision when requests race | Status changes are read-then-write | Transaction plus `lockForUpdate` |
| 6 | Audit trail lost when a comment is deleted | Existing foreign keys cascade on delete | Null on delete plus `body_snapshot` |
| 7 | N+1 queries in the comment list | Moderation data is loaded per comment | Eager-load `currentModeration` |
| 8 | Breaking RealWorld clients | The response format is shared across frontends | Only add fields; privileged block only for author/moderator |
| 9 | No moderators exist after deploy | There's no admin UI | Seeder/tinker runbook; document how to promote a user |
| 10 | Migrations on a large comments table | Adding an indexed column can lock the table | Run in a low-traffic window; the column is nullable, so no backfill |

Riskiest: #1 — hidden abusive comments still showing in the public comment list, because every existing path that reads comments has to go through the new visibility filter.
