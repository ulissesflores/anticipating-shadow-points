Changing the title already works: only the author can do it, and `PUT /api/articles/:slug` regenerates the slug (`articles/routers.go:152-160`). What's missing is the old slug. It gets overwritten, so links that were already shared return 404, and `makeUniqueSlug` (`articles/models.go:299`) lets a later article take that slug. The fix is to keep old slugs as permanent aliases. Nothing has been edited; the plan is saved at `claude-home/plans/let-authors-change-an-zippy-knuth.md`.

## Plan
1. **New alias table** (`articles/models.go`): add `ArticleSlugAliasModel{ID, Slug (unique index), ArticleID (index), CreatedAt}`, with no soft delete. Register it in `hello.go:Migrate` and in the test migration in `articles/unit_test.go` (around line 340).
2. **One lookup helper**: `FindArticleBySlug(slug)` looks up the current slug first. If that misses, it looks up the alias and loads the article by ID. Soft-deleted articles still return 404.
3. **Use the helper in every `:slug` handler**: retrieve, update, delete, favorite/unfavorite, and comment create/list/delete. Two places would break silently if you only swap the lookup:
   - `ArticleDelete` deletes with `WHERE slug = <URL param>`. It must delete by `articleModel.ID`.
   - `ArticleUpdate` sets `finalSlug := slug` from the URL param. It must start from `articleModel.Slug` and re-fetch the article by ID.
4. **Keep old slugs reserved**: change `makeUniqueSlug(base, ownerID)` so a slug counts as taken if another article uses it now or used it before. The same article can take back one of its own old slugs.
5. **Rename in one transaction**: in a single `db.Transaction`, save the old slug as an alias, delete the alias if the article is taking back an old slug, and update the article. Keep the existing retry on `gorm.ErrDuplicatedKey`.
6. **Response for old slugs**: return 200 with the article. The body already has the current `slug`, and a `Link: rel="canonical"` header is added. I chose not to use a 301: the API is called with fetch, and a cross-origin redirect drops the `Authorization` header, which would make `favorited` and `following` wrong.
7. **Tests** to add:
   - Rename A→B→C: `a` and `b` both return C.
   - Rename back to `a`: `a` becomes current again.
   - A new article whose title matches an old slug gets `-2`.
   - Writes through an old slug work, and a non-author still gets 403.
   - Delete through an old slug removes the right article.

   Then run `go test ./...`, `golangci-lint run` and `scripts/run-spec-tests.sh`.

## Assumptions
- "Shared links" means frontend URLs that call `GET /api/articles/:slug`. The frontend should switch to the current slug from the response.
- Changing the title still regenerates the slug, as the RealWorld spec suite expects. There is no separate "edit slug" field.
- Aliases are kept forever, including after the article is deleted, so a slug is never reused.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Another article takes an old slug | `makeUniqueSlug` only checks `articles.slug` | Also check the alias table in `makeUniqueSlug` |
| 2 | Delete through an old slug deletes nothing | `DeleteArticleModel(&ArticleModel{Slug: slug})` uses the URL param | Delete by ID, and test it |
| 3 | Update re-fetch returns 422 | `finalSlug := slug` is the URL param, not the current slug | Start from `articleModel.Slug` and re-fetch by ID |
| 4 | Article and alias get out of sync | Alias insert and slug update are two writes | Put both in one transaction |
| 5 | Two tables can't share one unique constraint | Each table has its own unique index | SQLite has one writer at a time; check inside the transaction; retry on duplicate key |
| 6 | Renaming back to an old slug fails or gets `-2` | The article's own alias blocks it | Exclude the owner in `makeUniqueSlug` and delete that alias in the transaction |
| 7 | Redirects lose auth | A cross-origin 301 drops `Authorization` | Return 200 with a canonical `Link` header |
| 8 | Spec suite expects the old slug to 404 | hurl/bruno tests from #57 | Run `run-spec-tests.sh` early |
| 9 | Test setup is missing the new table | Tests list their migrations by hand | Add the model to the test migration |
| 10 | Alias table grows without limit | Every rename adds a row | Index it; growth is small and acceptable |

Riskiest: #1 — if `makeUniqueSlug` doesn't check the alias table, a new article can take an old slug, and shared links quietly show the wrong article instead of a 404.
