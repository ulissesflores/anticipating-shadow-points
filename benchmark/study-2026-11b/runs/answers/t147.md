## Plan: moderators hide abusive comments, authors can appeal within 7 days

This is a Laravel 5.5 API that logs users in with JWT tokens. It has no roles today, so the first step is adding a moderator flag. I haven't edited any repo files; the plan is saved at `claude-home/plans/let-moderators-hide-abusive-cosmic-pike.md`.

**Assumptions** (non-interactive run, so I'm stating them instead of asking)
- **Who is a moderator:** a new `users.is_moderator` boolean, set through a seeder or tinker. It is not mass-assignable, and it is read from the database on each request rather than stored in the JWT. That way, removing someone's moderator status takes effect immediately.
- **Hiding:**
  - Hiding is not deleting, and it needs a reason.
  - A hidden comment is left out of the public comment list.
  - The author and moderators still see it, with `hidden` and `moderation` details attached.
- **Appeals:** the author gets one appeal per hide, until `hidden_at + 7 days` (worked out on the server, in UTC).
- **Resolving an appeal:** a moderator either **upholds** it (the comment stays hidden and the case closes) or **overturns** it (the comment is shown again). Moderators can also unhide a comment directly.
- **Scope:** API only, no frontend work.

**Data model** (three new migrations)
1. `users.is_moderator`, default false.
2. `comments.hidden_at`, nullable and indexed, so the public list can filter quickly.
3. A `comment_moderations` table with one row per hide: who hid it, the reason, when, the appeal text and time, the appeal status (none, pending, upheld, overturned), and who resolved it and when. Because each hide gets its own row, a comment that is hidden again later can be appealed again.

**Code changes**
- **`app/Comment.php`:**
  - a `moderations()` relation;
  - a `visibleTo($user)` filter (not hidden, or your own comment, or you're a moderator);
  - `isHidden()` and `appealDeadline()` helpers.
- **New model:** `app/CommentModeration.php`.
- **`app/User.php`:** add `isModerator()`.
- **`app/Policies/CommentPolicy.php`:**
  - rules for `hide`, `unhide`, `appeal` and `resolveAppeal`;
  - the appeal rule allows only the author, only on a hidden comment, only with no earlier appeal, and only while `now() <= hidden_at + 7 days`;
  - register the policy in `AuthServiceProvider`, replacing the placeholder entry.
- **New request classes**, built like the existing `DeleteComment`:
  - `HideComment` (reason required);
  - `AppealComment` (appeal text required);
  - `ResolveAppeal` (decision must be uphold or overturn).

  Each one also checks that the comment belongs to the article in the URL, because the current routes don't check this.
- **`CommentController`:**
  - `index` uses the `visibleTo` filter;
  - new `hide`, `unhide` and `appeal` actions;
  - each runs in a transaction that locks the comment row.
- **New `Api/ModerationController`:**
  - `GET /api/moderation/appeals?status=pending` (the moderator queue);
  - `POST /api/moderation/appeals/{id}/resolve`.
- **New routes:**
  - `POST /api/articles/{article}/comments/{comment}/hide`
  - `DELETE` on the same `.../hide` path, to unhide
  - `POST .../appeal`
- **`CommentTransformer`:**
  - adds `hidden`;
  - adds a `moderation` block (reason, hidden at, appeal deadline, appeal status) only for the author or a moderator;
  - never shows the author which moderator hid the comment.
- **Other places comments appear:** search for them (for example `User::comments` and the seeders) and apply the same filter wherever they are public.
- **Factories:** add a moderator user and a `CommentModeration` factory.

**Verification**
- **New tests** in `tests/Feature/Api/CommentModerationTest.php`, freezing the clock with `Carbon::setTestNow`:
  - a non-moderator trying to hide gets 403;
  - a hidden comment disappears for other users but stays visible to the author and to moderators;
  - an appeal on day 6 succeeds, and one at 7 days plus 1 second gets 403;
  - a second appeal and an appeal by someone other than the author both get 403;
  - overturning shows the comment again, and upholding keeps it hidden with no further appeal;
  - a comment ID from a different article in the URL is rejected;
  - sending `is_moderator` to `PUT /user` is ignored.
- **Existing tests:** run `vendor/bin/phpunit`. The current `CommentTest` must still pass, since nothing changes for comments that aren't hidden.
- **Manual check:** a curl walkthrough with two tokens, one moderator and one author.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | A user makes themselves moderator | `PUT /user` saves the request's fields; adding the new flag to the allowed fields would let anyone set it | Leave it out of `$fillable`; test that it's ignored |
| 2 | Hidden comment still visible somewhere | `CommentController::index` and `User::comments` both read comments without any filter | Apply the `visibleTo` filter everywhere and search for other comment queries |
| 3 | Acting on a comment through the wrong article | Routes don't check the comment belongs to the article (`destroy` ignores `$article`) | Check `article_id` in each new request class |
| 4 | Off-by-one or time-zone errors on the 7-day limit | Deadline compared against the clock; easy to get wrong | Compute on the server in UTC with `<=`; boundary tests with a frozen clock |
| 5 | Duplicate appeals or conflicting hides from simultaneous requests | Two requests can both pass the checks before either saves | Transaction with a row lock; check status inside it |
| 6 | Revoked moderator keeps their powers | Putting the role in the JWT would keep it valid until the token expires | Read `is_moderator` from the database on every request |
| 7 | Same moderator hides the comment and judges the appeal | No separation of duties, which undermines the appeal | Record who resolved it; optionally block self-review |
| 8 | Clients break on the new fields | Clients built to the RealWorld spec read the comment format | Add fields only (nothing removed or renamed); unhidden comments look the same |
| 9 | Deleting a comment erases the moderation history | Database rule deletes moderation rows along with the comment | Accept this, or keep a short audit record |
| 10 | Mistakes when changing the database | Three migrations on live tables | Columns are nullable or have defaults; test rolling back |

Riskiest: #2, a hidden comment still being visible through a comment query that doesn't apply the filter, which defeats the point of hiding it.
