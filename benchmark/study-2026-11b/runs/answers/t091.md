## Assumptions
- The change is to the defaults only: `same_site="strict"` and `https_only=True`. The `same_site` and `https_only` parameters stay, so callers can override them.
- This is a deliberate breaking change to a library's defaults, so it needs a changelog or release note.
- `tests/middleware/test_session.py` uses the default `TestClient` at `http://testserver`. Its cookie-roundtrip tests assume the default cookie is not Secure.

## What could go wrong
1. **Plain-HTTP dev and test setups lose their sessions.** Browsers and `httpx` drop Secure cookies over `http://`. Sessions silently stop persisting, with no error.
2. **The existing tests will break.** Many tests use `base_url="http://testserver"` and the default flags.
3. **Strict SameSite breaks cross-site navigation.** After an OAuth or SSO redirect back, or a link from an email or another site, the first request arrives without the cookie. Users look logged out, and flows that store state in the session (OAuth `state`, CSRF) fail.
4. **Apps behind a TLS-terminating proxy.** Starlette doesn't read the scheme to decide on `Secure`. The flag is a fixed string, so the cookie is still sent to the browser. Proxy-to-app HTTP hops don't matter because the browser is what enforces the flag.
5. **Cookie clearing.** The delete cookie reuses the same flags. If an old cookie was set without Secure, a Secure `Set-Cookie` can't overwrite it in some browsers. Logout may then fail to clear it.
6. **The docs and public API now say the opposite.** `docs/middleware.md` states `'lax'` and `False`, and the "Set this to True in production" advice becomes wrong. The type hints and `docs/config.md` are affected too.
7. **Subtle semantics.** `samesite=none` requires Secure in browsers. A user who sets `same_site="none"` now gets Secure automatically, which is correct. A user who sets `https_only=False` explicitly still gets a non-Secure cookie.
8. **Downstream frameworks and users.** Anything that embeds `SessionMiddleware` (FastAPI apps, test suites, local docker setups) changes behaviour on upgrade without code changes.
9. **Mobile apps and webviews.** Some embedded browsers handle Strict or Secure cookies inconsistently.
10. **Safari and localhost.** Safari doesn't treat `http://localhost` as secure, unlike Chrome and Firefox. Local development differs by browser.

## Suggested approach (not executed)
- Change the two defaults in `__init__`.
- Update `tests/middleware/test_session.py` to use `https://testserver` or to pass explicit opt-outs, and add tests for the new default flags and for the opt-out.
- Update `docs/middleware.md` and `docs/config.md`, and add a release note.
- Verify with `pytest tests/middleware` and the project's lint and type checks.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Sessions vanish on plain HTTP | Default `TestClient` and dev servers use `http://` | Document `https_only=False` for dev; use `https://testserver` in tests |
| 2 | Cross-site redirects drop the cookie | Strict blocks it on OAuth/SSO return | Document `same_site="lax"` for login flows; release note |
| 3 | Existing tests fail | Tests assume non-Secure default cookies | Update base URLs and add explicit-flag tests |
| 4 | Silent breaking change for downstream users | A library default flips on upgrade with no code change | Changelog, major or minor bump, clear upgrade note |
| 5 | Docs become wrong | `docs/middleware.md` states the old defaults | Update docs and examples together |
| 6 | Clearing old non-Secure cookies fails | The delete cookie reuses the new flags | Test logout with a legacy cookie; consider a flag-agnostic delete |
| 7 | Proxy and TLS-termination confusion | Secure is a fixed flag, not scheme-aware | Document it; keep `https_only` overridable |
| 8 | Safari and localhost inconsistencies | Safari doesn't treat `http://localhost` as secure | Note in the docs; recommend local HTTPS |

Riskiest: #1, because silent loss of sessions on plain HTTP breaks every dev and test setup with no error, and the existing tests assume that default.
