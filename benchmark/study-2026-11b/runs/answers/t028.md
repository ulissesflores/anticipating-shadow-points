Changing the title already changes the slug: `ArticleUpdate` builds a new one from it (`articles/routers.go:152-182`). The real gap is that the old slug is overwritten, so every link already shared returns 404. The plan keeps a list of old slugs (aliases) that resolve to the renamed article. I didn't edit or run anything. The plan is written to `claude-home/plans/let-authors-change-an-ethereal-key.md`.

**Assumptions**
- **No redirects:** an old slug works directly and returns 200, not a 301. Redirects behave badly for PUT/POST/DELETE and could break the RealWorld spec tests. The response's `article.slug` always holds the current slug, so a client can update its URL.
- **Old slugs stay reserved:** no other article can take one. This matches how soft-deleted slugs are already reserved via `Unscoped()` in `makeUniqueSlug`.
- **Renaming back is allowed:** an author can go back to one of the article's own earlier slugs.
- **Delete retires aliases:** after an article is deleted, its old slugs return 404.
- **No backfill:** renames done before this ships left no record, so those links stay broken.

**Plan**
1. **New model** in `articles/models.go`: `ArticleSlugAliasModel{gorm.Model; Slug (uniqueIndex); ArticleID (index)}`. Each alias points to the article ID rather than the next slug, so after renames A→B→C, a link to A is still one lookup.
2. **Migrations:** add it to `AutoMigrate` in `hello.go` and in both test DB setups in `articles/unit_test.go` (around lines 339 and 1597).
3. **Lookup:** a new `FindArticleBySlug(slug)` checks the current slug first, then the alias table, then loads the article by ID. Normal requests still cost one query.
4. **Slug uniqueness:** change to `makeUniqueSlug(base, selfID)`. A slug counts as taken if any article uses it, or if it is an alias of a *different* article (soft-deleted rows included). Create passes `0`.
5. **Update:** when the slug changes, do this in one transaction:
   - update the article;
   - remove the alias matching the new slug, if any (the rename-back case);
   - add an alias for the old slug.
   Keep the existing retry on duplicate-key errors, and re-fetch the article by ID instead of by slug.
6. **All eight `:slug` handlers** switch to `FindArticleBySlug` and use `articleModel.ID` from then on. One existing bug must be fixed here: `ArticleDelete` deletes by the slug in the URL (`DeleteArticleModel(&ArticleModel{Slug: slug})`). Called with an old slug, it would delete nothing and still return 204. Delete by ID, and soft-delete the aliases in the same transaction. Also check in `CommentDelete` that the comment belongs to that article.
7. **Tests:**
   - GET with an old slug returns 200 and the new slug.
   - After A→B→C, both A and B resolve.
   - Renaming back to A works.
   - A new article can't take someone's old slug.
   - Favorite, comment and delete through an old slug act on the right article.
   - A description-only edit adds no alias.
   - Run `go test ./...` and the hurl/bruno spec suite.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Delete through an old slug silently does nothing | `ArticleDelete` deletes by the URL slug, not the article's ID | Delete by `articleModel.ID`; add a test |
| 2 | A new article takes over a shared old link | `makeUniqueSlug` only checks `article_models` | Also check aliases (soft-deleted included) |
| 3 | Race between an alias and a slug | They are in two tables, so neither unique index sees the other | Use transactions plus the existing duplicate-key retry; SQLite runs one write at a time |
| 4 | Renaming back to an old slug fails | That slug already exists as the article's own alias | Ignore the article's own aliases in the check; delete that alias in the update transaction |
| 5 | Handlers still look up by slug | 8 handlers call `FindOneArticle(&ArticleModel{Slug: slug})` | Replace them all; grep for leftovers; test each route with an old slug |
| 6 | Alias table missing at runtime | Migrations are listed separately in `hello.go` and in 2 test setups | Add the model to all three places |
| 7 | Slug hoarding | Each rename permanently reserves one more slug | Optionally limit aliases per article or rate-limit renames |
| 8 | Spec test breakage | The hurl/bruno suites check the update response | Keep 200 plus the new slug in the body; run both suites |
| 9 | Links from earlier renames stay broken | Those renames left no record | Document it; no backfill is possible |

Riskiest: #1, because a delete through an old link would report success (204) while deleting nothing.
