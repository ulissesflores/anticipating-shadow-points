**Finding:** the update handler already regenerates the slug when the title changes (`articles/routers.go:152-160`). The old slug then stops resolving. Every `/:slug` route looks the article up with `FindOneArticle(&ArticleModel{Slug: slug})`, so shared links return 404. The missing piece is keeping old slugs working, not title editing. I made no edits, as requested.

## Assumptions
- Old slugs should keep working indefinitely, for reads and for writes (favorite, comment).
- The API returns the article's canonical (new) slug in the JSON body. I'm not using HTTP redirects. This is a JSON API, and RealWorld clients build URLs from `article.slug`.
- Soft-deleted articles keep returning 404 for both their current and old slugs.
- Authors can rename only their own articles. That check already exists.
- No data migration is needed beyond `AutoMigrate`.

## Plan
1. **New model** `ArticleSlugAlias` in `articles/models.go` with `ID`, `ArticleID` (indexed), `Slug` (`uniqueIndex`) and `CreatedAt`. Register it in `AutoMigrate` in `hello.go` and in the test setup in `articles/unit_test.go:339`.
2. **Record the old slug on rename.** In `ArticleUpdate`, write the alias row in the same transaction as the slug update. This means changing `ArticleModel.Update` or wrapping it in a transaction. If the new slug equals one of this article's own aliases, delete that alias row.
3. **Resolve aliases on lookup.** Add `FindOneArticleBySlug(slug)` in `models.go`. It tries the live slug first, then falls back to the alias table and loads the article by `ArticleID`. Use it in all seven slug handlers in `routers.go` (retrieve, update, delete, favorite, unfavorite, comment create, comment list). Add the same lookup to the comment-delete path, which is also under `/:slug`.
4. **Make slug uniqueness alias-aware.** `makeUniqueSlug` (`models.go:299`) must treat alias slugs as taken. Otherwise a new article titled like an old one would take over the old link. Also let it ignore the article being renamed, so renaming "foo-2" to "foo" doesn't churn the slug or create junk aliases.
5. **Handle races.** Keep the existing retry on `gorm.ErrDuplicatedKey`. Make sure the retry also covers the alias unique index.
6. **Avoid alias chains.** Aliases point at the article ID, not at the previous slug. Several renames therefore resolve in a single lookup.
7. **Tests** in `articles/unit_test.go`:
   - Rename, then GET the old slug and get the article.
   - Rename twice, and both old slugs resolve.
   - Create a new article with an old title and get a different slug.
   - Rename back to an old slug.
   - Delete the article, then both old and new slugs return 404.
   - A non-author PUT through an old slug returns 403.
   - Re-run the hurl and bruno suites from #57.
8. **Docs.** Note the alias behavior in `readme.md`.

**Verify:** `go build ./...`, `go test ./...`, `golangci-lint run`. Then run the server and PUT a new title, GET the old slug and compare the two responses.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Old slug gets reused by another article | `makeUniqueSlug` only checks `articles` today | Check aliases in it; unique index on alias slug |
| 2 | Alias row and slug update diverge | `Update` and `ReplaceTags` aren't transactional | Single transaction for update plus alias insert |
| 3 | Missed handler still 404s on old slugs | Eight handlers each do their own lookup | One shared lookup helper; test every route |
| 4 | Client sees a different slug than requested | Old-slug requests return the new canonical slug | Document it; always return the canonical slug |
| 5 | Slug race on concurrent renames | Check-then-write is already racy | Keep the retry loop; cover the alias index |
| 6 | Rename-back or same-base rename breaks | Own alias or own slug counts as a collision | Exclude self; delete own alias on reuse |
| 7 | Unbounded alias growth | Every rename adds a row | Accept it; optionally cap aliases per article |
| 8 | Deleted article leaks through an alias | The alias lookup could skip the soft-delete filter | Load via the scoped query; add a test |
| 9 | Schema change on existing DBs | A new table needs migration in `hello.go` and tests | `AutoMigrate` in both; test on the existing SQLite file |
| 10 | Spec suites regress | hurl and bruno assert the current slug behavior | Re-run both suites before merge |

Riskiest: #1. If an old slug is reused, a shared link silently opens someone else's article.
