## Assumptions (no one to ask in this run)
1. **There are no roles today.** `users` has no role column and `AuthServiceProvider` has no gates. I'll add an `is_moderator` boolean, default `false`, set only by hand in the database or a seeder. No API can change it.
2. **"Hide" means soft-hide, not delete.** The row stays, and only the author and moderators can see it.
3. **The 7 days start at `hidden_at`**, measured in server time (UTC), and the end is inclusive. Each hide allows one appeal.
4. **A moderator decides the appeal.** The outcome is either "overturned", which un-hides the comment, or "upheld". The deadline applies to filing an appeal, not to deciding it.
5. Authors can still delete their own hidden comment. A moderator can't appeal their own hide, and the same moderator who hid it shouldn't decide its appeal.
6. Notifications (email etc.) and a frontend UI are out of scope. The work is API only, in the existing RealWorld JSON style.

## Ways this could go wrong (before planning)
- **Hidden comments leak.** `CommentController@index` (`app/Http/Controllers/Api/CommentController.php:35`) returns `$article->comments()->get()` with no filter. Any other read path that skips the new filter would show hidden comments.
- **Anyone can act on any article's comments.** `Comment` is route-bound by id alone, and `$article` in `destroy` is an untyped string. So `/articles/A/comments/{id-from-B}` resolves today. Copying that pattern lets a request against one article act on another article's comment.
- **Privilege escalation.** If `is_moderator` ends up in `User::$fillable`, `PUT /api/user` lets anyone make themselves a moderator.
- **The wrong person appeals.** Only `comment.user_id` may appeal, not any logged-in user.
- **The window is off by a day or a timezone.** `addDays(7)` is compared against an unfrozen `now()`. Appeals could also be filed after the comment was un-hidden, or twice.
- **Old appeals cause trouble on re-hide.** If a comment is hidden again after an overturn, the old appeal must not block a new one or be counted as covering it.
- **Clients break.** RealWorld clients expect the existing `comment` shape, so new fields must be additions only.
- **The audit trail is lost.** If the hiding moderator's account is deleted, `hidden_by` breaks unless it's nullable with `onDelete('set null')`.
- **Tests miss it.** If tests don't control time and only check `index`, gaps slip through.

## Plan

**Schema** (new migrations in `database/migrations/`)
- `users.is_moderator` boolean, default false. Don't add it to `$fillable` in `app/User.php`.
- `comments`: `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users, set null on delete) and `hidden_reason` (nullable string). Don't add these to `Comment::$fillable` either.
- `comment_appeals`: id, comment_id (FK, cascade), user_id, `hidden_at` (a copy of the hide being appealed), reason (text), status (`pending|upheld|overturned`), resolved_by (nullable), resolved_at (nullable), timestamps. Add `unique(comment_id, hidden_at)` so there's one appeal per hide.

**Model** (`app/Comment.php`)
- `isHidden()`, `appeals()`, `currentAppeal()`.
- `canBeAppealedBy($user)`: the comment is hidden, `$user->id == user_id`, `now() <= hidden_at + 7 days`, and no appeal exists for this `hidden_at`.
- Scope `visibleTo(?User $user)`: show `whereNull('hidden_at')`, plus the viewer's own comments, plus everything when the viewer is a moderator.
- On `app/User.php`, add `isModerator()`.

**Authorization**
- Gate `moderate-comments` in `app/Providers/AuthServiceProvider.php`.
- New FormRequests that follow the `app/Http/Requests/Api/DeleteComment.php` pattern:
  - `HideComment`: moderator only; `comment.reason` required, max 500.
  - `AppealComment`: checks `canBeAppealedBy`; `appeal.reason` required.
  - `ResolveAppeal`: moderator, not the one who hid it; `decision` must be `in:upheld,overturned`.
- In every new action, return 404 unless `$comment->article_id === $article->id`. Bind `Article $article` so it resolves by slug.

**Routes / controller** (`routes/api.php`, a new `Api/CommentModerationController`, behind `auth.api`)
- `POST articles/{article}/comments/{comment}/hide` and `DELETE …/hide`. Un-hiding clears the `hidden_*` fields and marks any pending appeal as resolved.
- `POST articles/{article}/comments/{comment}/appeal` returns 403 when the caller isn't the author, and 422 for "window closed" or "already appealed".
- `GET moderation/appeals?status=pending` and `POST moderation/appeals/{appeal}/resolve`. "Overturned" un-hides the comment in a DB transaction.
- `CommentController@index` changes to `$article->comments()->visibleTo(auth()->user())->get()`.

**Transformer** (`app/RealWorld/Transformers/CommentTransformer.php`)
- Add only. For the author and moderators, include `hidden: true`, `hiddenAt`, `appealDeadline` and `appeal: {status}`. Leave all existing keys unchanged.
- New `CommentAppealTransformer` for the moderator queue.

**Verification**
- Add `tests/Feature/Api/CommentModerationTest.php`, reusing `tests/TestCase.php` users and the `CommentTest` setup.
- Cases:
  - Hidden comments are absent for guests and other users, and present for the author and moderators.
  - A non-moderator trying to hide gets 403.
  - A comment from another article in the URL gets 404.
  - With `Carbon::setTestNow`, an appeal at day 7 is accepted and one at day 7 + 1s is rejected.
  - An appeal from someone other than the author gets 403. A duplicate appeal gets 422.
  - Overturning un-hides the comment. A re-hide allows a new appeal.
  - `PUT /api/user` with `is_moderator: true` doesn't change the flag.
- Run with `vendor/bin/phpunit`. The existing `CommentTest` must stay green.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments still visible | `index` returns every comment unfiltered | `visibleTo` scope + tests per viewer role |
| 2 | Acting on another article's comment | Comment is bound by id only; `$article` is an untyped string in `destroy` | Bind `Article`, 404 when `article_id` differs |
| 3 | Users make themselves moderators | `UpdateUser` fills the user model from the request | Keep `is_moderator` out of `$fillable` + test |
| 4 | Non-authors can appeal | No policy layer exists; FormRequest checks are hand-written | `AppealComment::authorize` checks `user_id` |
| 5 | 7-day window off by one or by timezone | Carbon `now()` and inclusive boundaries | Single `canBeAppealedBy`, `setTestNow` boundary tests |
| 6 | Duplicate appeals or old appeals on re-hide | Same comment can be hidden more than once | `unique(comment_id, hidden_at)` |
| 7 | RealWorld clients break | Strict spec shape for `comment` | Add fields only, only for author and moderators |
| 8 | Overturn leaves state half-updated | Appeal and comment are written separately | DB transaction |
| 9 | Moderator decides the appeal of their own hide | Small moderator pool | Block `resolved_by == hidden_by` |
| 10 | Moderation history lost | Deleting a user cascades | `hidden_by` nullable with set null |

Riskiest: #1. Hidden comments leaking through the unfiltered `index` query (or any read path added later) would make the whole feature useless while looking like it works.
