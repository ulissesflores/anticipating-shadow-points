## Plan

The change itself is two default values in `SessionMiddleware.__init__` (`starlette/middleware/sessions.py:24-25`). Most of the work is updating tests and docs.

1. **Code:** change `same_site` to default to `"strict"` and `https_only` to default to `True`. The code that builds the cookie flags already adds `; secure` to both the "set" and "clear" `Set-Cookie` headers, so nothing else in that file needs to change.
2. **Docs (`docs/middleware.md`, around lines 233–252):**
   - Update both stated defaults.
   - Explain when to opt out:
     - `same_site="lax"` for apps that need the session cookie on cross-site navigations, such as OAuth/OIDC callbacks and links from emails.
     - `https_only=False` for local development over plain HTTP, and for `TestClient` with its default `http://testserver`.
   - Reword the `partitioned` bullet, which says to set `https_only=True`.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | OAuth/OIDC logins break | Libraries like Authlib keep the login `state` value in this session. The identity provider's redirect back to the app is cross-site, so with `strict` the browser doesn't send the cookie and the state check fails | Document opting out with `same_site="lax"`; flag it in the release note |
| 2 | Users' own test suites quietly lose sessions | `TestClient` defaults to `http://testserver`, and the test client drops `Secure` cookies over plain HTTP. The session comes back empty without any error | Release note plus a doc tip: use an `https://` base URL or `https_only=False` |
| 3 | Local development over plain HTTP breaks | Safari, and access via LAN IPs or Docker hostnames, may reject `Secure` cookies sent over HTTP | Document `https_only=False` for development |
| 4 | Sessions seem lost after following an external link | With `strict`, the first visit from an email or another site arrives without the cookie, so the user looks logged out | Recommend `lax` for apps where users arrive via such links |
| 5 | Silent change for existing apps | The defaults change without any warning or error | Put it under "Changed" in release notes; consider a minor version bump |
| 6 | Tests in this repo only partly updated | About 10 tests rely on the defaults over HTTP | Run the full suite; add a test for the default flags |
| 7 | Duplicate PR | AI_POLICY.md bans contributors who open duplicate PRs | Search PRs, issues and discussions again before opening |
| 8 | Docs left out of date | The `partitioned` bullet and the example both mention `https_only=True` | Update every mention in the same PR |

Riskiest: #1. OAuth/OIDC logins that keep their state in the session will stop working once the cookie is `SameSite=Strict`.
