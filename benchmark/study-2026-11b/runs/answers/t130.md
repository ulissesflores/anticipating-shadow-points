**Current state:** `ArticleUpdate` (`articles/routers.go:152-161`) already regenerates the slug when the title changes. Nothing records the old slug, so every previously shared link 404s. `FindOneArticle` only matches the current `slug` column, and `makeUniqueSlug` only checks live and soft-deleted article slugs.

**Assumptions (non-interactive):**
- The API shape stays RealWorld-compatible: `PUT /api/articles/:slug` returns the new slug in the body.
- Old links should keep working for reads. Writes to an old slug should also resolve.
- Old slugs are permanent, not time-limited.
- The "link" is the API path `/api/articles/:slug`. The frontend route is `/article/:slug`, which a SPA can only fix by reading the returned slug.
- SQLite via `AutoMigrate` is the only database, with no migration framework.

## What could go wrong (before planning)

1. **Old slug reclaimed.** Author A renames away from `foo`, then someone creates "Foo". `makeUniqueSlug` doesn't see `foo`, so it hands it out. The shared link now shows a different article, which is worse than a 404.
2. **Alias collisions.** The alias table needs its own unique index, and every uniqueness check must cover both tables. Otherwise a new title can claim an old alias, or the reverse.
3. **Rename-back and chains.** Renaming A→B→A, or A→B→C, must not create duplicate or cyclic alias rows. Every old slug must resolve to the current article, not to the previous hop.
4. **Race conditions.** Two concurrent renames or creates can pass `makeUniqueSlug` and collide. The existing retry loop covers only `articles.slug`, so alias inserts need the same handling. The slug swap and the alias insert must also be one transaction. Otherwise a failure leaves a renamed article with a lost old link.
5. **Authorization leak.** Alias lookup must go through the same checks as the current slug. Edit and delete through an old slug need the same author check. Comments, favorites and feed endpoints would also need it.
6. **Soft deletes.** Deleting an article must either keep its aliases reserved or remove them. Today soft-deleted slugs still occupy the unique index, and aliases should behave the same way.
7. **Response semantics.** A 301 redirect breaks API clients and the hurl/bruno spec suite. Serving the article directly with the canonical slug in the body is safer, but clients may then keep using the stale slug.
8. **Canonical-slug drift.** After `PUT`, the handler re-reads by `finalSlug` (`routers.go:185`). If lookup falls back to aliases, that re-read could resolve through an alias and return stale data.
9. **Migration.** Existing rows have no history, so their old slugs are already lost. The new table must be added to `AutoMigrate` in `hello.go` and in the test DB setup (`articles/unit_test.go:339`).
10. **Lookup cost.** A fallback query on every miss adds a DB hit per 404. Without an index it also slows down.
11. **Slug edge cases.** Titles that slugify to an empty string, to the same slug (no-op rename), or to a non-ASCII slug need handling. A no-op must not write an alias.
12. **Unbounded growth.** Unlimited renames mean unlimited alias rows per article, and rename spam could be used to squat slugs.

## Plan (recommended, not executed)

- **Model:** add `ArticleSlugHistory{ID, ArticleID (index), Slug (uniqueIndex), CreatedAt}` in `articles/models.go`. Register it in `hello.go` and in the test setup.
- **Uniqueness:** extend `makeUniqueSlug` to also check the history table (risks 1, 2).
- **Lookup:** add `FindArticleBySlug(slug)`. It tries `articles.slug` first, then the history join, and returns the article with its canonical slug. Use it in every `:slug` handler (risks 5, 10).
- **Rename:** wrap the update and the history insert in one transaction. Skip no-op renames. If the new slug equals one of this article's own history entries, delete that entry (risks 3, 4, 11).
- **Response:** serve the article directly, with no redirect, and make sure `slug` in the body is canonical (risks 7, 8).
- **Deletion:** keep the aliases of soft-deleted articles reserved (risk 6).
- **Tests** in `articles/unit_test.go`:
  - old-slug GET returns 200 with the new slug;
  - rename chain A→B→C;
  - rename back to A;
  - slug reclaim attempt;
  - non-author write via old slug returns 403;
  - delete via old slug.
- **Verify:** run `go build ./...`, `go test ./...`, and the hurl/bruno suites.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Old slug reclaimed by a new article | `makeUniqueSlug` checks only the `articles` table, so a freed slug gets reused | Check the history table in `makeUniqueSlug`; unique index on alias slug |
| 2 | Rename and alias insert not atomic | `Update` and the history write are separate calls today, so a failure loses the old link | One transaction around both |
| 3 | Concurrent renames collide | The existing retry loop covers only `articles.slug` | Extend retry to alias unique-key errors |
| 4 | Rename-back or chain makes bad alias rows | A→B→A would collide with its own history | Delete own matching alias; always resolve to the current article |
| 5 | Old-slug writes skip authorization | Handlers all call `FindOneArticle` directly, so a fallback must be shared | Single lookup helper; keep the author checks; test 403 |
| 6 | Redirect breaks API clients and specs | hurl/bruno suite expects JSON 200/404 | Serve directly with the canonical slug in the body |
| 7 | Stale re-read after update | `routers.go:185` re-fetches by slug, so alias fallback could return old data | Re-fetch by ID or the new slug explicitly |
| 8 | Existing links already lost | Past renames left no history, and nothing can restore them | Document it; backfill is impossible |
| 9 | Soft-delete and alias interplay | Deleted articles' slugs stay reserved today | Keep aliases reserved on soft delete |
| 10 | Unbounded alias growth and squatting | Each rename adds a permanent row | Cap aliases per article or rate-limit renames |

Riskiest: #1, reclaiming a freed slug. A shared link would silently open a different author's article, which is worse than a 404.
