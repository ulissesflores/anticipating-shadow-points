This is a one-line logic change in express-session: make the existing `rolling` option default to `true`. Most of the work is in the tests and in labelling it as a breaking change. I didn't edit any repo files; the plan is saved at `claude-home/plans/make-sessions-roll-by-rippling-horizon.md`.

**Assumptions** (non-interactive run)
- "Roll by default" means the existing `rolling` option should default to `true`. I'm not adding a new option.
- Setting `rolling: false` explicitly still turns it off. Only leaving the option unset changes behaviour.
- The change applies now, with no deprecation-warning period first (unlike how `resave` and `saveUninitialized` were handled). That makes it semver-major, or at least a clearly flagged breaking entry in HISTORY.md.

**Plan**
1. **`index.js:109`**: change `var rollingSessions = Boolean(opts.rolling)` to `opts.rolling === undefined ? true : Boolean(opts.rolling)`, and update the JSDoc at `index.js:78`. `shouldSetCookie` (`index.js:483-492`) already behaves correctly once the flag is true, so no other logic changes.
2. **`README.md` `##### rolling`**: change the stated default to `true`, document `rolling: false` as the way to opt out, and note that a cookie without `maxAge` is now re-sent on every response.
3. **`HISTORY.md` (unreleased)**: add "Change default `rolling` option to `true`" as a breaking change.
4. **`test/session.js`**:
   - Rename `'should default to false'` (line 1159) to `'should default to true'` and expect a `Set-Cookie` on the second request.
   - Add a test for an explicit `rolling: false`.
   - The test helper `createSession` (line 2838) sets `maxAge: 60000` by default. Some of the 26 tests that assert `shouldNotHaveHeader('Set-Cookie')` on a request carrying an existing session cookie will now fail. In those tests I'd add `rolling: false` one test at a time rather than in the helper, so the new default is still exercised everywhere else.
   - Add a test that the store's expiry is extended through `store.touch` with the default options.
5. **Verification**:
   - Run `npm test`.
   - Run a small express app with `maxAge: 10000` and send a request every 5s. `Expires` should move forward each time and the session should last past 10s.
   - With `rolling: false`, confirm there's no `Set-Cookie` on unmodified sessions.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Silent behaviour change for existing apps | Every app that never set `rolling` changes on upgrade | Major version bump plus a breaking-change HISTORY/README note |
| 2 | Idle sessions never time out for active users | Security or compliance policies may assume a fixed (absolute) session lifetime | Document `rolling: false`; suggest a separate absolute-timeout check |
| 3 | `Set-Cookie` on every response breaks caching | CDNs and proxies often refuse to cache responses that set cookies | Doc warning; mount session only on routes that need it |
| 4 | Many existing tests fail | Test helper defaults `maxAge: 60000`; some of the 26 no-`Set-Cookie` tests would now fail | Add `rolling: false` to each affected test |
| 5 | Setting the opt-out in the test helper hides regressions | Putting `rolling: false` in `createSession` would leave the new default untested | Opt out per test, not in the helper |
| 6 | More store writes and touches | Rolling sessions touch on every request; stores without `touch` plus `resave` write more | Test the `store.touch` path; recommend stores that implement `touch` |
| 7 | Header bloat and extra signing work with browser-session cookies | `shouldSetCookie` returns true even when `maxAge` is null | Note in README; optionally skip the cookie when `expires == null` (separate decision) |
| 8 | Falsy values handled inconsistently | `null` or `0` could be read as "unset" by mistake | Check strictly for `=== undefined`; add a test for `rolling: false` |

Riskiest: #1, the silent default change for every existing app.
