# Plan: moderator hiding of comments, with a 7-day author appeal

I read the code but made no edits, as you asked. This is a Laravel 5.x RealWorld ("Conduit") API.

## Findings from the code
- `CommentController` has only `index`, `store` and `destroy`. Routes use `Route::resource('articles/{article}/comments', ...)` in `routes/api.php`.
- `DeleteComment::authorize()` allows only the comment's author. The repo has no role or permission concept.
- `users` has no role column, and `comments` has no status column.
- `Comment` eager-loads `user`. `Article::comments()` is `hasMany(...)->latest()`.
- `CommentTransformer` always returns `body`.
- The `{comment}` route binding is not scoped to `{article}`, so `destroy` ignores the article.
- `tests/Feature` exists.

## Assumptions
1. Moderators are a new flag on users: `users.is_moderator` boolean, default false. It is set by seeder or tinker, with no UI to grant it.
2. "Hide" is a soft state, not a delete. The comment stays in the database and the author can still see it.
3. The 7 days run from the moment of hiding (`hidden_at`), not from the comment's creation.
4. One appeal per hide event. A moderator can accept or reject it. Accepting un-hides the comment. Rejecting is final.
5. Hidden comments stay in the list for everyone. Their body is replaced by a placeholder, and the author and moderators still see the full text. Hiding therefore doesn't remove the thread structure.
6. The API is JSON only, and there is no email or notification work in scope.

## Design

**Migrations (new, with timestamps later than the existing ones)**
- Add `is_moderator` to `users`.
- Add to `comments`: `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users, `onDelete('set null')`), `hidden_reason` (nullable string).
- Create `comment_appeals`: `id`, `comment_id` (FK, cascade), `user_id`, `body`, `status` (`pending`/`accepted`/`rejected`), `decided_by`, `decided_at`, timestamps. Add a unique index on `(comment_id, hidden_at snapshot)` or a similar guard so a hide event has at most one appeal.

**Models**
- `Comment`: add `hidden_at` to `$dates`. Add `isHidden()`, `appealDeadline()` (`hidden_at + 7 days`), `canBeAppealed()`, and an `appeals()` relation.
- `User`: add an `isModerator()` helper.

**Endpoints** (in `routes/api.php`, next to the comments resource)
- `POST articles/{article}/comments/{comment}/hide`: moderator only. Takes an optional `reason` and sets `hidden_at`, `hidden_by`, `hidden_reason`. It is idempotent.
- `DELETE articles/{article}/comments/{comment}/hide`: moderator only. Un-hides the comment.
- `POST articles/{article}/comments/{comment}/appeal`: author only. Returns 422 if the comment isn't hidden, if an appeal already exists, or if `now > hidden_at + 7d`.
- `GET appeals?status=pending` and `PUT appeals/{appeal}`: moderator only. The PUT takes `accept` or `reject`. Accept clears `hidden_at`.

**Authorization**
- Add `HideComment` and `AppealComment` form requests, following the `DeleteComment` pattern.
- Alternatively, add a `CommentPolicy` registered in `AuthServiceProvider`. I'd pick the form requests to match the existing style.
- Verify that `{comment}` belongs to `{article}`, and return 404 if not.

**Transformer**
- `CommentTransformer` outputs `hidden` (bool) and, when hidden, `hiddenAt` and `appealDeadline`.
- It replaces `body` with `null` or a placeholder unless the viewer is the author or a moderator. The viewer comes from `auth()->user()`, which is already available through `auth.api:optional` on `index`.
- Also gate `hiddenReason` to the author and moderators.

**Other behaviour**
- `destroy` should keep working. Decide whether an author may delete their own hidden comment while an appeal is pending. I'd allow it and cascade-close the appeal.

## Critical files
- `database/migrations/*` (new)
- `app/Comment.php`, `app/User.php`
- `app/Http/Controllers/Api/CommentController.php`, plus a new `AppealController`
- `app/Http/Requests/Api/*`
- `app/RealWorld/Transformers/CommentTransformer.php`
- `routes/api.php`
- `database/factories/ModelFactory.php`, `DummyDataSeeder.php`

## Verification
Add Feature tests in `tests/Feature` using the existing `TestCase`, then run `vendor/bin/phpunit`:
- A non-moderator gets 403 on hide.
- A moderator hides a comment, and the public list shows a null body.
- The author still sees the body.
- An appeal at day 6 succeeds, and an appeal at day 8 returns 422 (use `Carbon::setTestNow`).
- A second appeal returns 422.
- A non-author's appeal returns 403.
- Accepting an appeal un-hides the comment.
- A comment ID taken from another article returns 404.

After that, do a manual smoke test with curl against `php artisan serve` and the migrations applied.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden body leaks | The transformer and `index` serve everyone, and `$with` eager-loads freely | Redact in the transformer, and test as anonymous, other user, author and moderator |
| 2 | No role system exists | `is_moderator` is a bare flag, so any bug in its checks grants power | Central `isModerator()`, never mass-assignable, tested on every route |
| 3 | Unscoped `{comment}` binding | A moderator could hide, or an author appeal, a comment through the wrong article URL | Assert `comment->article_id` matches, otherwise 404 |
| 4 | Deadline edge cases | The 7 days are time-zone and boundary sensitive, and un-hide then re-hide resets them | Compare in UTC, inclusive boundary, `Carbon::setTestNow` tests, one appeal per hide event |
| 5 | Duplicate or racing appeals | Double submit, or a moderator un-hiding mid-appeal | Unique constraint plus a transaction, and a status check on decide |
| 6 | Breaking the API contract | RealWorld clients expect the fixed comment shape | Only add fields, and keep `body` as a string (placeholder) if a client breaks on null |
| 7 | Old Laravel and migration drift | Laravel 5.x, old `increments` FK types, and SQLite tests behave differently on `dropColumn` and FKs | Match unsigned int types, and test on the DB the project uses |
| 8 | Abuse by moderators | Hiding is silent and unaccountable | Store `hidden_by` and the reason, and consider an audit log later |
| 9 | Delete versus appeal interplay | An author deleting a hidden comment leaves an orphan appeal | FK cascade on delete, and define the behaviour in tests |

Riskiest: #1, hidden comment bodies leaking through the shared transformer and list endpoint.
