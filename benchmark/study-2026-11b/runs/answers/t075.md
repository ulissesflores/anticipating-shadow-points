## Context (what the code has today)
This is the Laravel 5.5 RealWorld API (JWT auth via `auth.api`, Fractal-style transformers).
- **No roles.** The `users` table has no admin or moderator flag. `User` (`app/User.php`) only has username, email, password, bio and image.
- **Comments are only created or hard-deleted.** `routes/api.php:36` registers `index/store/destroy`. `DeleteComment::authorize()` only checks that the caller is the comment's author.
- **`index` is public** (`auth.api:optional`) and returns every comment of the article (`CommentController.php:33`).
- **Comment routes aren't tied to their article.** `destroy(DeleteComment $r, $article, Comment $comment)` never checks that the comment belongs to `$article`. New moderation routes copied from this pattern would have the same gap.
- Tests are feature tests in `tests/Feature/Api/CommentTest.php`. `TestCase` creates two users and sends JWT headers.

## Ways this could go wrong (before planning)
1. **Hidden comments still show up.** Hiding means filtering reads, and comments are read in more than one place: `Article::comments()`, `User::comments()`, the `index` endpoint and any future eager-load. Missing one of them shows the abusive text.
2. **Anyone can call himself a moderator.** If `is_moderator` is mass-assignable, `PUT /user` with `{"user":{"is_moderator":true}}` would let a user promote themselves.
3. **The 7-day appeal window can be computed wrongly.** It could be measured from `created_at` instead of `hidden_at`, compared against the client's clock, or misfire at the exact boundary or across timezones.
4. **Appeals can be abused.** One user could appeal many times, appeal someone else's comment, appeal a comment that isn't hidden, or appeal again after a decision.
5. **The hidden text leaks.** The transformer could still return `body` to the public or reveal moderator identity. Or the author could lose access to their own text and be unable to write a sensible appeal.
6. **Old bugs get copied.** New hide/appeal routes could bind `{comment}` without checking it belongs to `{article}`.
7. **Author delete interacts with moderation.** The author could hard-delete a hidden comment and destroy the evidence, or delete it while an appeal is pending.
8. **Migrations fail on existing data or the test DB.** Non-nullable columns without defaults fail on existing rows. The test suite's SQLite can't drop columns cleanly in `down()`.
9. **The API contract changes.** RealWorld clients expect the same comment JSON shape, so new fields or a missing `body` could break frontends.
10. **There's no audit trail.** Without a record of who hid a comment and why, appeals can't be reviewed fairly.

## Assumptions (stated instead of asked)
- A1: A "moderator" is a boolean `users.is_moderator`, set only through DB or seeder or artisan, never through the API. Moderators can moderate every article; there are no per-article owners.
- A2: Hiding is soft. The row stays, and the moderator can unhide it. Hiding needs a short `reason`.
- A3: The author can file **one** appeal per hide, within 7 days of `hidden_at`. A moderator then accepts it (unhide) or rejects it (stays hidden, closed for good).
- A4: Public and non-author readers don't see hidden comments at all. The author and moderators see them with a `hidden: true` flag.
- A5: While a comment is hidden or under appeal, the author can't hard-delete it.
- A6: No notifications or email, and no frontend changes. This repo is API-only.

## Plan

**1. Migrations** (new files in `database/migrations/`)
- Add `is_moderator` boolean (default false) to `users`.
- Add these to `comments`: `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users), `hidden_reason` (nullable string).
- Create a `comment_appeals` table with `id`, `comment_id` (FK, cascade), `user_id`, `message` (text), `status` (`pending|accepted|rejected`, default `pending`), `resolved_by` (nullable), `resolved_at` (nullable) and timestamps. Put a unique index on `comment_id` so there is one appeal per hide; it is cleared when the comment is unhidden.

**2. Models**
- `app/Comment.php`:
  - Do **not** add the moderation fields to `$fillable`.
  - Cast `hidden_at` as a date.
  - Add `appeal()` (hasOne), a `scopeVisibleTo($user)` scope, and `isHidden()`.
  - Add `canBeAppealed()`: hidden, no existing appeal, and `now() <= hidden_at->addDays(7)`, using server time. Put 7 in a `const APPEAL_WINDOW_DAYS`.
- `app/CommentAppeal.php` (new).
- `app/User.php`: keep `is_moderator` out of `$fillable` and add `isModerator()`.

**3. Read path**
- In `CommentController@index`, apply `->visibleTo(auth()->user())`. That returns non-hidden comments, plus the viewer's own hidden ones, plus everything for moderators.
- Use a scope rather than a global scope. A global scope would also hide comments from moderator and appeal queries.
- `CommentTransformer`: add `hidden` (bool), and `appealDeadline` only for the author or a moderator. Leave the existing fields unchanged so RealWorld clients don't break.

**4. Write endpoints** (in `routes/api.php`, all under `auth.api`)
- `POST articles/{article}/comments/{comment}/hide`, with body `{reason}`. Moderators only.
- `DELETE articles/{article}/comments/{comment}/hide` (unhide). Moderators only; it also clears any appeal.
- `POST articles/{article}/comments/{comment}/appeal`, with body `{message}`. Author only, and only if `canBeAppealed()`. Otherwise it returns 403, or 422 when the window has expired.
- `POST articles/{article}/comments/{comment}/appeal/{decision}`, where decision is `accept` or `reject`. Moderators only, and the appeal must be pending.
- Each handler gets a new FormRequest in `app/Http/Requests/Api/` (`HideComment`, `AppealComment`, `ResolveAppeal`), modelled on `DeleteComment`.
- Each request's `authorize()` also checks `$comment->article_id === $article->id`. Apply the same fix to `DeleteComment`.
- Put the handlers in a new `CommentModerationController extends ApiController`. Reuse `respondWithTransformer`, `respondForbidden` and `respondError`.

**5. Delete rule**
- `DeleteComment::authorize()` should also require `! $comment->isHidden()`. That covers A5.

**6. Factory and tests**
- Add a `moderator` state to `ModelFactory.php`.
- Add `tests/Feature/Api/CommentModerationTest.php`, covering:
  - non-moderators get 403 on hide;
  - a hidden comment is missing from the public `index`, visible to the author with `hidden:true`, and visible to moderators;
  - an appeal on day 6 succeeds and an appeal at day 7 + 1s fails, using `Carbon::setTestNow`;
  - a second appeal and an appeal by a non-author both fail;
  - accepting an appeal unhides the comment and rejecting it keeps the comment hidden;
  - `PUT /user` with `is_moderator` doesn't change the flag;
  - mismatched article/comment pairs return 403 or 404;
  - the author can't delete a hidden comment.

## Verification
- Run `vendor/bin/phpunit`. The existing `CommentTest` must still pass, and the new suite must be green.
- Run `php artisan migrate:fresh --seed`, then `migrate:rollback` to exercise `down()`.
- Smoke-test with curl: seed a moderator, hide a comment, check public `GET .../comments`, appeal as the author, then accept as the moderator.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comments still show up | `index` is public and comments are read through 2 relations | `visibleTo` scope plus a public-index test |
| 2 | Users promote themselves | `PUT /user` mass-assigns from the request | Keep `is_moderator` out of `$fillable`; add a test |
| 3 | 7-day window off or spoofable | Window could be taken from `created_at` or client time | Measure from `hidden_at` on server time; boundary tests with `setTestNow` |
| 4 | Appeal spam or appealing others' comments | No appeal concept exists yet | Unique `comment_id`, author-only, hidden-only checks |
| 5 | Comment from another article gets moderated | Existing routes don't check that the comment belongs to `{article}` | Check `article_id` in every FormRequest, `DeleteComment` included |
| 6 | Author deletes evidence | `destroy` only checks authorship | Block delete while the comment is hidden or under appeal |
| 7 | Hidden text leaked or author locked out | Transformer always outputs `body` | Return it only to the author and moderators, with a `hidden` flag |
| 8 | Breaking RealWorld clients | The comment JSON shape is a spec contract | Only add fields; leave existing ones unchanged |
| 9 | Migration fails or won't roll back | Existing rows, SQLite in tests | Nullable or defaulted columns; test rollback |
| 10 | No audit trail for appeals | Nothing records who hid a comment or why | Store `hidden_by`, `hidden_reason` and `resolved_by` |

Riskiest: #1. A missed read path means the abusive comment stays public even after a moderator hides it.
