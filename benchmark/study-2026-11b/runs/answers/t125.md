# Plan: tenant isolation for to-do lists and items

## Context

This is the Clean Architecture template. `TodoList` and `TodoItem` have no owner, so every authenticated user sees every list. `GetTodosQueryHandler` reads `_context.TodoLists` with no filter. Four handlers use `FindAsync(id)`: UpdateTodoItem, UpdateTodoItemDetail, DeleteTodoItem and UpdateTodoList. Delete-list probably does too, and the IDs are sequential ints, so any user can edit or delete another company's data by guessing an ID. The database is created with `EnsureCreatedAsync` and the repo has no migrations folder. Auditing goes through `AuditableEntityInterceptor`, and `IUser` exposes only `Id` and `Roles`.

## Assumptions

- A tenant is a company. Each user belongs to exactly one tenant, and there are no cross-tenant users.
- The tenant ID comes from a `tenant_id` claim, which is added to the identity when the user signs in. The client never sends it.
- I'll use a `Guid TenantId` and a `Tenant` entity, and no subdomain routing.
- Existing rows are demo seed data and will go to a default tenant.
- A single shared database with a discriminator column is enough. I'm not planning database-per-tenant.
- Admin and super-admin cross-tenant access is out of scope.

## Steps

1. **Domain.** Add `ITenantEntity { Guid TenantId }` in `src/Domain/Common`. Implement it on `TodoList` and `TodoItem`. Add a `Tenant` entity (Id, Name).
   - `TodoItem` also gets a `TenantId`, so the query filter works without a join and a list-ID mismatch can be caught.
2. **Identity.** Add `Guid? TenantId` to `ApplicationUser` (`src/Infrastructure/Identity`). Emit it as a claim through a custom `IUserClaimsPrincipalFactory`.
3. **Current tenant.** Add `ITenantProvider { Guid? TenantId }` in Application, next to `IUser`. Implement it in `src/Web/Services`, beside `CurrentUser`, reading the claim. Register it as scoped.
4. **Read isolation.** In `ApplicationDbContext.OnModelCreating`, add `HasQueryFilter(e => e.TenantId == _tenant.TenantId)` for both entities.
   - The filter has to read a context instance field so EF re-evaluates it per request.
   - If the tenant is null (no claim), fail closed: match nothing.
   - `FindAsync` is not filtered in every case, because it can return an entity already tracked by the context. So I'll replace it with `FirstOrDefaultAsync(x => x.Id == id)` in the five handlers.
5. **Write isolation.** Add a `TenantInterceptor` (an `ISaveChangesInterceptor`) next to `AuditableEntityInterceptor`.
   - On Added, it stamps `TenantId`.
   - On Modified, it rejects any `TenantId` change or mismatch.
   - Register it in `DependencyInjection.cs`.
6. **Cross-entity checks.** In `CreateTodoItem`, check that the target list exists under the current tenant. The filter makes this fail naturally. Return `NotFoundException`.
7. **Schema.** There are no migrations, and `EnsureCreated` won't alter existing databases.
   - I'd add an EF migration to introduce `Tenants` and the `TenantId` columns, backfill a default tenant, then make the column non-nullable.
   - I'd add an index on `(TenantId)` and consider `(TenantId, ListId)` for items.
   - Update `TodoListConfiguration` and `TodoItemConfiguration`.
   - Make the initialiser seed a default tenant and assign the admin user to it.
8. **Frontend and API.** Probably no change, since the claim rides the existing cookie or token. The NSwag-generated clients stay the same because no DTOs change. I'll check the Angular and React clients to confirm.
9. **Tests.** In `tests/Application.FunctionalTests`, add a way to run as a user in tenant A or B.
   - Check `GetTodos` returns only tenant A's data.
   - Check that update, delete and create-item calls against tenant B IDs throw `NotFoundException`.
   - Check that stamping on create works.
   - Add a Domain or Infrastructure unit test for the interceptor.
   - Update the existing tests, which currently assume a single global scope.

## Verification

- Run `dotnet build` and `dotnet test`. The functional tests need the test database.
- Manually start the app, sign in as two users in different tenants, and confirm neither sees the other's lists. Then call the API directly with the other tenant's IDs and expect 404.
- Inspect the generated SQL (EF logging) to confirm `WHERE TenantId = @p` on every query. Check that the dashboard and the `ProjectTo` projection also get it.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Missed filter leaks data | `FindAsync` bypasses the filter when an entity is already tracked, and there are five call sites | Replace them with filtered queries, and add cross-tenant tests for every handler |
| 2 | Null tenant fails open | An unauthenticated or claim-less call could compare to null and match rows | Fail closed: a null tenant matches nothing |
| 3 | Existing data has no tenant | `EnsureCreated` and no migrations mean existing databases can't be altered | Migration with a default-tenant backfill, then NOT NULL |
| 4 | Client-supplied tenant | A `TenantId` in a request body would let a user write into another company | Take it only from the claim, and stamp it in the interceptor |
| 5 | Cross-tenant FK | A tenant A item could point at a tenant B list | Check the list under the filter, and add a composite constraint |
| 6 | Stale claims | A user moved between tenants keeps the old claim until re-login | Short token lifetime, or reload the claim from the database |
| 7 | Filter ignores DI scope | A filter captured at model-build time would freeze the first tenant for all requests | Reference the context field, not a captured value |
| 8 | Background paths | The initialiser and domain event handlers run with no tenant | Use `IgnoreQueryFilters` explicitly, with a seeding tenant |
| 9 | Tests break | Existing functional tests assume a global scope | Add tenant-aware test helpers and update the fixtures |
| 10 | Performance | Every query now filters on `TenantId` | Index it, and check the query plans |

Riskiest: #1, a missed filter silently leaking another company's data through the `FindAsync` call sites.
