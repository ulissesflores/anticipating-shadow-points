## Assumptions
- "By default" means changing the constructor defaults in `SessionMiddleware.__init__` to `same_site="strict"` and `https_only=True`. Callers can still override both. That is a source-compatible but behavior-breaking change.
- Starlette is a published library, so this is a breaking default change. It needs a release-note entry and an update to `docs/middleware.md`. `AGENTS.md` requires explanatory text after each heading, before any code snippet.
- `same_site="none"` combined with `https_only=False` stays allowed. Browsers reject that pairing, but the middleware doesn't police it today.
- I'm not adding new parameters or auto-detection from `scope["scheme"]`.

## Ways this could go wrong
1. **Plain-HTTP deployments lose sessions.** Browsers drop `Secure` cookies on `http://` origins. Local dev and internal HTTP services would see `request.session` always empty, with no error.
2. **The test suite breaks.** `TestClient` uses `http://testserver`, and its cookie jar won't send `Secure` cookies back over HTTP. Most tests in `tests/middleware/test_session.py` that use the defaults would lose their session on the second request. `tests/middleware/test_middleware.py:42` builds a bare `SessionMiddleware` as well.
3. **Strict SameSite breaks cross-site navigation.** Strict withholds the cookie on top-level navigations from other sites. Users following a link or an OAuth/SSO redirect back to the app arrive logged out on the first request.
4. **Existing tests that assert the old flags fail.** The cookie-string assertions expect `samesite=lax` and no `secure`.
5. **Reverse proxies terminating TLS.** The app sees `http` behind the proxy, but the browser sees HTTPS. The `Secure` cookie still works in the browser, but any Starlette code that infers scheme internally behaves differently.
6. **The cookie-clearing path is affected too.** It reuses `security_flags`. Clearing a cookie with different attributes than it was set with can leave the old cookie in the browser. Existing sessions set under `lax` without `Secure` might not be overwritten consistently during rollout.
7. **Documentation drifts.** `docs/middleware.md` says `same_site` defaults to `'lax'` and `https_only` to `False`. Stale text would mislead users.
8. **Cross-site embeds break.** Users of `partitioned=True` or `same_site="none"` who only set one of the flags would now get a conflicting combination, such as strict plus partitioned.
9. **Silent failure and hard debugging.** Nothing warns when the cookie is set but never returned, so users blame the session logic.
