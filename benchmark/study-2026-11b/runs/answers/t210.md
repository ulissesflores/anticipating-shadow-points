## What the code does today
- This is Spring PetClinic. `Visit` (`src/main/java/org/springframework/samples/petclinic/owner/Visit.java`) has only `date` (a day, no time) and `description`. It has no vet and no time, so "the same vet at the same time" can't be recorded at all yet.
- Booking already exists at `/owners/{ownerId}/pets/{petId}/visits/new` in `VisitController`. It saves through `owners.save(owner)`.
- The app has no login at all.
- The schema is plain SQL with no migration tool. The MySQL and Postgres schemas use `CREATE TABLE IF NOT EXISTS`. The H2 and MySQL sample-data files insert visit rows by column position, without naming the columns.
- `spring.jpa.open-in-view=false`, so the owner details page can't load related data on demand.
- A test (`I18nPropertiesSyncTest`) requires every message key to exist in all 11 `messages*.properties` files.

## Assumptions
- Visits are 30-minute slots on a fixed grid, 09:00–17:00, and the hours can be changed in config. Because every visit starts on the grid, "overlapping" becomes "same vet, date and start time", which a database unique constraint can enforce.
- "Online" means the existing booking page. Owner login and checking that the visitor owns the pet are a separate follow-up.
- Existing visits keep an empty vet and time. Cancelling and rescheduling are out of scope.
- The server's time zone is the clinic's time zone.

## The plan
1. **Schema (all 3 databases):** add `vet_id` (linked to `vets`) and `visit_time` to `visits`, plus `UNIQUE (vet_id, visit_date, visit_time)`. Empty values never count as duplicates, so old visits are unaffected. Add an `ALTER TABLE` script for existing MySQL and Postgres databases, and switch the sample-data inserts to named columns.
2. **`Visit` entity:** add a required `vet` and `time`. Load the vet together with the visit, because the owner details page shows visits after the database session has closed.
3. **Repositories:** add `VetRepository.findById`. Add a new `VisitRepository` with `existsByVetIdAndDateAndTime` and `findByVetIdAndDate`.
4. **`VisitBookingService`:** in one transaction, check whether the slot is free, then save and flush immediately. If the database rejects a duplicate, turn that error into a "slot taken" error. The database constraint is what actually prevents double booking; the check first just gives a friendlier message.
5. **`VisitController`:** provide the vet list (from the existing cached `findAll`) and the time slots to the form. Reject times off the grid or outside hours, and show a "slot taken" error on the time field. Add a vet formatter following `PetTypeFormatter`. The vet is bound through a `vet` field because `*.id` fields are blocked from form binding.
6. **Templates:** add vet and time selects to `createOrUpdateVisitForm.html`, and show vet and time on `ownerDetails.html`, allowing for old visits that have neither.
7. **Messages:** add the new keys to all 11 message files.
8. **Tests:**
   - Controller tests for success, missing vet or time, bad time, and slot taken.
   - An H2 test that the unique constraint rejects a second booking of the same slot.
   - A two-thread test where exactly one of two bookings succeeds.
   - Run the schema and migration against MySQL and Postgres.
   - Run `./mvnw verify`, then book the same slot from two browser tabs.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Two concurrent bookings of the same slot both succeed | A "check then insert" in code alone has a race window | DB unique constraint on (vet, date, time) is the real guard; flush and translate the error |
| 2 | Existing MySQL/Postgres databases never get the new columns | Their schema uses `CREATE TABLE IF NOT EXISTS`, and there's no migration tool | Ship an explicit `ALTER TABLE` script and document it; consider adding Flyway |
| 3 | Sample-data loading breaks at startup | H2 and MySQL insert visits by column position | Rewrite the inserts with named columns |
| 4 | Error when showing the vet on the owner page | `open-in-view=false`, so the vet can't be loaded later | Load the vet together with the visit, or fetch it in the query |
| 5 | Duplicate error shows up at commit as a 500 page | `owners.save` cascades the insert, which only runs when the transaction commits | Save and flush in the service, and catch `DataIntegrityViolationException` |
| 6 | Overlaps the constraint doesn't catch | It only compares equal start times | Enforce on-grid, fixed-length slots on the server |
| 7 | Anyone can book for any owner | No login exists, and owner and pet IDs are in the URL | State it explicitly as a follow-up (owner login and ownership checks) |
| 8 | Build fails on missing message keys | `I18nPropertiesSyncTest` checks all 11 files | Add every new key to all files |
| 9 | Old visits break the UI or validation | They have no vet or time | Columns allow empty values; templates handle missing values; validation applies only to new bookings |
| 10 | Wrong-day or wrong-hour bookings | `LocalDate.now()` uses the server's time zone | Set the clinic time zone in config |

Riskiest: #2. Existing MySQL/Postgres databases won't get the new columns or constraint because there's no migration tool, so the app fails or double booking stays possible until someone runs the `ALTER TABLE` script by hand.
