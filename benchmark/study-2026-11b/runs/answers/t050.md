## Context

`SessionMiddleware.__init__` in `starlette/middleware/sessions.py:24-25` defaults to `same_site="lax"` and `https_only=False`. That means the session cookie goes out without `Secure` and with `SameSite=Lax`. The request is to flip both defaults: `Secure` and `SameSite=Strict` out of the box.

**Assumptions** (non-interactive run, so I didn't ask):
- Keep the current argument names and change only the defaults. No new parameters and no deprecation shim.
- This counts as a breaking change, so it goes into the next major/minor release with a release-notes entry.
- Before opening a PR, I'd search existing PRs, issues and discussions for the same proposal, as `AI_POLICY.md` requires. Starlette bans contributors who open duplicate PRs.

## Ways this could go wrong (before planning)

1. **Logins via OAuth/SSO break.** With `Strict`, the browser doesn't send the cookie on the cross-site redirect back from the identity provider. Any OAuth `state` or PKCE value stored in `request.session` (Authlib's Starlette client does this) is missing, and the callback fails.
2. **Users look logged out when they follow links from other sites.** With `Strict`, a link from an email, Slack or another site arrives without the session cookie. `Lax` exists to prevent exactly this.
3. **Plain-HTTP setups lose the session.** Browsers drop or don't send `Secure` cookies over plain HTTP. That covers `http://127.0.0.1`, LAN IPs, Docker hostnames, older Safari on `localhost`, and internal HTTP-only tools.
4. **Downstream test suites break quietly.** `TestClient` defaults to `http://testserver`, and httpx's cookie jar won't send a `Secure` cookie back over http. Every user test that checks session state across requests stops working, with no error pointing at the cookie.
5. **This repo's own tests break.** `tests/middleware/test_session.py` uses http clients in many places, e.g. line 175 uses `base_url="http://testserver/second_app"`, and some tests assert exact `set-cookie` strings.
6. **Existing cookies don't change.** Cookies already in browsers keep their old attributes until the session is modified or `max_age` runs out (14 days by default).
7. **It's an unannounced behavior change.** Nothing raises an error. Sessions just disappear in some flows, so without loud release notes the fix is hard to find.
8. **Docs go stale.** `docs/middleware.md:235-252` documents the `'lax'`/`False` defaults, recommends `https_only=True`, and tells `partitioned` users to set `https_only=True`.
9. **Two clashing combinations.** `same_site="none"` without `Secure` gets rejected by browsers, and that is still possible if someone sets `https_only=False`. On the other side, `partitioned=True` combined with the new `Strict` default is close to useless for cross-site embeds.

## Plan

1. **`starlette/middleware/sessions.py`:** change the defaults to `same_site="strict"` and `https_only=True`. The `security_flags` building stays the same. The cookie-clearing branch already reuses `security_flags`, so cleared cookies stay consistent.
2. **`tests/middleware/test_session.py`:**
   - Add a test that asserts the default `set-cookie` contains `secure` and `samesite=strict`.
   - Tests that use `http://` clients either switch to `base_url="https://testserver"` or pass `https_only=False` explicitly.
   - Update the tests that compare exact `set-cookie` strings (lines 64, 178, 218, 251).
   - Keep `test_secure_session` (line 130) to show that http clients don't get the cookie back.
3. **`docs/middleware.md`:**
   - Update the `same_site` and `https_only` defaults.
   - Simplify the example, since `https_only=True` is now the default.
   - Add a short "Local development and OAuth" note: use `https_only=False` for plain-HTTP dev, and `same_site="lax"` if login goes through OAuth/SSO redirects or users arrive via external links.
   - Rewrite the `partitioned` advice.
   - Per `AGENTS.md`, put explanatory text after every heading before any code block.
4. **`docs/release-notes.md`:** add a breaking-change entry with a before/after table and the one-line opt-outs.
5. **PR hygiene:** search existing and closed PRs and issues first (AI policy). Commit and PR attribution as configured.
