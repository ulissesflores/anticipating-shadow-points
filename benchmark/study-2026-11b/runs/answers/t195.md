## Finding

`ArticleUpdate` (`articles/routers.go:152-160`) already regenerates the slug when the title changes. Nothing keeps the old slug, so every shared link to the old slug now returns 404. The fix is to remember retired slugs and resolve them. The 404 is the bug to fix, not a missing feature.

## Assumptions
- Old slugs should keep working for reads, and any method on an old slug should resolve to the same article.
- `GET /api/articles/:slug` should answer 200 with the article, whose `slug` field is the canonical one. Clients can then rewrite their URL. An HTTP 301 is not suitable for a JSON API.
- Retired slugs must never be reused by another article.
- The title-to-slug rules stay as they are (`makeSlug`, `makeUniqueSlug`).
- SQLite with GORM `AutoMigrate`, as today. There's no migration framework.

## Plan

1. **New model** in `articles/models.go`: `ArticleSlugAlias{ID, ArticleID (index), Slug (uniqueIndex), CreatedAt}`.
   - Add `db.AutoMigrate(&articles.ArticleSlugAlias{})` in `hello.go` and in the two test setups in `articles/unit_test.go` (around lines 339 and 1597).
2. **Resolution helper**: `resolveArticleBySlug(slug)`.
   - Try `FindOneArticle(&ArticleModel{Slug: slug})` first. On `ErrRecordNotFound`, look up the alias and load the article by `ArticleID`.
   - The current slug always wins over an alias.
   - Use it in the handlers that take `:slug`: Retrieve, Update, Delete, Favorite, Unfavorite, the two comment routes, and comment delete.
   - Deleted articles stay 404, because the soft-delete scope applies to the article lookup.
3. **Write the alias inside the update**, in the same transaction as the slug change.
   - `articleModel.Update` currently runs outside a transaction. Wrap the slug update and the alias insert together, so a failure cannot leave a retired slug unrecorded.
   - Keep the existing duplicate-key retry loop.
4. **Make slug generation alias-aware.**
   - `makeUniqueSlug` must also check the alias table, so a new article cannot take a retired slug.
   - Use the same check for the new slug on rename.
5. **Chain and revert handling.**
   - On A→B→C, aliases A and B both point to the article ID, so no chain walking is needed.
   - If a title changes back to a slug the same article retired earlier, delete that alias row inside the transaction before the update. Otherwise the slug is both current and aliased.
   - `makeUniqueSlug` must treat the article's own aliases as available, or the revert gets a `-2` suffix.
6. **Delete and cleanup.** Delete the aliases when the article is hard-deleted, since the article currently soft-deletes.
7. **Tests** in `articles/unit_test.go`:
   - Rename then GET by the old slug returns 200 with the new canonical slug.
   - Rename twice (A→B→C): A and B both resolve.
   - Rename back (C→A) leaves no stale alias.
   - A new article titled like a retired slug gets a suffixed slug.
   - A non-author PUT via an old slug returns 403.
   - A deleted article's old slug returns 404.
   - A rename with no title change creates no alias.
8. **Docs and API specs.** Update the README to note that old slugs resolve. Re-run the hurl and bruno spec suites from #57 to confirm they still pass.

## Verification
Run `go build ./...`, `go test ./...` and `golangci-lint run`, then the hurl and bruno suites. Finish with a manual check using `go run hello.go`: create an article, rename it, and GET the old slug.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Alias collides with a live slug | `makeUniqueSlug` only checks `articles`, so a new article can take a retired slug and steal the old links | Make slug uniqueness checks cover aliases, and test it |
| 2 | Slug update and alias insert not atomic | `Update` runs outside a transaction, so a crash can lose the old slug | Wrap both in one `db.Transaction` |
| 3 | Rename back to a retired slug | The slug ends up both current and aliased, or gets a needless `-2` | Delete the article's own alias and ignore its own aliases when checking uniqueness |
| 4 | Concurrent renames or creates race | The existing retry only handles `ErrDuplicatedKey` on `articles` | Unique index on alias slug, and retry on both tables |
| 5 | Old slug accepted on write routes | A write via a stale slug (for example DELETE) may surprise clients | Resolve aliases on every `:slug` route, and keep the author check after resolution |
| 6 | Existing rows have no history | Links shared before this change stay broken, because the old slugs weren't recorded | State this limitation, since it can't be backfilled |
| 7 | Unbounded alias growth | Repeated renames add one row each | Cap or dedupe aliases per article if abuse appears |
| 8 | Breaks the RealWorld spec tests | The hurl and bruno suites may expect 404 for an old slug after a rename | Run both suites and adjust any such assertions deliberately |
| 9 | Soft-delete semantics | Aliases of a deleted article still occupy the unique index, as soft-deleted slugs do today | Keep aliases unscoped in uniqueness checks, and return 404 on read |

Riskiest: #1, a retired slug being reissued to another article, because it silently redirects shared links to the wrong content.
