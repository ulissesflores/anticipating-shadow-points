**Steps**
1. **Change the defaults.**
   - In `sessions.py`, set `same_site` to `"strict"` and `https_only` to `True`.
   - The flag-building logic at lines 34-36 needs no change, because `https_only` already appends `; secure`.
2. **Fix the existing tests.**
   - `tests/middleware/test_session.py` and `tests/middleware/test_middleware.py:42` use the default `SessionMiddleware(secret_key=...)`.
   - `TestClient` defaults to `http://testserver`, and httpx won't send a Secure cookie back over http. So session round-trips (set, read, clear) will fail.
   - Either pass `https_only=False` in those tests, or build the client with `base_url="https://testserver"`.
   - The latter is better for the default-path tests, because it exercises the real defaults.
3. **Add tests for the new defaults.**

   - Also cover the clear-session cookie path, which reuses `security_flags`.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Sessions silently stop working on plain HTTP | Browsers drop Secure cookies on http. `localhost` is exempt in some browsers but not all, and not in `httpx`. | Document `https_only=False` for dev, and add a release-note migration. |
| 2 | Existing tests fail | `TestClient` uses `http://testserver`, so the cookie isn't resent. | Use an https `base_url`, or pass opt-outs. |
| 3 | Breaking change for all downstream users | Starlette's default changes under FastAPI and other frameworks that depend on it. | Call it out as breaking, bump the version, and consider a deprecation warning first. |
| 4 | Strict breaks cross-site login flows | OAuth/OIDC redirects back to the app won't send a Strict cookie, so state or session is lost at the callback. | Document `same_site="lax"` for OAuth callbacks. |
| 5 | Strict breaks inbound links | A first-page load from an external link arrives without the session, so users look logged out. | Document the trade-off and the `lax` opt-out. |
| 6 | TLS-terminating proxies | Behind a proxy the app sees http, but the browser sees https. | Starlette only sets the flag and doesn't check the scheme, so this is fine. Note it in the docs. |
| 7 | Websocket sessions | `SessionMiddleware` also covers websockets, and `ws://` clients may not send Secure cookies. | Test the websocket path, and document it. |
| 8 | Docs and AGENTS.md convention | New headings must have text before code. | Review the docs diff against that rule. |

Riskiest: #3. It's a silent, ecosystem-wide breaking default, and sessions on plain-HTTP deployments will fail with no error.
