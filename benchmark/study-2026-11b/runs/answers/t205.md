## What exists today
`PUT /api/articles/:slug` already lets the author change the title and regenerates the slug (`articles/routers.go:151-160`). But the old slug is overwritten, so any link shared before the edit now returns 404. What's missing is a way for old slugs to keep pointing at the article.

## Assumptions
- **Old slugs work silently.** They return 200 with the article, and the response's `slug` field is the current one. I chose this over an HTTP 301 redirect because redirects on PUT/DELETE/POST are fragile with auth headers and CORS. The frontend can switch the address bar to the current slug itself.
- **Old slugs are reserved forever.** A new article whose title produces a retired slug gets a `-N` suffix, the same way soft-deleted slugs are already handled in `makeUniqueSlug`.
- **Deleting an article kills its old slugs too.** They return 404 but stay reserved.
- **The title is the only way to change the slug.** Editing the slug directly is out of scope.

## Plan
1. **New table** (`articles/models.go`): `ArticleSlugAlias{gorm.Model; Slug uniqueIndex; ArticleID index}`, one row per retired slug.
2. **`FindArticleBySlug(slug)`**: look up the current slug first, then fall back to the alias table. The current slug always takes precedence, which makes concurrent create/rename races harmless.
3. **`makeUniqueSlug`** (`models.go:299`): treat a slug as taken if it's in the articles table or the alias table (including soft-deleted rows in both).
4. **`Rename(updates, oldSlug)`**: the title/slug update and the alias insert happen in one transaction. If the author renames back to an earlier title, the matching alias row is deleted first. It returns `gorm.ErrDuplicatedKey` unchanged so the existing retry loop still works.
5. **Handlers** (`articles/routers.go`): all 8 routes that take a slug from the URL switch from `FindOneArticle(&ArticleModel{Slug: slug})` to `FindArticleBySlug`. Three fixes come with that, because the URL may now be an old slug:
   - `ArticleUpdate` compares the new slug against the article's stored slug, not the URL.
   - `ArticleUpdate` re-fetches the article by its current slug.
   - `ArticleDelete` deletes by the article's ID. It currently deletes by the URL slug, which would delete nothing when an old slug is used.
6. **Delete**: soft-delete the article's alias rows in the same transaction.
7. **Migrations**: add `AutoMigrate(&ArticleSlugAlias{})` in `hello.go` and in both setup spots in `articles/unit_test.go` (`TestMain` and the reset helper around line 339). No backfill is possible, since past renames left no record.
8. **Tests to add**:
   - Old slug still resolves after a rename.
   - After chained renames A→B→C, both A and B resolve.
   - Renaming back to A works.
   - A new article with an old title gets `-2`.
   - PUT, DELETE, favorite and comments work through an old slug, and non-authors still get 403.
   - After delete, every slug returns 404 and stays reserved.
   - A title change that produces the same slug creates no alias row.
9. **Verify**: `go test ./...`, `golangci-lint run`, then `scripts/run-spec-tests.sh hurl` and `bruno`.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Old slug given to a different article | `makeUniqueSlug` only checks `article_models` today | Also check the alias table (incl. soft-deleted rows); current slug wins on lookup |
| 2 | Write handlers act on nothing or the wrong row via an old slug | `ArticleDelete` deletes by URL slug; `ArticleUpdate` re-fetches by `finalSlug` | Act on the resolved ID and stored slug; test every route through an old slug |
| 3 | Article renamed but no alias saved | Update and alias insert are separate writes | One `db.Transaction` for both |
| 4 | Retry loop stops catching slug collisions | Retry depends on `errors.Is(err, gorm.ErrDuplicatedKey)` | Return the tx error unwrapped; test concurrent renames |
| 5 | Renaming back to an earlier title fails | The alias row still holds that slug | Delete this article's matching alias row inside the tx |
| 6 | Spec suite expects 404 on the old slug | The pinned hurl/bruno specs may check rename behavior | Run both suites; if one asserts 404, raise it with the spec maintainers |
| 7 | New table missing in some environment | Three separate AutoMigrate lists (`hello.go` + 2 in tests) | Add to all three; a test fails fast if it's missing |
| 8 | Extra query on every miss | Unknown slugs now hit two tables | Unique index on `alias.slug`; the fallback runs only on a miss |
| 9 | Duplicate content / stale cached URLs | Old slugs return 200, not a redirect | Optional `Link: rel=canonical` header; frontend uses `replaceState` |
| 10 | Links already broken stay broken | No record of past renames exists | Accept and document; no backfill is possible |

Riskiest: #1. If a retired slug is reused, an old shared link quietly opens a different author's article, which is worse than a 404.
