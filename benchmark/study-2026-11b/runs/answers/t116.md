# Plan: let users download all their data as one file

I didn't write the plan file, because you asked me not to edit any files. The whole plan is below.

## Context
This is Flasky (the Flask Web Development book app): Flask 0.12, SQLAlchemy 1.1, Python. Each user has three kinds of data in `app/models.py`:
- **Profile fields on `User`:** `email`, `username`, `name`, `location`, `about_me`, `member_since`, `last_seen`, `confirmed`, `role`.
- **`Post` rows:** linked through `User.posts`.
- **`Comment` rows:** linked through `User.comments`. A comment can sit on anyone's post and can be `disabled` by a moderator.

The app has no export feature today. The goal is a "Download my data" button that returns a single file holding all three.

## Ways this could go wrong (before planning)
1. **Someone else's data leaks (IDOR).** A route like `/export/<username>` or `/export/<id>` would let anyone download another user's data, including their email.
2. **Secrets end up in the file.** Dumping every `User` column would include `password_hash` and `avatar_hash`.
3. **Other people's content gets in.** Exporting "comments" by walking `post.comments` would pull in what other users wrote on your posts. Exporting a comment's parent post would copy text you didn't write.
4. **Unconfirmed users get locked out.** `auth.before_app_request` (`app/auth/views.py:12`) sends unconfirmed users away from every non-`auth` endpoint, so "every user" quietly becomes "confirmed users only".
5. **Dates don't serialize.** `json.dumps` fails on `datetime`, and `jsonify` in Flask 0.12 turns dates into RFC-1123 strings, which are lossy and hard for tools to read.
6. **Shared caches keep the file.** Without `Cache-Control: no-store`, a proxy or the browser cache could hold onto personal data.
7. **Big accounts cause trouble.** Building everything in memory means heavy users could hit Gunicorn/Heroku timeouts (30 s on Heroku).
8. **Content gets dropped.** If the export copies the UI's filtering, moderated (`disabled`) comments disappear even though they are still the user's data.
9. **Nothing tests it.** Without tests it's easy to regress later, for example when someone adds a column to `User`.
10. **The download filename breaks.** Usernames go straight into `Content-Disposition`, so header-unsafe characters could break the download.

## Assumptions (non-interactive run)
- **Format:** one JSON file, `flasky-<username>-<YYYYMMDD>.json`. It's a single file, can be read by machines, and needs no new dependency (ZIP or CSV would need several files or more code).
- **Who gets what:** only the logged-in user can export, and only their own data. The URL takes no user identifier. Admins don't get a "download someone else's data" option.
- **Included:**
  - Profile: username, email, name, location, about_me, member_since, last_seen, confirmed, role name.
  - Every post: id, body (Markdown), body_html, timestamp.
  - Every comment: id, body, body_html, timestamp, `disabled`, and the `post_id` plus URL of the parent post. The parent post's text is not copied.
- **Excluded:** `password_hash`, `avatar_hash`, other users' comments, and follower/following lists. The request didn't ask for follower/following lists, but they're easy to add later as usernames only.
- **Unconfirmed users** can export. The route lives in the `auth` blueprint, which the confirmation gate already skips.
- Doing it in memory is fine for this app's scale. Streaming is listed as a mitigation in case it's needed later.

## Implementation
1. **`app/models.py`:** add `User.export_data()`, which returns a plain dict built from an explicit allowlist of fields.
   - Posts come from `self.posts.order_by(Post.timestamp)`.
   - Comments come from `self.comments.order_by(Comment.timestamp)`.
   - Dates are written as `.isoformat() + 'Z'` (they're stored as UTC).
   - Add an `export_version: 1` key and a `generated_at` timestamp.
   - Don't reuse `to_json()`. It returns API URLs and counts, not the content itself.
2. **`app/auth/views.py`:** add `GET /auth/export`, protected by `@login_required`.
   - Return `Response(json.dumps(current_user.export_data(), ensure_ascii=False, indent=2), mimetype='application/json')`.
   - Set the `Content-Disposition: attachment; filename="flasky-<id>-<date>.json"` header. Use the numeric id rather than the username, which avoids problem 10.
   - Set `Cache-Control: no-store`.
   - A GET request has no side effects, and other sites can't read the response because of the browser's same-origin policy, so no CSRF token is needed.
3. **`app/templates/user.html`:** next to "Edit Profile", inside the existing `{% if user == current_user %}` block, add `<a class="btn btn-default" href="{{ url_for('auth.export') }}">Download my data</a>`. Optionally add the same link to the account dropdown in `base.html`.
4. **`tests/test_client.py`:** add tests that:
   - register and confirm a user, create a post, and add a comment by that user on someone else's post;
   - call `GET /auth/export` and check the status, `attachment` disposition, `application/json` type, and `no-store` header;
   - check the JSON contains the user's own post and comment;
   - check it contains no `password` or `password_hash`, and nothing from the other user's posts or comments;
   - check that an anonymous request is redirected to login;
   - check that an unconfirmed user gets a 200.
5. **`tests/test_user_model.py`:** add a unit test asserting that the key set of `export_data()['profile']` exactly equals the allowlist. That way a new sensitive column can't slip into the export unnoticed.

## Verification
- Run `flask test` (or `python -m unittest discover tests`).
- Run `flask run`, log in as a user seeded with `app/fake.py`, and click **Download my data**. Open the file and confirm it contains the posts and comments and no password hash.
- Log in as a second user and confirm there is no way to get the first user's file.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Another user's data leaks (IDOR) | Existing routes take `<username>` or `<id>`, so it's tempting to copy that pattern | No identifier in the URL; always use `current_user`; add a test |
| 2 | Password hash in the file | `User` has `password_hash` and `avatar_hash` next to profile fields | Explicit allowlist plus a test on the exact key set |
| 3 | Other users' text included | `post.comments` holds comments by everyone | Query only `User.comments` and give parent posts by id/URL only |
| 4 | Unconfirmed users blocked | `auth.before_app_request` redirects them away from non-`auth` endpoints | Put the route in the `auth` blueprint and test it |
| 5 | Dates fail or lose precision | `json.dumps` can't encode datetime; Flask 0.12 `jsonify` writes RFC-1123 | ISO-8601 UTC strings written explicitly |
| 6 | File cached by proxy or browser | Production sits behind Heroku/Docker proxies | `Cache-Control: no-store` |
| 7 | Timeout on large accounts | Whole export built in memory under Gunicorn's 30 s limit | Fine at this scale; switch to a streaming generator with `yield_per` if needed |
| 8 | Moderated comments silently missing | UI hides `disabled` comments | Include them, with a `disabled` flag |
| 9 | Download filename breaks | Usernames are user-controlled | Use the numeric id and date in the filename |
| 10 | Export goes stale as the schema grows | New columns are skipped quietly, or leak quietly | `export_version` key and the allowlist test |

Riskiest: #1 (IDOR), where one wrong route pattern lets anyone download any user's email, posts and comments.
