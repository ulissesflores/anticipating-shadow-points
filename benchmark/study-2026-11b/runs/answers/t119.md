# Plan: moderator comment hiding and author appeals (7 days)

I didn't edit any file, including the plan file, because you said not to. The plan is from reading the code in `app/Comment.php`, `CommentController.php`, `DeleteComment.php`, `CommentTransformer.php`, `routes/api.php`, the users and comments migrations, and `AuthServiceProvider`.

## What the code does today
- **Moderators:** `users` has no role or admin flag, and there are no policies. Authorization is done inside FormRequests, for example `DeleteComment::authorize()` checks `comment->user_id == auth()->id()`.
- **Comments:** `comments` has only `body`, `user_id` and `article_id`. `Comment` has no soft delete and no status. `CommentController@index` returns every comment, and `CommentTransformer` always exposes `body`.
- **Routes:** comments are a `Route::resource` with `index`, `store` and `destroy`, behind the `auth.api` JWT middleware.
- **Conventions to reuse:** the `ApiRequest` subclasses for validation and authorization, `Transformer`, and `respondSuccess()`/`respondWithTransformer()`.

## Assumptions
1. "Moderator" means a new role. I'll add `users.is_moderator` (boolean, default false) instead of a roles table. It is granted by seeder or tinker, with no API to self-promote.
2. "Hide" is reversible and non-destructive. The row is kept and the public API stops showing its body.
3. A hidden comment stays in `index` as a placeholder (`hidden: true`, body `null`). Threads stay intact and the author still sees it. Moderators and the author get the original body.
4. The appeal window is 7 days from the time of hiding, not from the time of posting.
5. One appeal per hide event, with a free-text reason. A moderator then upholds the hide or restores the comment.
6. Only the comment's author can appeal. Moderators can't hide their own comments, to avoid self-review.
7. Notifications such as email are out of scope. The author sees the status in the API.

## Implementation steps
1. **Migrations (new files only)**
   - Add `is_moderator` to `users`.
   - Add `hidden_at`, `hidden_by` (FK to `users`, null on delete), `hidden_reason`, `appeal_body`, `appealed_at`, `appeal_resolved_at` and `appeal_outcome` to `comments`. This is simple and fits the one-appeal rule. If appeal history is needed, use a `comment_moderation_events` table instead.
   - Add an index on `hidden_at`.
2. **Models**
   - `Comment`: add the casts for the new columns, `isHidden()`, `appealDeadline()` (`hidden_at + 7 days`), `canBeAppealed()`, and a `visibleTo($user)` helper.
   - `User`: add the `is_moderator` cast and `isModerator()`.
3. **Requests** in `app/Http/Requests/Api/`
   - `HideComment`: allowed only for moderators, and not on their own comment.
   - `AppealComment`: allowed only for the author, only while the comment is hidden, within 7 days, and only if no appeal exists yet. Validates `appeal.body`.
   - `ResolveAppeal`: allowed only for moderators. Validates `outcome` (restore or uphold).
4. **Routes and controller**
   - `POST articles/{article}/comments/{comment}/hide` and `DELETE .../hide` (unhide).
   - `POST .../appeal`, and `PUT .../appeal` to resolve.
   - Add the actions to `CommentController`. Move the 7-day logic into one place so the request and the transformer share it.
5. **Transformer and index**
   - `CommentTransformer` reads the viewer, and a moderator sees everything.
     - Other viewers get `body: null`, `hidden: true`.
     - The author also gets `hiddenReason`, `appealDeadline` and `appealStatus`.
   - `index` runs with optional auth, so anonymous viewers must get the redacted form.
   - Also check `ArticleTransformer` and any other path that serializes comments.
6. **Tests** in `tests/Feature/Api`
   - Hide and unhide permissions.
   - Appeal on day 6 and 23:59 versus day 7 and 1 second (use `Carbon::setTestNow`).
   - A second appeal is rejected.
   - An appeal by a non-author is rejected.
   - A hidden body never appears for anonymous or other users.
   - The author can still delete their own comment.
   - Resolving an appeal restores the body.
7. **Docs:** add the new endpoints and fields to `readme.md`.

## Verification
Run `php artisan migrate`, then `vendor/bin/phpunit`. After that, run a manual curl pass with three JWTs (moderator, author, stranger). Confirm the stranger's and anonymous responses never contain the hidden body, including through `GET articles/{slug}/comments`.

## Risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden body leaks | Comments are serialized by one transformer, `index` allows anonymous users, and `$with` eager-loads | Redact in one place (the transformer) and add leak tests for every viewer type |
| 2 | Moderator role escalation | No roles or policies exist, and `User::$fillable` may allow mass assignment | Keep `is_moderator` out of `$fillable` and the register/update requests, and grant it only by seeder |
| 3 | Wrong 7-day window | The deadline could be measured from the wrong timestamp, or have timezone and boundary bugs | Define it as `hidden_at + 7d` in UTC, and test with a frozen clock at the boundary |
| 4 | Re-hide resets the window | Unhide then re-hide could give the author fresh appeals or deny them one | Store one appeal per hide event and clear the appeal fields on a new hide |
| 5 | Moderator abuse or no audit trail | Moderators have unchecked power and nothing is logged | Record `hidden_by` and the reason, and forbid self-hiding. Consider an events table |
| 6 | Old API clients break | The RealWorld spec expects `body` as a string, so `null` may break frontends | Document the change, and consider a placeholder string plus the `hidden` flag |
| 7 | Migration on a live table | New columns on `comments` run against production data | Make all columns nullable and additive, with no backfill, so rollback is trivial |
| 8 | Author-delete bypass | The author can delete a hidden comment and so remove the appeal subject | Block deletion during an open appeal, or keep an audit copy |
| 9 | Missing validation order | `authorize()` runs before the comment-state checks, which can give wrong 403/422 codes | Test status codes explicitly in the Request classes |

Riskiest: #1, hidden comment bodies leaking through the unauthenticated or shared serialization path.
