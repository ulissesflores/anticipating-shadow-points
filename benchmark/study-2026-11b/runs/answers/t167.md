## What the code looks like now

This is the RealWorld (Conduit) API on Laravel 5.5, using JWT auth through the `auth.api` middleware.

- **No roles.** The `users` table has no role or moderator column, and `AuthServiceProvider` defines no gates or policies.
- **Comment permissions live in form requests.** `app/Http/Requests/Api/DeleteComment.php:15` checks only `$comment->user_id == auth()->id()`.
- **Comment routes.** `CommentController` exposes `index`, `store` and `destroy` under `articles/{article}/comments`. `index` uses `auth.api:optional`, so anonymous users can read comments.
- **One query feeds the list.** `Article::comments()` (`app/Article.php:74`) is the single relation behind `index`.
- **Response shape.** `CommentTransformer` decides what clients see. It returns `id`, `body`, timestamps and `author`.
- **Existing gap.** `destroy` never checks that `{comment}` belongs to `{article}`, and the new routes would inherit that.
- **Tests.** Feature tests are in `tests/Feature/Api/CommentTest.php`, and `TestCase` creates two users per test.

## Ways this could go wrong (before planning)

1. **Hidden comments still leak.** `index`, the JSON returned by `store`, or a future "show" endpoint could still return the body if the filter isn't applied everywhere.
2. **Anyone can make themselves a moderator.** If `is_moderator` is added to `User::$fillable`, a user can set it on themselves through `PUT /user` (`UpdateUser`).
3. **The 7-day window is checked wrongly.** It could be measured from the wrong timestamp, use mismatched timezones, be enforced only in the UI, or be off at the boundary (`<` vs `<=`).
4. **Appeals can be spammed.** Without a uniqueness rule, an author can appeal many times or re-appeal after a rejection.
5. **The wrong people can act.** Someone other than the author appeals, or a moderator rules on an appeal about their own comment or their own hide.
6. **Hide and delete get mixed up.** Hiding must not delete, and an author deleting a hidden comment during an appeal raises a policy question.
7. **Route scoping is missing.** Moderation endpoints copied from `destroy` would accept an ID pair where the comment isn't on that article.
8. **The API contract changes.** New transformer fields such as `hidden` could break RealWorld spec clients.
9. **There is no record of who did what.** Without storing who hid the comment, when, and why, appeals can't be reviewed fairly.
10. **Migrations break existing data.** New columns must be nullable or have defaults so existing comments stay visible, and `down()` must reverse them.

## Assumptions (non-interactive)

- A moderator is a site-wide boolean flag on `users`, set only by seeder or DB/console, never through the API.
- "Hide" is a soft state, not a delete. Other users stop seeing the comment. The author and moderators still see it, flagged as hidden.
- An appeal is valid only within 7 days of `hidden_at`. Only the comment author can file it, and only once per hide.
- A moderator decides the appeal. Upholding keeps the comment hidden; overturning unhides it. Either way the appeal is closed.
- Moderators can't decide appeals on hides they made themselves, if another moderator exists.
- Non-moderators keep the current response shape. Moderation fields appear only for the author and for moderators.

## Plan

1. **Migrations**
   - `users.is_moderator` (boolean, default false, not fillable).
   - On `comments`: `hidden_at` (nullable timestamp), `hidden_by` (nullable FK to users, null on delete) and `hidden_reason` (nullable).
   - A new `comment_appeals` table: `comment_id`, `user_id`, `reason`, `status` (pending, upheld or overturned), `decided_by`, `decided_at`, timestamps. It gets a unique index on `(comment_id, hidden_at_snapshot)` or a check in the app for one pending or decided appeal per hide.
2. **Models**
   - `Comment`: a `scopeVisibleTo(?User)`, `isHidden()`, and an `appeals()` relation.
   - New `CommentAppeal` model.
   - `User::isModerator()`.
3. **Read filtering**
   - `CommentController@index` uses `$article->comments()->visibleTo(auth()->user())`.
   - Non-moderators never see other users' hidden comments.
4. **Authorization**
   - Add a `CommentPolicy` (`hide`, `unhide`, `appeal`, `decideAppeal`) in `AuthServiceProvider`.
   - Or add form requests in the existing style (`HideComment`, `AppealComment`, `DecideAppeal`), each checking that the comment belongs to the article.
5. **Routes** (all under `auth.api`)
   - `POST`/`DELETE articles/{article}/comments/{comment}/hide`
   - `POST .../comments/{comment}/appeal`
   - `POST appeals/{appeal}/decision` (moderators only)
   - `GET appeals?status=pending` (moderators only)
6. **Rules**
   - An appeal is allowed only if the comment is hidden, the caller is the author, `now() <= hidden_at + 7 days` (UTC), and there is no existing appeal for this hide.
   - The decision runs in a transaction, and unhiding clears the `hidden_*` columns.
7. **Transformer**
   - Add `hidden` and `appeal` info only when the viewer is the author or a moderator.
8. **Tests** (extend `CommentTest`, plus a new `CommentModerationTest`)
   - Moderators can hide; normal users can't hide others' comments.
   - Hidden comments disappear for anonymous users and other users, but stay visible to the author and moderators.
   - An appeal on day 6 works; one on day 8 is rejected (use `Carbon::setTestNow`).
   - A second appeal is rejected.
   - Users other than the author can't appeal.
   - Overturning an appeal brings the comment back.
   - Calls where the article and comment don't match return 404 or 403.
   - `PUT /user` with `is_moderator` is ignored.

**Verification:** run `vendor/bin/phpunit` against `realworld_test`, then try it by hand with curl: a seeded moderator hides a comment, the author appeals, the moderator decides.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Hidden comment still visible | `index` and the transformer don't filter at all today | Single `visibleTo` scope, plus tests for anonymous and other users |
| 2 | Users make themselves moderators | `UpdateUser` mass-assigns `User::$fillable` | Keep `is_moderator` out of fillable; add a test |
| 3 | 7-day window wrong | Laravel time handling and timezone config are easy to misuse | Compare against `hidden_at` in UTC; boundary tests with `setTestNow` |
| 4 | Appeal spam or re-appeals | No uniqueness exists | One appeal per hide, enforced in the DB and the app |
| 5 | Wrong actor appeals or decides | Only an owner check exists now | Policy checks for author-only appeals and no self-review |
| 6 | Article and comment not matched | `destroy` already skips this check | Assert `comment->article_id == article->id` |
| 7 | Hide treated like delete | Only delete exists today | Separate columns; delete flow unchanged |
| 8 | Spec clients break | RealWorld comment shape is fixed | Extra fields only for author and moderators |
| 9 | No audit trail | No moderation history exists | Store `hidden_by`, reason, decider, timestamps |
| 10 | Migration affects existing rows | Old comments have no moderation state | Nullable columns with defaults; reversible `down()` |

Riskiest: #1, hidden comments still showing through an unfiltered read path, because nothing filters comments today.
