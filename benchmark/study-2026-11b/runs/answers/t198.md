## What's there now
A visit (`owner/Visit.java`) records only a date and a description. It has no vet and no time, so "same vet at the same time" can't be expressed yet. The booking form at `/owners/{o}/pets/{p}/visits/new` is already public. The repo already solved a similar race for duplicate pet names in `PetController.processCreationForm`: a database UNIQUE constraint, `saveAndFlush`, and catching `DataIntegrityViolationException` by constraint name, tested in `PetClinicConcurrencyTests`. I'll reuse that pattern.

## Assumptions
- **Online booking:** "online" means the existing web form. There is no Spring Security, so adding owner login is out of scope.
- **Slots:** fixed 30-minute slots, 09:00–16:30, weekdays only, one slot per visit. Because every visit starts on the slot grid, "same time" means the same start time, and a plain UNIQUE constraint is enough.
- **Old visits:** existing and seed visits keep vet and time empty (NULL). All three databases allow repeated NULLs under UNIQUE.
- **Out of scope:** cancelling or rescheduling, and time zones. The server's local time is used, as the code does today.

## Plan
1. **Schema** for H2, MySQL and Postgres:
   - Add a `vet_id` column (pointing at `vets`) and a `visit_time` column to `visits`.
   - Add `CONSTRAINT uq_visits_vet_slot UNIQUE (vet_id, visit_date, visit_time)`, explicitly named on every database.
   - Fix the positional `INSERT INTO visits VALUES` lines in the `data.sql` files.
   - Ship a `migrate-visit-booking.sql` script for MySQL and Postgres. The current setup only runs `CREATE TABLE IF NOT EXISTS`, so existing databases would never get the new columns.
2. **Domain:** add a required `Vet vet` (`@ManyToOne`) and a required `LocalTime time` to `Visit`, plus a small slot helper (`isValidSlot`) to check weekday, grid and opening hours.
3. **Persistence:**
   - Add `VetRepository.findById`.
   - Add a new `VisitRepository` with `existsByVetIdAndDateAndTime` and a "taken slots for a vet on a date" query.
4. **Web:**
   - Add a `VetFormatter` (modelled on `PetTypeFormatter`) so the form binds `vet` from an id. The controller's `@InitBinder` blocks `*.id`, so binding `vet.id` directly would be silently dropped.
   - In `VisitController`: check the slot is valid → pre-check whether it's taken → `saveAndFlush` → catch the exception that names `uq_visits_vet_slot` and show "slot taken" on the form. Any other database error is rethrown.
   - Add vet and time pickers to the form, and show vet and time in the visit lists.
   - Add the new message keys to all 11 locale files, which `I18nPropertiesSyncTest` enforces.
   - Optional: a JSON endpoint listing free slots, so the form can grey out taken ones.
5. **Tests:**
   - `VisitControllerTests` cases: success, missing vet or time, invalid slot, slot taken at the pre-check, slot taken at save, and other errors rethrown.
   - A new double-booking test in `PetClinicConcurrencyTests`: two pets post the same vet and slot at once → exactly one row is saved. The same slot with different vets → both succeed.
   - Run the Testcontainers MySQL and Postgres integration tests, then `./mvnw verify`.

## Main risks

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Existing MySQL/Postgres databases never get the new columns | Setup only runs `CREATE TABLE IF NOT EXISTS` and there's no migration tool, so the app breaks on deploy | Ship a migration script and document it; consider Flyway |
| 2 | "Slot taken" detection misfires on some databases | The handler matches the constraint name in the error message; MySQL's existing UNIQUE is unnamed | Name the constraint on every database; run the MySQL and Postgres integration tests |
| 3 | Race between the pre-check and the insert | The pre-check alone allows double booking | Rely on the database constraint plus `saveAndFlush` and catching the exception; add a concurrency test |
| 4 | Vet choice silently ignored | `@InitBinder` blocks `*.id` | Bind with `VetFormatter` on the `vet` field; test it |
| 5 | Positional seed inserts break | `INSERT INTO visits VALUES (...)` without column names | Use explicit column lists in all three `data.sql` files |
| 6 | Anyone can book for any owner | The app has no authentication | Accept for now; flag it for a follow-up on auth |
| 7 | Overlaps if visit lengths ever vary | UNIQUE only catches the same start time | Enforce the slot grid on the server; vary lengths later via a Postgres exclusion constraint |
| 8 | Old visits have no vet or time | Columns must allow NULL | Templates must handle NULL; require vet and time only on new bookings |
| 9 | Build fails on i18n | 11 locale files must have the same keys | Add every key to every locale file |

Riskiest: #1 — existing MySQL/Postgres databases won't get the new columns, so the app fails on deploy unless the migration script is run.
