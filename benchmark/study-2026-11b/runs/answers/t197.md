I've written the plan to `claude-home/plans/let-every-user-download-merry-noodle.md`. No repo files were changed.

**Assumptions** (non-interactive run):
- **Format:** the export is one JSON file, built during the request. There's no ZIP, no background job and no email.
- **Who can export:** users can only export their own account; admins get nothing new.
- **What's included:** profile, posts and comments. Comments hidden by moderators are included and marked as hidden. Follows, role internals and the password hash are left out.
- **No migration and no new dependency.**

**Plan**
1. **`app/models.py`**: add `User.to_export_dict()`.
   - It returns a fixed list of profile fields: username, email, name, location, about_me, member_since, last_seen, confirmed and role name. It never includes the password hash.
   - It adds every post (`self.posts`) and every comment (`self.comments`), sorted by time. Each item includes `body` (the original Markdown) and `body_html`; comments also carry `post_id` and `disabled`.
   - It adds `export_version` and `exported_at` at the top.
   - Dates are written in ISO-8601 UTC form and links are absolute. The existing `to_json()` won't do here: its links are relative API paths and `jsonify` writes dates in the RFC-822 format.
2. **`app/main/views.py`**: new `GET /export` route with `@login_required`.
   - It serialises with `json.dumps(..., ensure_ascii=False, indent=2)` and builds the response with `make_response`.
   - Headers: `Content-Disposition: attachment; filename="flasky-export-<username>-<date>.json"` and `Cache-Control: no-store`.
   - The existing check in `app/auth/views.py:12` still sends unconfirmed users to the unconfirmed page. I'm keeping that.
3. **`app/templates/user.html`**: add a "Download my data" button next to "Edit Profile", shown only when you're viewing your own profile (`user == current_user`).
4. **Optional later:** `/api/v1/users/me/export` for API clients.

**Tests** (`tests/test_client.py`):
- A logged-out visitor is redirected to login.
- A confirmed user gets a 200 with the download header, and the JSON parses.
- The file has the right post and comment counts, including a hidden comment.
- `password_hash` is absent and non-ASCII text survives.
- User A's file contains none of user B's data.
- An unconfirmed user is redirected.

**Verification:** run `flask test`, then click the button in `flask run`. Also generate a heavy user with `app/fake.py` and time the export.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Exporting another user's data | Routes elsewhere take `<username>`/`<id>` | No URL parameter; use only `current_user`; test that A's file has none of B's data |
| 2 | Leaking sensitive fields | `User` has `password_hash` and email | Fixed list of exported fields; test that the hash is absent |
| 3 | Slow or memory-heavy export for big accounts | Built synchronously; `fake.py` can make thousands of posts | Two queries with no per-item lookups; measure, and stream or move to a background job if needed |
| 4 | Dates not valid JSON or ambiguous | `datetime` objects can't go into `json.dumps` directly, and stored times are naive UTC | Write explicit ISO strings with a `Z` suffix |
| 5 | Hidden comments surprise users or moderators | Moderation sets `disabled` | Include them with a `disabled` flag; document it |
| 6 | Unconfirmed users can't export | The confirmation check catches every non-auth page | Accept it for now (they have little data), or exempt this route |
| 7 | Browser or proxy caches personal data | It's a normal GET response | `Cache-Control: no-store` |
| 8 | Characters broken in the file or filename | Usernames and posts may be non-ASCII | `ensure_ascii=False` + UTF-8 charset; keep the filename ASCII-safe |
| 9 | Format drifts and breaks importers | No schema exists yet | `export_version` field plus a test of the file's structure |

Riskiest: #1, an export that returns another user's data, because it would leak private data.
