Here's the plan. Changing the title already changes the slug today. What's missing is a way to keep the old slug working after that.

## What the code does now
- `ArticleUpdate` (`articles/routers.go:152-183`) builds a new slug from the new title and writes it over the old one. After that, `GET /api/articles/<old-slug>` returns 404.
- `makeUniqueSlug` (`articles/models.go:299`) adds `-2`, `-3`, … when a slug is taken. Its check includes soft-deleted articles.
- There's an existing bug: change the title of an article whose slug is `foo-2` and the slug becomes `foo-3`, even when the title still produces `foo`. That's because the code compares the new base slug with the article's own suffixed slug.
- `ArticleDelete` deletes by the slug from the URL rather than by the article's ID.

## Assumptions
- The links that matter are API paths (`/api/articles/:slug`). This repo has no HTML frontend.
- Old slugs never expire.
- The slug still always comes from the title; authors don't get a separate slug field.
- Old slugs resolve directly with a 200 response, and the body carries the current slug. I'm not using a 301 redirect, because it would break PUT, POST and DELETE requests from API clients.

## Plan
1. **New table.** Add `ArticleSlugAliasModel{gorm.Model; Slug uniqueIndex; ArticleID index}`. Add it to `AutoMigrate` in `hello.go` and in the test setup (`articles/unit_test.go` ~L340).
2. **One lookup function.** `FindArticleBySlug(slug)` checks the article's current slug first and falls back to the alias table. A current slug always wins over an alias.
3. **Use it in every `:slug` handler.** That's retrieve, update, delete, favorite/unfavorite, and comment list/create/delete. The author check stays tied to the article ID, so using an old slug can't get around it.
4. **Renaming.** Do these in one transaction:
   - Store the old slug as an alias.
   - Delete this article's own alias if it equals the new slug (so renaming A → B → A works).
   - Apply the update.
   
   Keep the existing retry on `ErrDuplicatedKey`, and re-load the article by ID afterwards.
5. **Reserve old slugs.** `makeUniqueSlug` also checks the alias table, so a new article can't take a slug that someone already shared. The article's own current slug and aliases count as free, which also fixes the `foo-2` → `foo-3` bug.
6. **Deleting.** Delete by ID, and soft-delete the article's aliases in the same transaction. The old slugs stay reserved, the same way soft-deleted articles keep theirs.
7. **No backfill.** The table starts empty, so existing data needs no migration.

## Verification
New tests:
- After a title change, the old slug returns 200 with the new slug.
- Rename A → B → A works.
- A new article with an old title gets `-2` instead of taking over the alias.
- Comment and favorite through an old slug work.
- A non-author using an old slug gets 403.
- Deleting through an old slug works, and the old slug then returns 404.

Then run `go test ./...`, `golangci-lint run` and `bash scripts/run-spec-tests.sh hurl` to confirm the spec suite still passes.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Old link points to a different article | `makeUniqueSlug` only checks `articles`, so a new article with the old title would take the freed slug | Check the alias table in `makeUniqueSlug`; current slug wins over aliases |
| 2 | A handler misses the fallback | 8 handlers each call `FindOneArticle(&ArticleModel{Slug: …})` | Route all of them through `FindArticleBySlug`; test each endpoint with an old slug |
| 3 | Delete via old slug hits nothing | `DeleteArticleModel(&ArticleModel{Slug: slug})` uses the URL slug | Delete by ID |
| 4 | Rename back to an earlier title fails | The old slug sits in the unique alias index | Remove the article's own alias in the same transaction |
| 5 | Two renames at once collide | `makeUniqueSlug` checks and then writes with no lock | Use a transaction, keep the `ErrDuplicatedKey` retry, cover both tables |
| 6 | Slugs churn on small title edits | Comparing against `foo-2` makes a `-3` and piles up aliases | Treat the article's own slug and aliases as free |
| 7 | Spec tests break | The hurl/bruno suite expects exact update and 404 behaviour | Return 200 with the current slug, no redirect; run the spec suite |
| 8 | Alias table grows without limit | Every title change adds a row, and deletes leave soft-deleted rows | Accept for now (rows are small); add a cap later if needed |
| 9 | Missing migration in tests or prod | `AutoMigrate` calls are listed by hand in `hello.go` and the test setup | Add the new table to both |

Riskiest: #1 — an old shared link that quietly shows a different article is worse than a 404.
