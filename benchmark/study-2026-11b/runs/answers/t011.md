No files were edited, as you asked. This is `express-session` 1.19.0, a library, so "by default" means changing the default of the `rolling` option.

## Assumptions
- "Roll by default" means `rolling` defaults to `true` when `opts.rolling` is `undefined`. An explicit `rolling: false` must still opt out.
- This is a breaking default change, so it needs a semver-major release. The alternative is to leave the default alone and document `rolling: true`. I'm assuming you want the real default flip.
- Only the in-library behavior changes. Session stores in other packages stay as they are.

## How this could go wrong (before planning)
1. **Extra writes on every request.** Today `shouldSetCookie` (`index.js:491`) returns true only when `rollingSessions` is set or the session was modified. With rolling on, every response carries `Set-Cookie`. The store is also touched or re-saved on every request, which adds write load to Redis, SQL and other remote stores.
2. **Stores without `touch()`.** `storeImplementsTouch` (`index.js:175`) falls back to a full save when a store has no `touch`. This is worse when `resave` is true.
3. **Caching breaks.** CDNs and proxies usually refuse to cache, or strip, responses that carry `Set-Cookie`. Static and public endpoints that used to be cacheable stop being cached.
4. **Sessions never expire for active users.** Anyone who relied on a fixed lifetime now gets an unbounded session. That includes polling clients, health checks and background tabs. It is a security and compliance regression because there is no absolute timeout.
5. **Unauthenticated traffic keeps sessions alive.** Bots and monitors that hold a cookie keep it alive indefinitely.
6. **Existing tests encode the old default.** Tests in `test/session.js` that assert "no Set-Cookie on an unmodified session" will fail and need review. They should not just be edited until they pass.
7. **Silent behavior change for downstream apps.** Apps upgrading with no code change get different cookie and store behavior.
8. **Concurrent requests race.** Parallel requests each re-save or touch the session. With `resave: true`, a stale copy can overwrite a newer write.
9. **Sessions without `maxAge`.** For a session cookie (`expires == null`), rolling sends a redundant `Set-Cookie` and changes nothing else.

## Plan
1. In `index.js:109`, change the default to `var rollingSessions = opts.rolling === undefined ? true : Boolean(opts.rolling)`.
2. Update the `rolling` section of `README.md` (around line 295) with the new default. Add a migration note that `rolling: false` restores the old behavior, and mention the CDN caching and store-write implications.
3. Add a `HISTORY.md` entry marked as a breaking change and bump the major version.
4. In `test/session.js`, make the rolling tests explicit. Cover default (rolling on), `rolling: false` (old behavior) and `rolling: true`. Review which existing tests relied on the old default and pass `rolling: false` only where that is the real intent.
5. Verify:
   - Run `npm test`.
   - Run a manual script against `MemoryStore` that makes two requests and checks `Set-Cookie` and `expires` advance by default and stay fixed with `rolling: false`.
   - Check that a store with `touch()` is touched and one without falls back to a save.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Breaking default change | Library consumers upgrade silently | Major version, HISTORY note, README migration |
| 2 | Write amplification on stores | A touch or save on every request | Document it; recommend stores that implement `touch` |
| 3 | Stores without `touch` do full saves | The fallback path at `index.js:175` | Test both store types; warn in the docs |
| 4 | No absolute session timeout | Active clients stay logged in forever | Document an app-level absolute cap |
| 5 | `Set-Cookie` defeats CDN caching | Public and static routes get a cookie | Mount the session only on routes that need it |
| 6 | Bots or pollers keep sessions alive | Unauthenticated hits extend expiry | Skip the session middleware for health and static paths |
| 7 | Old tests assert the previous default | Blind edits hide real regressions | Review each failure; add explicit option tests |
| 8 | Concurrent requests race on saves | Parallel touches or saves with `resave` | Prefer `touch`; document `resave: false` |
| 9 | Redundant cookies for session-cookie mode | `expires == null` gains nothing | Only roll when `maxAge` or `expires` is set (optional) |

Riskiest: #1, the silent breaking default change that alters cookie, store-write and expiry behavior for every downstream app.
