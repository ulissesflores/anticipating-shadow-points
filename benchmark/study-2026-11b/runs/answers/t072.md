The update handler already changes the slug when the title changes, so the missing piece is keeping old links working. `ArticleUpdate` (`articles/routers.go:152-160`) regenerates the slug through `makeUniqueSlug` and overwrites `articles.slug`. Nothing remembers the old value, so any link shared before the rename now returns 404.

## Ways this could go wrong

1. **Old slug is lost on rename.** Every shared link 404s. This is the current behavior.
2. **Old slug collides with a new article.** If old slugs live in a separate table, `makeUniqueSlug` only checks `articles.slug`. A new article titled "Foo" could take a slug that is still reserved as someone's alias.
3. **Alias vs. live slug precedence is ambiguous.** Suppose A is renamed away from "foo" and B is later created as "foo". Then `/foo` has two candidates, and the live article must win.
4. **Rename back and rename chains.** Renaming A→B→A can violate a unique index on aliases, or create redirect chains.
5. **Concurrent renames or creates.** `makeUniqueSlug` is check-then-write and already races. The existing retry on `gorm.ErrDuplicatedKey` needs to cover the alias table as well.
6. **Soft-deleted articles.** `makeUniqueSlug` uses `Unscoped`, so deleted slugs stay reserved. Aliases of deleted articles must also not resolve.
7. **Wrong HTTP semantics.** A 301 on write endpoints (PUT, DELETE, favorite, comments) breaks clients. The RealWorld spec and the hurl and bruno suites expect `/api/articles/:slug` to return the article JSON.
8. **Response `slug` field.** If a lookup by old slug returns the article, its `slug` must be the canonical one, so clients can update their stored URLs.
9. **Non-atomic update.** The slug change, alias insert and tag update must share one transaction. Otherwise a partial failure leaves an article with no alias.
10. **Authorization leaks.** Resolving by alias must go through the same author check as the live slug path, for PUT and DELETE.
11. **Migration and unbounded growth.** AutoMigrate must add the new table. Repeated renames grow it, and slug length and casing edge cases (empty slug from non-Latin titles) matter.

## Assumptions

- "Without breaking links" means old slugs keep resolving for reads (`GET`). I'm not assuming browser-style redirects, because this is a JSON API.
- Old slugs resolve permanently. Aliases are removed with the article.
- I'm adding an `article_slug_aliases(slug unique, article_id)` table, since an extra column on `ArticleModel` can't hold multiple old slugs.
- `makeUniqueSlug` must treat aliases as taken. A live slug beats an alias.
- All `/:slug` routes resolve through one helper that tries the live slug first, then the alias.
- Writes (PUT, DELETE, favorite, comments) via an old slug are accepted, since that is the least surprising behavior. A stricter option would be to reject them with 404.
- Responses always carry the canonical slug.

## Plan (no files edited, as requested)

1. Add `ArticleSlugAlias` in `articles/models.go`, register it in the AutoMigrate list, and add a `FindArticleBySlug` helper that checks live then alias.
2. Extend `makeUniqueSlug` to check aliases, and keep the `ErrDuplicatedKey` retry.
3. In `ArticleUpdate`, wrap the slug change, alias insert and tag update in one transaction. Skip the alias if the slug is unchanged, and delete any alias equal to the new slug on a rename back.
4. Replace the `FindOneArticle(&ArticleModel{Slug: slug})` calls in `routers.go` with the helper, keeping the author checks.
5. Delete aliases in `DeleteArticleModel`, in the same transaction as the article delete.
6. Add tests in `articles/unit_test.go` for each risk above, then run `go test ./...` and the hurl and bruno suites.

| # | Risk | Why it bites here | Mitigation |
|---|------|-------------------|------------|
| 1 | Old slug not kept | `ArticleUpdate` overwrites `slug`, so shared links 404 | Alias table written on rename |
| 2 | New article steals an old slug | `makeUniqueSlug` checks only `articles.slug` | Also check aliases there |
| 3 | Alias vs live slug conflict | Two articles can claim `/foo` | Resolve live first, alias second |
| 4 | Rename-back or chain breaks the unique index | A→B→A reinserts an existing alias | Delete the alias that matches the new slug |
| 5 | Concurrent slug race | `makeUniqueSlug` is check-then-write | Unique indexes, plus retry on `ErrDuplicatedKey` |
| 6 | Partial write on update | Slug, alias and tags updated separately | One DB transaction |
| 7 | Deleted articles | Aliases outlive the article or still resolve | Delete aliases with the article; join on non-deleted |
| 8 | Redirects break the API contract | The spec and hurl/bruno suites expect 200 with JSON | Resolve and serve in place, no 301 |
| 9 | Authorization gap via alias | PUT and DELETE use the lookup before the author check | One helper, author check kept after it |
| 10 | Stale canonical slug in responses | Clients keep using the old slug | Always serialize the canonical slug |

Riskiest: #2/#3, because alias-versus-live slug conflicts can silently hand someone else's old URL to a different article.
