1. In `PasswordHasher.cs`, algorithm detection currently relies on a fragile byte-length check (`hash.Length == 64 && salt.Length == 16`) for HMAC-SHA512 before passing payloads to ASP.NET Core Identity's `VerifyHashedPassword`. Introducing a third hashing format risks decoding errors or format collisions unless an explicit format discriminator is established to distinguish HMAC, Identity PBKDF2, and the new scheme.

2. Transparent rehashing upon authentication is implemented only in `Login.Handler`, whereas `Edit.Handler` updates password hashes only when a new password is explicitly submitted. Users who authenticate exclusively through existing JWT tokens without logging in via `/api/users/login` will continue using legacy password hashes indefinitely.

3. The `Person` entity lacks concurrency tokens or row-versioning, leaving rehash operations vulnerable to race conditions. Simultaneous login requests for the same account, or a login concurrent with a profile update in `Edit.cs`, could overwrite newer user data or trigger concurrency exceptions under SQL Server's `ReadCommitted` isolation.

4. Password hashing in `PasswordHasher` executes synchronously on thread-pool threads via `Task.FromResult`. Upgrading to a computationally heavier or memory-intensive algorithm doubles the execution overhead during an existing user's first login (verifying the legacy hash and generating the new hash), risking thread-pool starvation and request timeouts under peak login traffic.

5. If the new hashing scheme requires alterations to `Person.Hash`, `Person.Salt`, or the addition of algorithm metadata columns, migrations must be synchronized across both `SqliteConduitContext` and `SqlServerConduitContext`. Any discrepancy between the providers will immediately cause `MigrationTests.cs` to fail its `HasPendingModelChanges()` assertion and break CI.

6. `ConduitMapper.cs` uses `Riok.Mapperly` code generation with explicit `[MapperIgnoreSource]` attributes on `Person.Hash` and `Person.Salt`. Adding any new domain properties to `Person` (such as an algorithm version indicator) will produce compilation errors under the repository's strict `<WarningsAsErrors>true</WarningsAsErrors>` build configuration until the mapper is updated.

7. The `IPasswordHasher` interface enforces `Hash(string password, byte[] salt)` and `Verify(string password, byte[] hash, byte[] salt)`, and multiple test classes (`CreateTests`, `LoginTests`, `EditTests`) instantiate `new PasswordHasher()` directly rather than resolving it from DI. Altering this signature or adding constructor dependencies will break compilation across numerous integration test fixtures.

8. Because `Login.Command` does not implement `IReadOnlyRequest`, every login is wrapped in an explicit transaction by `DBContextTransactionPipelineBehavior`, which uses `Serializable` isolation for SQLite. Converting every active user's initial login from a read operation into an immediate database write will significantly increase database lock contention on SQLite deployments.

9. The project enforces centralized package management via `Directory.Packages.props` and locked restores via `RestorePackagesWithLockFile`. Introducing third-party cryptographic dependencies (such as an Argon2 or BCrypt library) requires updating locked package files and risks introducing cross-platform native runtime issues between macOS, Linux, and containerized deployments.

10. Existing integration tests in `PasswordHashingTests.cs` explicitly assert legacy HMAC rehash semantics and verify that upgraded records have empty salt arrays (`Assert.Empty(upgraded.Salt)`). Changing the hashing strategy, payload representation, or rehash lifecycle without updating these tests will cause the test suite to fail.

11. Sequential fallback verification across multiple algorithm generations (HMAC-SHA512, Identity PBKDF2, and the new scheme) introduces execution timing variances during authentication. Without constant-time mitigation across all branches, differences in verification duration could leak whether an account is on a legacy format or facilitate account enumeration.
