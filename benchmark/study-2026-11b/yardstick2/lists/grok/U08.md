Release 1.0.0 was yanked for a default-digest change, and 1.1.0 put the default back on SHA-1.

2. `Signer.unsign` and `TimestampSigner.unsign` never consult `fallback_signers`. Only `Serializer.loads` and `TimedSerializer.loads` do. Callers of the signer classes lose every existing signature, and those classes have no migration argument.

3. `default_fallback_signers` is `[]` since 2.0, when the old SHA-512 compatibility fallback was removed. `Serializer`, `TimedSerializer`, `URLSafeSerializer`, and `URLSafeTimedSerializer` all inherit that empty list and do not set their own digest, so a default swap rejects their existing cookies and URL tokens.

4. In `iter_unsigners`, a dict fallback becomes the whole `signer_kwargs`. A SHA-1 entry of `{"digest_method": hashlib.sha1}` drops a caller's `key_derivation` or `sep`, so tokens signed with the old digest plus a non-default derivation such as `"hmac"` still fail.

5. A new default SHA-1 fallback starts accepting SHA-1 again for applications that already passed `digest_method=hashlib.sha256` or `sha512` and relied on the empty default. `fallback_signers=None` copies `default_fallback_signers`, and `TimedSerializer.loads` never expires an algorithm: `SignatureExpired` stops the loop only after a digest has already matched.

6. `_lazy_sha1` exists so FIPS builds that lack SHA-1 fail at first use, not at import (2.2.0). `loads` catches only `BadSignature`. A SHA-1 fallback that calls `hashlib.sha1` on FIPS raises a different error and aborts the rest of `iter_unsigners`.

7. The default lives on both `HMACAlgorithm.default_digest_method` and `Signer.default_digest_method`. `Signer` passes the digest into `HMACAlgorithm` only when `algorithm` is omitted. Callers who pass a custom `algorithm` still derive the key with `Signer.digest_method`, so updating one attribute and not the other mixes a SHA-256 key with a SHA-1 MAC.

8. The signature is the raw HMAC, then `base64_encode` strips padding, so the signed tail grows from 20 bytes to 32. `URLSafeSerializerMixin` compresses only the payload, and `docs/concepts.rst` already treats that growth as material for cookies and URLs.

9. The tree is `2.3.0.dev`, and the 2.3.0 changelog only drops Python 3.8/3.9 and removes deprecated code. A wire-incompatible default on that minor line breaks the compatibility 2.x has kept since 1.1.0, and the docstrings, `docs/concepts.rst`, and `docs/serializer.rst` still say the default is SHA-1 and that HMAC-SHA1 is acceptable.
