Vou mapear como título, slug e links de artigo funcionam neste repositório antes de listar os riscos.1. `FindOneArticle` matches only `ArticleModel.Slug`, and retrieve, update, delete, favorite, unfavorite, and both comment routes each call it on their own. A shared URL is also the editor path (`/#/editor/<slug>`), the comment route, and the favorite route, so preserving the link only on `GET /api/articles/:slug` still leaves those handlers returning the `{"errors":{"article":["not found"]}}` body the tests assert.

2. `hello.go` sets `RedirectTrailingSlash` to false because a redirect drops the body. A 301/302 from an old slug changes the status codes the pinned Hurl suite checks, and the hash clients in `FRONTEND_INSTRUCTIONS.md` (`/#/article/<slug>`) will not rewrite that hash from an API `Location`.

3. `scripts/run-spec-tests.sh` pins `realworld-apps/realworld` at `25588846c314b15a5e427ffe816e6b4af7be68c7` with a sha256, and that Hurl suite is the CI source of truth. It expects `PUT` to return 200 with the new slug in the article JSON and has no alias rule, so answering 200 for a slug that is no longer current can fail `hurl-api-test` or the weekly spec-drift run unless both pin constants move together.

4. `Slug` is a `uniqueIndex`, delete is a GORM soft delete, and `makeUniqueSlug` counts `Unscoped()` rows, so a deleted article keeps its slug forever while `FindOneArticle` will not return it. `makeUniqueSlug` never looks at any other table, so a later `POST /api/articles` can take a slug that is still a shared link, and a soft-deleted row can block a rename onto a slug no live `GET` serves.

5. `makeUniqueSlug` does not exclude the row being edited. An article already on `base-2` whose new title slugifies to `base` is bumped to `base-3` because its own current slug counts as taken, and a rename back onto a slug this article just released does the same, so the helper mints a suffix instead of reclaiming the shared URL.

6. `ArticleUpdate` writes the new slug with `Update`, then `ReplaceTags`, then re-fetches, with no transaction. The retry loop only regenerates `updates["slug"]` twice, and only on `gorm.ErrDuplicatedKey`. `TestArticleUpdateSlugRaceRetries` already shows a concurrent insert taking the destination slug. The same window lets a create grab the old slug the moment the `UPDATE` frees it, before any alias row exists.

7. Comments and favorites already point at the numeric article id (`CommentModel.ArticleID`, `FavoriteModel.FavoriteID`), so they survive a slug change. An alias stored as "previous slug string to next slug string" breaks on the second rename (A to B to C) once B is no longer on the row. `TestArticleUpdateDescriptionAndCollidingTitle` expects the colliding retitle to land on `slugA-2`, which stops being true once old slugs stay reserved.

8. `ArticleDelete` checks `AuthorID`, then calls `DeleteArticleModel` with the path slug rather than the primary key. Resolving an alias for the read and then deleting by the raw param can return 204 and leave the row, and an alias that outlives the soft delete makes a later `GET` of that slug find the article again, against the test that a deleted slug is 404.

9. Schema changes exist only as `AutoMigrate` in `Migrate` (`hello.go`) and again in `TestMain` (`articles/unit_test.go`). A history table added in one place and not the other splits the test database from `./data/gorm.db`, and `AutoMigrate` will not rebuild the existing unique index or record the current slug of rows already stored, so links shared before the deploy still 404.

10. The slug moves only when `makeSlug(title) != articleModel.Slug`. `github.com/gosimple/slug` folds case and punctuation, so a real title edit can leave the slug unchanged, and a title that passes `min=4` but is only symbols becomes an empty slug. An empty slug collides with `GET /api/articles/`, and `makeUniqueSlug` would then issue `-2` and `-3`. The update validator checks the title string and never the generated slug.
