Vou ler o fluxo de cadastro e login neste repositório para listar os riscos concretos de exigir verificação de e-mail antes do acesso.1. `join.tsx` calls `createUserSession` immediately after `createUser`, and `requireUserId` (used by `notes.tsx`) treats any `__session` `userId` as logged in. A check added only in `verifyLogin` still lets a new account open `/notes` before the address is confirmed, and the login loader redirects away whenever that cookie is already set.

2. This app cannot send mail. `package.json` has no mail client, `mocks/index.js` only passes through `/ping` with MSW `onUnhandledRequest: "bypass"`, and the Fly config documents `SESSION_SECRET` but no mail secret or public origin. `npm run validate` boots through `start:mocks`, so a real provider call either escapes CI or fails with no captured message.

3. `User` has no verified flag, token, or expiry, and both the Fly `release_command` and `npm run setup` run `prisma migrate deploy` before `prisma/seed.ts` creates `rachel@remix.run` with only email and password. A required column with no default breaks that seed, while `@default(false)` migrates cleanly, does not trip `auto_rollback`, and locks the seed user plus every existing row, with no admin screen to mark them verified.

4. `getUser` destroys the cookie only when the user row is missing, and "Remember me" sets `__session` `maxAge` to 7 days. Enforcing verification there also rejects the cookie from `cypress/support/create-user.ts`, which never calls `verifyLogin`. Leaving the check only on the login action keeps every session that signup already issued.

5. `User.email` is a case-sensitive unique column, and a duplicate signup returns "A user already exists with this email". If the message never arrives, that address stays reserved: login has no resend, `deleteUserByEmail` is only used by Cypress, and nothing expires unverified rows, so a signup can squat an inbox the real owner can no longer register.

6. Login currently returns one string, "Invalid email or password", for both a missing user and a bad password. A separate "verify your email" response after `bcrypt.compare` succeeds tells the caller that the address is registered and that the password was correct. `validateEmail` only requires length greater than 3 and an `@`, and the value is stored unchanged, so `Rachel@Remix.run` and `rachel@remix.run` are different users and a token lookup can miss.

7. `getUser` returns the whole Prisma `User`, and the root loader puts that object in the document JSON on every page. A token column on `User` is therefore sent to the browser. `morgan("tiny")` in `server.ts` logs the request URL, so a token in the query string is written to the Fly logs, and the trailing-slash middleware 301s while keeping that query string.

8. Outside `PRIMARY_REGION`, `app/db.server.ts` points Prisma at port 5433, and `server.ts` replays only non-GET methods to the primary. A verification link that writes from a loader will try to mark the user verified on a read replica and fail in every secondary region.

9. `cypress/e2e/smoke.cy.ts` submits "Create Account" and then follows "View Notes for {email}" in the same session, which only renders when `useOptionalUser` is set. `cy.login()` depends on `create-user.ts` inserting a user and a session cookie. Both assume `createUser` already grants access to notes, and that is what `npm run validate` runs.

10. `fly.toml` publishes the app on internal port 8080 behind `force_https` and sets no public base URL, and Express never enables `trust proxy`. A link built from `request.url` can point at the internal port or at plain `http`, so the message confirms an address the recipient cannot open.
