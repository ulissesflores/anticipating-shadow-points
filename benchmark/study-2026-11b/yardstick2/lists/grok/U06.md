Vou ler o repositório para localizar modelo de dados, autenticação e o que já existe de exportação antes de listar os riscos.1. `GET /api/v1/users/<id>`, `/users/<id>/posts/` and `/users/<id>/timeline/` return any account to any confirmed caller, and `tests/test_api.py` `test_users` treats Susan reading John as success. An export copied from those routes, or hung off `/user/<username>`, lets one user download another account. The file has to be built only from the session’s `current_user` or `g.current_user`.

2. `User.to_json()` omits `email`, `name`, `location`, `about_me`, `confirmed` and `role`, and `user.html` shows `email` only when `current_user.is_administrator()`. Adding those fields to `to_json()` would put the address on the existing any-user API, not only in the download.

3. `password_hash` is an ordinary column, and `avatar_hash` is the MD5 of the email. A dump of the row, of `__dict__`, or of a loaded `Follow` user also ships the hash. Confirmation, reset and email-change tokens are not stored. They are signed with `SECRET_KEY` inside `generate_*_token`, so the export must not mint them.

4. `user.comments` are comments this user wrote on other people’s posts, while `post.comments` are other people writing on this user’s posts. `followed_posts` joins everyone this user follows, and `User.__init__` always inserts a self-follow. Pulling the timeline or parent `body` into the file publishes third-party text. A joined load of `Follow.follower` or `Follow.followed` carries those users’ `email` and `password_hash`.

5. `Comment.disabled` is hidden in `_comments.html` unless the viewer is on `/moderate`, and `Comment.to_json()` does not include it. Reusing `to_json()` drops the moderation state of the user’s own comments. Dumping `post.comments` or the moderator query also includes other authors.

6. Every list uses `paginate` with `FLASKY_POSTS_PER_PAGE` 20 and `FLASKY_COMMENTS_PER_PAGE` 30, and `error_out=False`. Reusing `get_user_posts` or `get_post_comments` silently writes the first page only. `Post.to_json()` also runs `comments.count()` per post.

7. `body` and `body_html` are unbounded `Text`, and the process is synchronous `gunicorn flasky:app` with no job queue. `SQLALCHEMY_RECORD_QUERIES` is on, and `after_request` logs any statement slower than `FLASKY_SLOW_DB_QUERY_TIME` (0.5s), parameters included, to stderr. On Heroku that is the log stream. An exception during the same request is emailed to `FLASKY_ADMIN` by `SMTPHandler`.

8. The API rejects unconfirmed users in `before_request`. Web routes only use `@login_required`, so a logged-in unconfirmed account can still act. API auth is HTTP Basic with the raw password, or a 3600-second token that is not revoked on logout or password change. There is no rate limit. One stolen token is enough to pull the whole archive, and repeated downloads block a worker.

9. Nothing sets `Cache-Control`. A `GET` download can be stored by the browser or by Heroku’s proxy (`ProxyFix` in `HerokuConfig`). The same response needs `Content-Disposition: attachment` and a JSON body. Serving `body_html` as a document reopens stored markup that today is only rendered inside the app.

10. Profile, posts and comments are three queries with no single transaction, while `edit_profile_admin` can change `email`, `username`, `confirmed` and `role` mid-flight. The file needs a defined snapshot, and the admin screen must not become a way to export someone else’s archive.
