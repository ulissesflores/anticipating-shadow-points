Vou ler o código de comentários e moderação antes de listar os riscos deste pedido.1. There is no moderator principal: `users` has no role column, `AuthServiceProvider` only maps a missing `App\Policies\ModelPolicy`, and `DeleteComment::authorize()` allows only `$comment->user_id == auth()->id()`. Adding `is_moderator` to `User::$fillable` is privilege escalation, because `UserController::update` passes the raw `user` JSON into `$user->update()`.
2. Hide cannot go through `CommentController::destroy`, which calls `$comment->delete()` on a table with no `hidden_at` or `deleted_at`. That removes the row the author would appeal, and `CommentTest` currently locks both the empty relation and the 403 for every non-author.
3. `GET articles/{slug}/comments` is public (`auth.api` except `index`), `Article::comments()` is an unfiltered `hasMany()->latest()`, and `CommentTransformer` always emits `body` plus author. A flag that does not change this query still serves the abusive text to anonymous RealWorld clients, while dropping or reshaping rows breaks `it_returns_all_the_comments_of_the_article` and the published comment contract.
4. The author has no way to learn about or read a hidden comment: that public index is the only read path, a global hidden scope or `SoftDeletes` makes implicit `{comment}` binding return 404, and `Notifiable` is never used (`notify` / `Mail` have no callers), so the 7-day clock can expire with no notice.
5. The deadline cannot be a delayed job or a scheduled command. `QUEUE_DRIVER` defaults to `sync` (and `phpunit.xml` forces it), `Console\Kernel::schedule` is empty, and `docker-compose.yml` runs only PHP and MySQL. It has to be a `hidden_at` checked on the appeal request; `created_at` is wrong because older comments and the factory’s backdated timestamps would already be past 7 days, and `updated_at` moves on any later save. The app timezone is UTC, so the cutoff is exactly 168 hours from `hidden_at`.
6. An appeal that clears the hidden flag lets the author undo the moderator inside the window. The schema has nowhere to store appeal text, status, or a reviewer, so someone must define who accepts or denies, whether a denial is final, whether a new hide restarts the 7 days, and that a moderator who wrote the comment cannot grant their own appeal.
7. `destroy` takes an untyped `$article` and a globally bound `Comment`, and never checks `article_id`, so the same binding would hide or appeal a comment under the wrong slug. `articles` and `users` both `onDelete('cascade')` comments, and `ArticleController::destroy` hard-deletes the article, which erases a pending appeal with no decision.
8. `Comment::$fillable` is only `body` and `user_id`. New hidden or appeal columns placed there can be set by the client on create, the same way a moderator bit on `User` can. Existing rows and `DummyDataSeeder` need a default of visible, and a global scope would leave `assertEmpty($this->article->comments)` green even if “delete” stopped removing the row.
