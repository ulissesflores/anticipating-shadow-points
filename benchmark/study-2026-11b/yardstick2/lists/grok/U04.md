Vou ler o código de bloqueio por IP e usuário para listar só os riscos reais desta mudança.1. `AXES_LOCKOUT_PARAMETERS` already has two different shapes, and this request fits only the nested one. `[["username", "ip_address"]]` (the old `AXES_LOCK_OUT_BY_COMBINATION_USER_AND_IP` branch in `axes/conf.py`) locks that pair, while the flat `["username", "ip_address"]` is an OR: `get_failures` takes the max of the separate filters, so one address locks every username from it and one username is locked from every address. The flat form also makes `AxesCacheHandler.reset_attempts` raise `NotImplementedError` when `reset_request` sets `ip_or_username=True`.

2. A pair filter makes `AxesDatabaseHandler.get_failures` sum `failures_since_start` only for rows that match both username and IP. A guess that changes the username, or the IP, never reaches the default `AXES_FAILURE_LIMIT` of 3, and `axes_lockout_params_check` (`axes.W006`) stays quiet because `ip_address` is still in the list.

3. `get_client_username` keeps the raw posted string, truncated to 255, with no case folding and no check that the user exists. `Admin`, `admin`, and a random name are separate counters. `AxesTestCase.login` already posts a new random username on every failure, and those attempts only add up today because the default filter ignores the username. `check_handler` and `lockout()` depend on that.

4. Both handlers skip writing a failure only when `lockout_parameters == ["username"]`. A nested pair does not match, so a missing name is stored as NULL and later filtered with `username IS NULL`. `make_cache_key_list` drops that falsy value and hashes the IP alone, which is the same key the current IP-only default already wrote, so the cache handler and the database handler lock different requests.

5. Cache keys are the SHA-256 of the parameter values joined with no separator. With a pair default, `("admin", "1.2.3.4")` and `("admin1.2.3", ".4")` share one `AxesCacheHandler` counter and stay different `AccessAttempt` rows.

6. Sites that never set `AXES_LOCKOUT_PARAMETERS` receive `["ip_address"]` from the fallback in `axes/conf.py`. Changing that fallback does not trip `axes_deprecation_check`, which warns only when a deprecated flag is present, and it reinterprets existing rows: an address that is locked only because several usernames were summed together falls under the limit on the next request, with no data migration.

7. That same fallback still rewrites the list when `AXES_USE_USER_AGENT` or the deprecated lockout flags are set. Setting the new default on the `getattr` before that branch drops `AXES_ONLY_USER_FAILURES`, `AXES_LOCK_OUT_BY_USER_OR_IP`, and `AXES_LOCK_OUT_BY_COMBINATION_USER_AND_IP`. `AXES_USE_USER_AGENT=True` would append `user_agent` onto the inner list, producing `[["username", "ip_address", "user_agent"]]` where the upgrade notes in `docs/2_installation.rst` document `[["ip_address", "user_agent"]]`.

8. `axes.utils.reset(ip=...)`, `axes_reset_ip`, and `reset_request` with only `REMOTE_ADDR` delete every database attempt for that IP, because `AxesDatabaseHandler.reset_attempts` applies the username filter only when a username was passed (`tests/test_attempts.py` expects the count to drop from 5 to 3). The cache handler builds its key from `username=None` and leaves the pair keys that login wrote in place. One unlock path clears every account on the address, and the other clears none.

9. `IsLockedOutFilter` marks a row locked only when that row's own `failures_since_start` reaches `AXES_FAILURE_LIMIT`. Rows are unique on `(username, ip_address, user_agent)`, and the lock decision sums across user agents, so a locked pair can show as open in the admin.

10. The published default becomes false in the same change. `docs/4_configuration.rst` still says the default is `["ip_address"]` and "only use IP address", and `docs/2_installation.rst` tells existing installs to set `["ip_address"]` to keep current behavior. `user_locked_out` still carries only `username` and `ip_address`, so a receiver that bans the IP bans an address Axes would still allow for every other username.
