1. **Database schema breakage** – Adding a `TenantId` column to `TodoItem.cs` and `TodoList.cs` (and related EF configurations) will require migration scripts; existing data and tests that assume no tenant field may fail.  

2. **Query leakage** – Current queries (e.g., `src/Application/TodoLists/Queries/GetTodos/GetTodos.cs`) do not filter by tenant, so without adding tenant predicates every tenant could see other companies’ todo data.  

3. **Command authorization gaps** – Commands such as `CreateTodoItem`, `UpdateTodoItem`, and `DeleteTodoList` (in `src/Application/TodoItems/Commands/*` and `src/Application/TodoLists/Commands/*`) lack explicit tenant ownership checks; a malicious user could modify another tenant’s records.  

4. **Missing tenant propagation** – The `IUser` interface (`src/Application/Common/Interfaces/IUser.cs`) provides user information but no tenant info, so services like `CurrentUser` (`src/Web/Services/CurrentUser.cs`) must be extended; otherwise tenant context will be null, causing runtime errors.  

5. **EF Core configuration oversights** – The entity configurations (`src/Infrastructure/Data/Configurations/TodoItemConfiguration.cs` and `TodoListConfiguration.cs`) need global query filters for `TenantId`; forgetting this will leave the database unprotected.  

6. **Cascade delete side effects** – Introducing tenant‑scoped foreign keys may trigger cascade deletes across tenants if not configured with `OnDelete` restrictions, risking data loss when a tenant is removed.  

7. **Testing suite mismatches** – Unit and functional tests (e.g., `tests/Application.FunctionalTests/TodoLists/Commands/CreateTodoListTests.cs`) assume a single‑tenant model; they will break unless tenant setup is added to test fixtures.  

8. **Performance regression** – Adding a tenant filter to every query can affect query plans; without proper indexing on `TenantId`, the `TodoItems` and `TodoLists` tables may experience latency spikes under multi‑tenant load.  

9. **API contract changes** – Controllers/endpoint definitions (`src/Web/Endpoints/TodoLists.cs`) currently return DTOs without tenant fields; exposing or omitting them inconsistently will break client contracts and Swagger documentation.  

10. **Security rule enforcement** – The `AuthorizationBehaviour` (`src/Application/Common/Behaviours/AuthorizationBehaviour.cs`) only checks roles; it must also enforce tenant isolation, otherwise role‑based access may inadvertently grant cross‑tenant visibility.  

11. **Data migration complexity** – Existing production data must be backfilled with correct `TenantId` values; an incomplete migration could leave orphaned records accessible to the wrong tenant.  

12. **Caching and concurrency hazards** – Any in‑memory caches (e.g., MediatR pipelines) that store todo data without tenant keys could serve stale data to the wrong tenant after the change.
